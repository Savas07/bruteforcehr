## Design Critique: App icon concepts

### Overall Impression

All three are calm and on-palette; none uses force imagery. Only **B (Monogram)** survives 16 px intact: A turns into a "text-align / speed lines" glyph and C into a generic launcher grid as soon as they drop below 48 px. B is the least novel idea, but it is the only one that stays itself at every size the brief names.

### Visual Hierarchy

- **What draws the eye first**: A: the top white pill (correct intent, wrong reading). B: the whole letter. C: the single white cell, which reads as a badge rather than as "the match".
- **Reading flow**: A diagonally bottom-left to top-right; B none needed; C scans the grid, then stops on the lit cell — only at ≥ 87 px.
- **Emphasis**: B's optical weight sits in the bowls; the glyph's bounding box is centred, so the letter looks a few pixels right of centre at 1024. Minor.

### Consistency

| Colour       | All three use the `@bfhr/ui-tokens` teal family; the website's interim favicon uses flat `accent.solid` `#216863`.  | Keep the gradient for app icons; the favicon and web mark use the same gradient so the tab and the Dock match. |
| Shape        | Windows plate radius 3/16 matches the interim favicon; macOS uses Apple's 824/185.4 body; iOS lets the system mask. | Keep.                                                                                                          |
| Interim mark | B continues the website's interim "B"; A and C would replace it.                                                    | Favour continuity.                                                                                             |

### Accessibility

- **Color contrast** (graphical object, SC 1.4.11 as a guide; logos are exempt): white glyph on the gradient 4.58:1 (top) to 8.07:1 (bottom) — pass for B and for A's top bar. A's 50 % bar 2.30–3.31:1 and C's 30 % cells 1.69–2.12:1 — fail.
- **Icon edge on dark canvases**: the gradient bottom `#1B5954` is 2.36:1 against `#0E1014`; the silhouette softens at the bottom in dark Docks, taskbars and tabs. 🟢 Minor — the top edge (4.15:1) defines the shape; log for the dark appearance.
- **Text readability**: n/a (no text in the icon). The app name always appears next to the icon (Home Screen label, Dock tooltip, tab title), so the icon carries no information on its own.

### What Works Well

- A calm palette that is clearly ours next to the blue/green category.
- No force, lock, hammer or code imagery; nothing reads as "hacking".
- B carries over the website's interim mark, so nothing a visitor already saw changes meaning.

### Priority Recommendations

1. **Choose B (Monogram)** — the only concept that is recognisable at 16 px on all three platforms and on the web.
2. **Hint the small sizes** — 16 and 32 px masters on the pixel grid for favicon, ICO and ICNS small entries.
3. **Design the appearances** — Icon Composer `.icon` with light, dark and tinted, rendered by `ictool`, used by both Xcode and Tauri.

**Chosen concept: B (Monogram).** Why: it is the only concept that is still itself at 16 px (favicon, Windows small icon, macOS list views), it keeps the meaning the website already introduced, and it is calm without having to explain the product name. A and C told a better story at 1024 px and lost it below 48 px.
