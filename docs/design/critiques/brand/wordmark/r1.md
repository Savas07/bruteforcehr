- **Sheet:** [r1-options.png](r1-options.png) — lockups at 64, 28 and 20 px tall on the light (`#F6F7F9`) and dark (`#0E1014`) canvases, rendered by Chrome at 2×.

## Design Critique: BruteForceHR wordmark

### Overall Impression

All three are quiet and legible. The name is one 12-letter camel-case word, so the open question is parsing, not style: W1 and W3 read as one long word that the eye has to split; W2 splits it with colour and moves the emphasis from "BruteForce" to "HR", which is what the product is about.

### Usability

| Finding                                                                                                                                                                                      | Severity    | Recommendation                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | --------------------------------------------------------------------------------------------- |
| W1 / W3: "BruteForceHR" in one colour forces the reader to segment three words by capitals alone; at 20 px the "eHR" junction blurs.                                                         | 🟡 Moderate | Separate "HR" from "BruteForce" visually.                                                     |
| W2: the accent "HR" reads as the product's domain and gives the mark's teal a second home in the lockup. Risk: an accent-coloured word inside a header link could look like a separate link. | 🟢 Minor    | The whole lockup is one link target with one accessible name; "HR" never appears alone. Keep. |
| W3 (Medium) is the calmest, but at 20 px its strokes are lighter than the B plate next to it, so plate and text feel like two weights.                                                       | 🟢 Minor    | Use SemiBold; it matches the plate's stroke weight.                                           |
| Gap 28 units: at 20 px tall the gap is 5.6 px, enough to keep plate and "B" from touching visually; at 64 px it is 18 px, still tight enough to read as one unit.                            | —           | Pass.                                                                                         |

### Visual Hierarchy

- **What draws the eye first**: the plate, then the name — correct for a header logo.
- **Reading flow**: W2 reads "BruteForce · HR"; W1/W3 read "BruteForceHR" as one token.
- **Emphasis**: W2 puts the colour on the calm part of the name ("HR"), so "BruteForce" is neutral text instead of the loudest element.

### Consistency

| Element | Issue                                                                                                                             | Recommendation                                                                                                      |
| ------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Colour  | W2 uses existing roles only: `fg.primary` and `accent.text` per scheme (light `#161A22` / `#1F635D`, dark `#ECEEF2` / `#43BEB4`). | Render the website's lockup inline with `currentColor` and `var(--bfhr-color-accent-text)` so it follows the theme. |
| Type    | Inter Display matches the display family of `@bfhr/ui-tokens` visually.                                                           | —                                                                                                                   |
| Mark    | The plate is the app icon's plate at the same 3/16 radius.                                                                        | —                                                                                                                   |

### Accessibility (and copy)

- **Color contrast** (logotypes are exempt from 1.4.3; checked anyway): "BruteForce" 17.43:1 on `#FFFFFF` and 15.15:1 on dark `surface.base` `#16191F`; "HR" `#1F635D` 7.00:1 on white, `#43BEB4` 7.76:1 on `#16191F`.
- **Name**: the lockup is an image of text; its accessible name must be the product name exactly ("BruteForceHR"), not "logo" or "home". The surrounding link goes to `/`, which screen readers already announce as a link.
- **Copy** (`ux-copy`): no tagline in the lockup — the footer description carries it, and a tagline would have to be translated in three languages.

### What Works Well

- One component for header and footer, same proportions as the app icon.
- No uppercase, no italics, nothing that shouts the name.

### Priority Recommendations

1. **Choose W2** — colour separates "HR", parsing improves, emphasis lands on the calm half of the name.
2. **Ship it inline on the website** so it follows light/dark tokens, with the accessible name "BruteForceHR".
