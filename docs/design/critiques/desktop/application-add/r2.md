## Design Critique: Log an application

### Overall Impression
The dialog now scans as a tidy two-column form with a clear primary path (type company + role, ⌘↩). States behave like the rest of the app: a form-shaped skeleton while the tracker loads, a scoped error with Try again, and an offline line that says the add is kept on this device. The remaining issues are minor.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Loading dark: the label bars of the skeleton don't show (`skeleton.base` equals `surface.elevated` in dark); the field outlines carry the shape | 🟢 Minor | Token follow-up for the design system: a skeleton tone for elevated surfaces. Logged for DesktopTracker |
| DE footer: "Ctrl Enter zum Hinzufügen" no longer fits beside three buttons; the buttons wrap to a second row (r2 fix for an overlap seen in the first DE capture) | 🟢 Minor | Accept: wrapping keeps everything readable; EN/TR stay on one row |
| Saved/Preparing remove the applied date row | 🟢 Minor | Accepted in r1 |
| The board behind still has its own "Add application" toolbar button and column "+ Add" wired to the board's placeholder, not to `openAddApplication` | 🟢 Minor (other slice) | Board owner calls `openAddApplication()` / `openAddApplication({ status })`; reported to DesktopTracker |

No Critical or Moderate findings remain.

### Visual Hierarchy
- **What draws the eye first**: title, then the focused Company field.
- **Reading flow**: Company/Role → Link (full width) → Status/Applied on → Sent via/Location → CV/Version → Notes → footer (hint left, actions right).
- **Emphasis**: single primary; the error summary is the only red block and only after a failed add; the duplicate note is info-blue with "Open it".

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Fields, labels, dialog frame | Same tokens and sizes as the CV and snooze dialogs | Keep |
| Keycaps | Shared `Keycaps`, platform glyphs (⌘ ↩ / Ctrl Enter) | Keep |
| Error state | `InlineAlert` error + "Try again" like PaneError copy (what + reassurance) | Keep |
| Offline | Same wording family as the shell strip ("saved on this device … syncs") | Keep |

### Accessibility
- **Color contrast**: no violations in 20 axe runs; needs-review items are Radix focus guards / the aria-hidden background and the shared keycap chips (see accessibility.md).
- **Targets**: 32 px controls; summary links are text buttons that move focus to their field.
- **Readability**: footnote labels, callout inputs; errors under each field and announced via `aria-describedby`.

### What Works Well
- Keyboard: Mod+N anywhere, focus lands on the first empty required field, Enter/⌘↩ adds, Esc closes (asks first when something was typed, with "Keep editing" focused).
- Calm copy: "You're already tracking … (Interviewing)." with "Open it"; "Pick today or an earlier day."; no red for rejections or duplicates.
- Version picker labels by date + how it was made ("14 Oct · Tailored with AI (current)").
- TR and DE fit without truncation.

### Priority Recommendations
1. Skeleton tone for elevated surfaces (design-system token, outside this slice).
2. Wire the board's Add buttons and the palette's "New application" to `openAddApplication`.
