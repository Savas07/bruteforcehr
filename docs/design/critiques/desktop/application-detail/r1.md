# Application detail · desktop · critique round 1

- **Screen:** application detail, full page (`/tracker/applications/$applicationId`), desktop (Tauri webview).
- **User goal:** open one application and, in one place, see where it stands and what to do next (follow up, prepare for the interview), correct an automatic change, and keep the details (rounds, people, documents, notes, reminder) together.
- **Persona:** active job seeker, often stressed and short on time, switching between phone and desktop.
- **Stage:** refinement (first real build on the memory store). **Focus:** information order at 1280 × 800, the suggestion card and next action, the interview editor, trust rows (automatic move + Undo), state coverage.
- **Method:** `skill://design-critique`, with `skill://ux-copy` for wording and `skill://accessibility-review` + axe for the a11y lines; applied to the captures below (each image looked at).

Captures judged (first build, before the fixes under Resolution):

## Design Critique: Application detail (desktop)

### Overall Impression
Calm and complete: one teal primary, a readable stage strip, and every section says what belongs in it when it's empty. The biggest opportunity is order: the most trust-relevant row (the automatic move with its Undo) and the timeline sit below the fold because the interview card takes the main column first, and the header asks for a second "next action" while a suggestion card already asks the real question.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| At 1280 × 800 the Brightwave timeline starts at y ≈ 720: the automatic "Moved to Interviewing" row with Undo is below the fold, under a 150 px interview card. research/tracker.md puts interview rounds in the right column. | 🟡 Moderate | Main column = Up next → Timeline; move Interview rounds to the top of the side column. |
| While a suggestion is visible the header still shows a primary ("Set a reminder" on Quill Docs, "Add interview round" on Kiez Health), so the page asks two different things at once and the louder one is the less relevant. | 🟡 Moderate | When a suggestion is due, the card is the next step: no header next action. |
| The user's reminder appears twice: a grey band under the status ("Reminder: Hiring manager interview · Due Wednesday, 17:00") and the "Your reminder" block in Reminders. The band also pushes the stage strip down. | 🟡 Moderate | Keep the band only in the side panel (which has no Reminders section); on the page the header's "Change reminder" opens the editor in Reminders. |
| "Prepare for Hiring manager interview" (⌘↩) opens the round editor with focus on **Round**; the prep notes are the last field, below the dialog's fold. The action promises prep and lands on metadata. | 🟡 Moderate | Open with focus in Prep notes (taller field) when started from "Prepare for …". |
| The suggestion card repeats "Quill Docs · Frontend Engineer" and the monogram right under the identical page header. | 🟡 Moderate | On the application's own page the card drops the application line; the message becomes its heading (additive `hideApplication` on the shared `NudgeCard`). |
| Closed application header reads "16 days in Not selected": grammatical but odd, and it frames an outcome as a stage the user is "in". | 🟡 Moderate | Closed outcomes: "Closed 16 days ago". |
| Turkish and German captures: every `application-detail.*` string is English; in German the pins line reads "Kept as sent on 5. Okt.. Documents…" (double full stop: the date ends with a period). | 🟡 Moderate | Translate all ids (TR siz, DE du); reword so the date never ends a sentence: "Recorded on {date}, when you applied. Documents used stay as you sent them." |
| Native date and time fields render in the harness browser's locale (10/28/2026, 10:00 AM) while the page is en-GB. | 🟢 Minor | Log: WKWebView / WebView2 render these from the OS locale, which is the user's own setting in the app. |
| The stage strip ticks Saved / Preparing / Acknowledged on Brightwave although it went Saved → Applied → Screening. | 🟢 Minor | Log: the strip shows position, not history (the timeline is the history); a "skipped" state would add a fourth visual state for little value. |
| The prep reminders switch is disabled in the harness with "Notifications need the BruteForceHR desktop app." | 🟢 Minor | Log: correct for a plain browser; the app shows the real permission states (critiqued in tracker-reminders). |

### Visual Hierarchy
- **What draws the eye first:** the role title, then the teal "Prepare for Hiring manager interview" button. Correct when an interview is upcoming; wrong when a suggestion is due (fixed above).
- **Reading flow:** header → status line → stage strip → main column; the side column reads as reference. After the reorder, the eye goes Up next → Timeline (actions, then history), with the upcoming round on the right where Calendly puts "Upcoming meetings".
- **Emphasis:** section titles (headline) are clearly above body text; automatic rows are marked by the "Automatic · Mail" tag, not by colour; "Not selected" stays grey in the strip and pill.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Status pill + Move to… | Same `InteractiveStatusPill` / `StatusMenu` as the board; Accepted / Declined greyed with the D16 reason. | — |
| Timeline rows | Shared `TimelineRow`: "Undone" tag, "Can't undo — the status changed since.", View source. Same as the board panel. | — |
| Toasts | Snooze, Undo of a move, deletes use the shared toast (⌘Z keycap, "back to Screening" without a second Undo, D12). | — |
| Dialogs | Interview, contact, CV and delete dialogs share one shell (title, form, Cancel + primary); delete focuses Cancel (IA.md). | — |
| Empty sections | One muted line each (`EmptyState subArea`), saying what arrives and how. | — |

### Accessibility
- **Color contrast:** body and secondary text pass in both themes by eye; axe reports no contrast violations (2 "needs review" are keycaps with symbols only).
- **Structure:** axe serious — Documents used nests `<dt>`/`<dd>` inside an extra `<div>` with the icon, so the `<dl>` has invalid children (definition-list ×1, dlitem ×4). Fix: icon inside `<dt>`, one `<div>` per group.
- **Keyboard:** Esc back, M Move to…, H Later, D answer no, N note, ⌘↩ next action, ⌘S notes, all in the shortcuts sheet; dialogs trap focus; the zone picker is a labelled combobox.
- **Targets:** 24 px icon buttons in cards (desktop minimum), 32 px primary buttons.

### What Works Well
- The automatic move shows source ("Automatic · Mail"), the email's reason and Undo; after Undo the row is tagged "Undone" and a "Undid a move · back to Screening" row appears — the trust principle end to end.
- The interview card gives the user's time first and the organiser's under it ("10:00–10:45 New York time"), with one-click `.ics`.
- The snoozed state isn't a disappearance: "Follow-up suggestion snoozed until Tomorrow, 09:00 · Show now".
- Delete asks with consequences and keeps contacts ("Contacts stay in your address book. You can't undo this.").

### Priority Recommendations
1. **Reorder columns** — timeline with Undo above the fold; rounds on the right.
2. **One next step at a time** — no header primary while a suggestion is due; no duplicate reminder band on the page.
3. **Fix the dl structure and translate** — the axe serious findings and the English-only TR/DE pages.

| Timeline below the fold | **Fixed** — `Screen.tsx`: main column Up next → Timeline; side column starts with Interview rounds. |

| Native date/time locale | **Logged** — OS-controlled in the app's webviews. |
| Strip ticks skipped stages | **Logged** — position, not history. |
| Prep toggle disabled in harness | **Logged** — permission states reviewed in `tracker-reminders`. |
