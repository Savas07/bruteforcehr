## Design Critique: Command palette (desktop) — round 1

Context: the ⌘K / Ctrl+K palette (`src/components/CommandPalette.tsx`), opened from the keyboard, the sidebar's "Jump to…", and Help/app menu. Research: `docs/design/research/desktop-chrome.md` → "Command palette" (Vapi, Supabase, Navattic) and the M6 addendum (Juicebox, Grok, Devin). Stage: final polish. It has grown since M0: **Go to** (six sections), **Settings** (eight panes), **Help** (Keyboard shortcuts, Check for updates) and **Account** (Sign out).

Captures judged: `pnpm --filter @bfhr/desktop capture:design chrome --axe` (+ `--locale tr|de`). The palette states are `palette`, `palette-filtered` ("mail") and `palette-empty` ("salary"), opened with ⌘K in WebKit (≈ macOS WKWebView, macOS chrome) and Ctrl+K in Chromium (≈ Windows WebView2, Windows chrome), light + dark, 1280 × 800: `artifacts/screens/desktop/harness/{webkit,chromium}/{,tr/,de/}chrome-palette*-{light,dark}-1280x800.png`. Keyboard probe: Playwright, no pointer (see [keyboard-pass.md](../keyboard-pass.md)).

### Overall Impression

Quiet and fast: the field has focus at once, Today is preselected, and every section shows its two shortcuts, so the palette teaches the keys. The problems were at the edges: an empty result left an invalid widget behind, and closing the palette lost the user's place.

### Usability

| Finding                                                                                                                                                                                                                                      | Severity    | Recommendation                                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Esc (or a click outside) dropped focus on `<body>`: the palette has no Radix trigger, so Radix had nothing to return to. A keyboard user opening it from the sidebar's "Keyboard shortcuts" row had to Tab from the top of the window again. | 🟡 Moderate | Remember what had focus when the palette (or the sheet) opened and return there on close; commands that move focus themselves (Go to, Keyboard shortcuts) keep doing so. |
| Choosing a Settings pane (or ⌘, / Ctrl+, from anywhere) navigated but left focus on `<body>`; the section commands already focus the new section's title.                                                                                    | 🟡 Moderate | Settings commands focus the pane title too, the same as Go to.                                                                                                           |
| With no match, the result list stayed an empty listbox under the message (see Accessibility).                                                                                                                                                | 🟡 Moderate | Hide the list when nothing matches; announce the empty message.                                                                                                          |
| At 1280 × 800 the eight Settings panes push Help and Account below the fold (the list scrolls at 360 px).                                                                                                                                    | 🟢 Minor    | Keep: typing filters ("sign" → Sign out), and the order puts the frequent rows first.                                                                                    |

### Visual Hierarchy

- **What draws the eye first**: the input (largest text, top), then the preselected row's teal fill. Correct: type or press ↵.
- **Reading flow**: group heading → icon → label → keycaps on the right. Keycaps are secondary (smaller, sunken) and never compete with the labels.
- **Emphasis**: one selected row, no accent anywhere else. The scrim dims the app enough that the palette reads as modal without hiding where you are.

### Consistency

| Element        | Issue                                                                                                                 | Recommendation |
| -------------- | --------------------------------------------------------------------------------------------------------------------- | -------------- |
| Footer hints   | Same keycap style as the sheet and the sidebar ("↑ ↓ to move · ↵ to open · esc to close").                            | —              |
| Group headings | "Go to · Settings · Help · Account" match the native menu's order (app menu → Settings…, Help → Keyboard Shortcuts…). | —              |
| Empty message  | Same calm tone as the rest ("Nothing matches that yet. Try a section name, like “Jobs”."), in TR (siz) and DE (du).   | —              |

### Accessibility

- **Color contrast**: axe passes on every palette state in both themes and engines; the selected row's text stays `fg-primary` on `surface-selected`.
- **Touch targets**: 36 px rows, pointer and keyboard both work.
- **Text readability**: 14 px labels, 11 px footer hints (hidden from assistive tech; the combobox already announces the keys).
- See [accessibility.md](accessibility.md).

### What Works Well

- The first row is selected, so ↵ always does something (Base44).
- Each section row shows ⌘1 / Ctrl+1 **and** the `G T` sequence: the palette is where people learn the keys (Supabase).
- Sign out saves open edits first, and the palette closes before anything changes.

### Priority Recommendations

1. **Return focus on close**: the palette is opened from the keyboard; losing focus breaks the very flow it serves.
2. **No empty listbox**: a valid widget in every state.
3. **Settings commands land on the pane title**, like the sections.
