## Design Critique: ATS check

### Overall Impression
Facts, not grades: fractions, a neutral bar, "Keyword checks are a guide, not a guarantee". But the tab offered two keyword checks at once (a pasted description against the PDF, and a saved job against the CV) with nothing telling them apart, and on the live app (no saved jobs yet) it said "Save a job, then check…" right under a box that accepts a pasted job.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Two keyword coverages stacked without headings: "Job description" (paste, compares with the PDF) above "Check against" (saved job, compares with the CV), each with its own fact line, bar and disclaimer. Users can't tell which number answers which question. | 🟡 Moderate | Give the saved-job block its own heading ("Keywords from a saved job"), put it first (live, no export needed), then the PDF check with its paste box. |
| With no saved jobs (always the case in M2's live app), the tab ends with "Save a job, then check which of its keywords your CV covers." directly below a working paste box: contradictory and a dead end. | 🟡 Moderate | Without saved jobs show only the PDF check; the paste box is the keyword check. |
| A section that didn't read back is a red ✕ (`danger-text`). The system reserves red for errors; this is something to fix, and the research asks for "no blame". | 🟡 Moderate | Amber for both "Partly read back" and "Not found", told apart by icon shape and the status text. |
| Repeated "Add to Skills" / "I don't have this" buttons in the saved-job list don't say which keyword they act on when reached by Tab. | 🟢 Minor → fixed anyway | Describe each button by its keyword (`aria-describedby`). |
| On failure the "Try again" button sits above the error that explains it. | 🟢 Minor | Order is acceptable (button is where "Run check" was); could move into the alert's action later. |
| Coverage of a pasted description needs a run first ("Run the check to compare these keywords with your PDF."), while the saved-job coverage is live. | 🟢 Minor | By design (it compares with the PDF text); the hint says so. |

### Visual Hierarchy
- **What draws the eye first**: the primary "Run check". Correct for the idle state.
- **Reading flow (after fix)**: saved job (when there is one) → PDF read-back → pasted description.
- **Emphasis**: neutral bars, fractions; status as icon + text.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Headings | PDF block had an h3, saved-job block had none. | Fixed. |
| Status colours | Red ✕ vs calm principle. | Fixed. |

### Accessibility
- **Color contrast**: warning-text on base 5.28 / 5.97:1; success-text 5.32 / 6.36:1.
- **Live regions**: the read-back summary is announced once (`role="status"`); "Added to Skills…" is a status.

### What Works Well
- "What a parser sees" shows the raw extracted text, focusable and scrollable.
- Stale results say so ("You've edited your CV since this check.").

### Priority Recommendations
1. **One clear structure for the two keyword checks**, and no contradictory empty state.
2. **No red for read-back results.**

## Resolution

| # | Finding | Severity | Status |
|---|---------|----------|--------|
| 1 | Two unlabelled keyword checks | Moderate | Fixed: `CheckTab` renders a `section` headed "Keywords from a saved job" (`cv-editor.check.savedJobHeading`, select label now "Job"), first, then the PDF check. |
| 2 | Contradictory "Save a job…" empty state | Moderate | Fixed: without saved jobs the tab is the PDF check alone; `cv-editor.check.noJobs` removed from all catalogs. |
| 3 | Red "Not found" | Moderate | Fixed: `missing` uses `text-warning-text` with the ✕ icon (`AtsCheckPanel.tsx`). |
| 4 | Ambiguous repeated buttons | Minor | Fixed: `aria-describedby` → the keyword. |
| 5 | Try again above the error | Minor | Logged. |
| 6 | Pasted coverage needs a run | Minor | Logged (by design). |
