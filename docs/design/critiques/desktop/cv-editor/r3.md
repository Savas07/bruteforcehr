# CV editor (desktop) — critique round 3 (real app, Windows)

Source: Main's review of the Windows CI real-app captures (WebView2, classic scrollbars), `artifacts/ci/windows-design/cv-editor-*` in the main checkout. Round 2's browser-harness captures didn't show this because Playwright's Chromium and WebKit use overlay scrollbars.

## Findings

### Usability / Visual Hierarchy
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| The section jump bar (Header · Summary · Experience …) draws a horizontal scrollbar under itself in WebView2, so a 32 px strip turns into ~50 px with a scrollbar that looks broken. Same risk for the inspector tab list. | 🟡 Moderate | Hide the strip's scrollbar. It still scrolls by wheel/trackpad, and Tab scrolls focused buttons into view. Move to the shared horizontal-strip utility when it lands. |
| The preview pane shows scrollbars on both axes at fit zoom. Cause: the off-screen measuring copy (the page's content width, ~674 px) sat inside the scrollport and added horizontal overflow. The fit was also computed from the observer's box rather than the scrollport, so the classic vertical scrollbar wasn't accounted for. The zoom read 37 % instead of the 40 % seen on macOS. | 🟡 Moderate | Move the measuring copy outside the scrollport. Compute the fit from `clientWidth` (scrollbar-independent) and round it down. Reserve the gutter (`scrollbar-gutter: stable`) so the fit doesn't jump when the pages start to overflow. |

## Resolution

| # | Finding | Severity | Status |
|---|---------|----------|--------|
| 1 | Jump bar / inspector tabs show a horizontal scrollbar in WebView2 | Moderate | Fixed (ea5c692): both strips use `HORIZONTAL_STRIP` (`features/cv-editor/strip.ts`, interim: `overflow-x-auto`, scrollbar hidden). This gets swapped for DesktopFoundation's shared strip utility once it's on main. |
| 2 | Preview scrollbars on both axes; fit read off the observer box | Moderate | Fixed (ea5c692): the measuring copy now sits in a zero-size clip outside the canvas. Fit = ⌊(`clientWidth` − 48) / page width⌋ to the nearest 1 %. Stable scrollbar gutter. When zoomed past fit, the page container is `w-fit min-w-full`, so wide pages scroll from their left edge instead of being cut off by centring. |

Verification (Playwright, 1280 × 800 and 1920 × 1080). Chromium was forced to classic scrollbars (`--disable-features=OverlayScrollbar`) to stand in for WebView2:

| Engine | Width | Canvas `clientWidth` / `offsetWidth` | `scrollWidth` | Jump bar scrollbar height | Fit |
|---|---|---|---|---|---|
| Chromium, classic scrollbars | 1280 | 347 / 362 | 347 (no horizontal overflow) | 0 | 37 % |
| Chromium, classic scrollbars | 1920 | 526 / 541 | 526 | 0 | 60 % |
| WebKit (overlay) | 1280 | 362 / 362 | 362 | 0 | 39 % |
| WebKit (overlay) | 1920 | 541 / 541 | 541 | 0 | 62 % |

On Windows the fit still reads 37 % at 1280. That's correct: the reserved 15 px scrollbar gutter leaves a narrower scrollport, and the page now fits it exactly with no horizontal scrollbar. macOS reads 39 % (rounded down from 40.4 %). axe on populated and offline × light/dark × both engines: 0 serious, 0 critical.
