## Design Critique: Export

### Overall Impression
Short, honest dialog: "The file is made on this device; nothing is uploaded", a live file-name preview and a guard that refuses to export "[X%]". Two gaps: the segmented controls had no visible labels, and the placeholder guard left the user to hunt for the placeholder.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Format and Paper are two bare segmented controls (names only in `aria-label`); sighted users see "PDF · Word (DOCX) · JSON Resume" and "A4 · US Letter" with nothing saying what they choose, and the tracks stretched to the full dialog width with the segments bunched left. | 🟡 Moderate | Visible "Format" / "Paper" labels; tracks sized to their content. |
| "Fill in 1 placeholder first … [X%]" disables Export but offers no way to the placeholder; the user must close the dialog and search the form. | 🟡 Moderate | "Show in CV" on the alert: close the dialog and focus the field that holds the first placeholder. |
| The file-name line is `aria-live`, so every keystroke in Company re-announces "File name: …". | 🟢 Minor | Acceptable (confirms the result); revisit if screen-reader users find it chatty. |
| Paper here overrides the CV's paper for this file only; nothing says so. | 🟢 Minor | The preview line in the inspector shows the CV's paper; low risk. |
| Windows real-app print failure. | — | Not a design issue; the copy shown ("We couldn't make the file. Your CV is fine; try again, or pick another format.") is right for it. |

### Visual Hierarchy
- **What draws the eye first**: title "Export Base CV — English", then the primary "Export…". Correct.
- **Reading flow**: format → paper → company → resulting file name → guard/error → actions.
- **Emphasis**: the file name in mono stands out as the outcome.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Labels | Company had a visible label; the segmented controls didn't. | Fixed. |
| Disabled Export | Uses `disabledReason` (tooltip + description). | — |

### Accessibility
- **Color contrast**: footnote labels fg-secondary on elevated 7.84 / 7.23:1; warning alert passes.
- **Targets**: segments 24 px, buttons 32 px.

### What Works Well
- The privacy line answers "does this upload my CV?" before it's asked.
- Placeholders block every format, not just PDF.

### Priority Recommendations
1. **Visible labels for Format and Paper.**
2. **A way from the placeholder warning to the placeholder.**

## Resolution

| # | Finding | Severity | Status |
|---|---------|----------|--------|
| 1 | Segmented controls without visible labels; stretched tracks | Moderate | Fixed: each group has a visible footnote label (`aria-hidden`, the group keeps its `aria-label`) and an `items-start` column so the track hugs its segments. |
| 2 | No path to the placeholder | Moderate | Fixed: the warning's action "Show in CV" (`cv-editor.export.showPlaceholder`) calls `onShowPlaceholder(path)`; `Screen.tsx` closes the dialog and runs `locate(path)` (expands the section/item and focuses its field). Harness: `export-placeholder-located-*`. |
| 3 | Chatty file-name live region | Minor | Logged. |
| 4 | Paper scope not stated | Minor | Logged. |
