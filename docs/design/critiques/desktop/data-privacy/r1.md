## Design Critique: Data & privacy

### Overall Impression

Calm and specific. The page says what the ZIP contains and what it never contains, shows the export's progress in place, and keeps deletion one deliberate step away. The first pass had three problems: a red-tinted list that made the dialog feel alarming, no way to make a fresh export while one was ready, and duplicate "Deleting your account…" text (button label + note + tooltip) during deletion.

### Usability

| Finding | Severity | Recommendation |
| --- | --- | --- |
| The itemized "This permanently deletes" list sat in a red (`danger-subtle`) box; with the destructive button also tinted, the dialog read as an alarm rather than an explanation. | 🟡 Moderate | Neutral sunken box, "This can't be undone." in semibold. |
| With an export ready there was no way to make a new one (e.g. after editing CVs) until the card expired 7 days later, while the footnote says "Making a new export replaces it." | 🟡 Moderate | Plain "Create export" under the ready card. |
| Deleting: the button's loading label, the progress note and the focused "Keep my account" tooltip all said "Deleting your account…", the tooltip covering the note. | 🟡 Moderate | One progress note (role=status); the destructive button keeps its label with a spinner; "Keep my account" no longer shows a disabled tooltip (closing is ignored while deleting). |
| In the "Link sent" step, the plain "Send link" button's padding misaligned it from the text above. | 🟢 Minor | `-ml-3`. |
| "Keep my account" looks enabled during deletion although closing is ignored. | 🟢 Minor | Accept: deletion takes seconds, the progress note is announced, and the button can't cause harm. |
| Enter in the confirm field never submits; Esc and outside clicks close (except while deleting). | — | Keep. |
| Refusals (too soon, daily limit, too large) use the info tone, not error; only a failed request is an error with Try again. "Too large" offers Open GitHub (support channel). | — | Keep. |

### Visual Hierarchy

- **First**: the page heading, then "Export everything" with the primary "Create export". Deletion is a separate section at the bottom with a tinted destructive button (Render placement).
- **Dialog**: title → what is deleted → "Export my data first" → the confirm field → the re-authentication step when needed → "Keep my account" (initial focus) / "Delete everything".

### Accessibility

- **axe** (WCAG 2.1 A/AA): 0 critical · 0 serious · 0 moderate · 0 minor on all 80 English captures and the 20 TR/DE spot captures.
- **Keyboard**: dialog opens with focus on "Keep my account"; Tab reaches "Export my data first", the field, the re-auth button and "Delete everything"; focus returns to "Delete account…" (or to the export button after "Export my data first").
- **Disabled buttons say why** (`disabledReason`): "To confirm, type DELETE", "Confirm it's you", "Needs a connection".

### What Works Well

- The included / not-included lists answer "is my password in this file?" before the user asks.
- The ready card shows size and the exact local expiry; Save… uses the native save dialog.
- Re-authentication happens inside the dialog: the typed word survives, and the step names the address the link goes to.

### Priority Recommendations

1. Neutral list box in the dialog.
2. "Create export" while one is ready.
3. One progress message while deleting.

## Resolution

| # | Finding | Severity | Status |
