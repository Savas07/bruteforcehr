- **Screen:** Insights (`/insights`), desktop. **User goal:** see how far applications get and where replies come from, then open those applications. **Stage:** refinement (light design protocol: populated light + dark while iterating, full matrix + a11y at the end).
- **Method:** `skill://design-critique` on harness captures (looked at each image): `artifacts/screens/desktop/harness/{webkit,chromium}/insights-{populated,empty,loading,error,offline}-{light,dark}-{1280x800,1920x1080}.png`, plus full-height scratch captures at 640, 1280 and 1920 px (populated light/dark, empty, low sample `?range=30d&source=lever`, error, offline).

## Design Critique: Insights (desktop)

### Overall Impression
Calm and legible: one teal series hue, every rate next to its count, sentence titles. The first iteration had uneven funnel bars, a cramped breakdown table and fake-looking "—" rates in the low-sample funnel; all fixed in this round.

### Usability
|Finding|Severity|Recommendation|
|---|---|---|
|Funnel bars had different widths (the step chip took space from the next bar), so bar area misread as volume.|🟡 Moderate|**Fixed**: equal columns, the step chip sits in the gap.|
|Breakdown table at 1280 wrapped "Too few to compare" and headers on 3 lines.|🟡 Moderate|**Fixed**: 3fr/2fr row, nowrap low-sample label, "First response" header (ⓘ defines median).|
|Low-sample funnel showed "2 · —" and "— →" chips: zeros dressed as data.|🟡 Moderate|**Fixed**: counts only, no chips; the "Not enough applications yet…" note explains.|
|First use showed range, compare, filters and Export over nothing.|🟡 Moderate|**Fixed**: title + empty state + "Open Tracker" only.|
|Week labels truncated ("10 A…", "This…").|🟢 Minor|**Fixed**: every third week + "This week"; every bar's name carries its date.|
|KPI tiles went single column at 640 px.|🟢 Minor|**Fixed**: 2 columns, 5 from 52 rem container width.|
|Breakdown row checkboxes (add series to the weekly chart, research "Substack") not built.|🟢 Minor|Deferred: the chart is single-series by design (series toggle); logged for M6 polish.|

### Visual Hierarchy
- **First:** title + range, then the KPI strip. Correct.
- **Flow:** KPIs → funnel (+ table) → breakdown | activity. Question titles make each card's purpose clear.
- **Emphasis:** no deltas by default; "Compare" deltas are neutral text ("+3 vs. previous 30 days"), never red/green.

### Consistency
|Element|Issue|Recommendation|
|---|---|---|
|Colors|Only `chart.series`, `chart.grid`, surfaces; status hues not reused.|—|
|Controls|Shared `SegmentedControl`, `ExportButton` (Mod+E), `EmptyState`, `PaneError`, `StaleStamp`.|—|

### Accessibility
- Every datum is a `<button>` named by its visible content, described by the full sentence + "Opens these applications in Tracker." Funnel and breakdown are real tables (scrollable regions focusable at narrow widths). Weekly bars use roving focus with ←/→/Home/End.
- No colour-only encodings: numbers print on every bar; low-sample rows say "Too few to compare".

### What Works Well
- Drill-downs resolve through `@bfhr/core` `selectDrillDownIds`, so the Tracker table shows exactly the counted set.
- Calm copy: "Still waiting", "marked no response", no goals or streaks.

### Priority Recommendations
1. Equalise the funnel bars. 2. Remove fake "—" data in low sample. 3. Strip first use to the explanation.

## Resolution
All Moderate findings fixed in this round (commits on `m3/insights`). Remaining: one Minor deferred (row checkboxes). Zero Critical, zero open Moderate. Real-app (Tauri) captures and Windows run via CI.
