## Design Critique: Jobs — job detail

### Overall Impression
At 1280 the match now sits in the first screen (band, "88 of 100", bar, basis line, counts), the action row reads as one line, and offline explains itself in place. What's left is mostly behaviour detail: how corrections look, how hidden jobs navigate, and how the Turkish offline header wraps.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| "I have this" strikes the gap through ("~~German at B2 or above; your CV lists A2~~"). Strikethrough reads as "deleted / wrong", and the posting's requirement didn't go away; the user only told us they have it. | 🟡 Moderate | Keep the text, switch the glyph to ✓ and show "Added to your profile. We'll update the match. · Undo" under it. |
| A hidden job opened from a deep link shows ↑ / ↓ with no position, and the disabled tooltip reads "↑ ↓ to move · Enter to open", which isn't a reason. At the ends of the list the same wrong reason appears. | 🟡 Moderate | Hide prev / next when the job isn't in the list; at the ends say "This is the first / last job in the list". |
| Not for me: the placeholder row ("Hidden: … · Undo · Why?") keeps the hidden job in the list, so the row doesn't really disappear and Undo appears twice (row + toast). D19 specifies the toast "Hidden from your feed · Undo · Why?" now that the toast supports a second action. | 🟡 Moderate | Remove the row instantly; toast carries Undo and Why?; the reason popover anchors where the row was. |
| In the real app, `openExternal` only allows the app's own sites, so Open original, Apply ↗ and "Found on" links would fail for job sites. | 🔴 Critical | Use `openJobUrl` (any public https job link) from main; keep the toast on rejection. |
| Turkish, offline: the list header splits into three cramped columns ("37 / ilan", "Güncelleme: / 10:05", "Sıralama: En iyi / eşleşme"). | 🟡 Moderate | Let the header wrap by item (count, then stamp + sort), each item on one line. |
| German: the action row wraps "•••" alone onto a second line at 1280. | 🟢 Minor | Accept: wrapping is the system rule for DE; the overflow stays reachable and in order. |
| German: the search placeholder truncates ("Nach Titel, Unternehmen oder Ort su…"). | 🟢 Minor | Widen the field to 384 px. |
| Stretch band: the bar fills the "Stretch" segment with the accent, which can read as "good". | 🟢 Minor | Shared `MatchBandBar`; logged as a taste question for the user rather than forked. |
| Loading: the list skeleton is 400 px wide while the loaded list starts at 340 px below 1440 px, so the splitter jumps. | 🟢 Minor | Pass the same `listPane` to the loading `SplitView`. |

### Visual Hierarchy
- **What draws the eye first:** Apply (filled teal), then "Strong match". Correct.
- **Reading flow:** header → actions → three facts not already in the header → match → description. Wide panes keep Details / Apply / Found on in the rail.
- **Emphasis:** impact is now quiet tertiary text in requirements but still a bordered tag in "Why it matches" and "Gaps" cards.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Impact labels | Inline text in Requirements, bordered tags in factor cards. | Inline tertiary text everywhere. |

### Accessibility
- **Color contrast:** unchanged pairings, all allowed.
- **Touch targets:** the "Sorted by Best match ⓘ" button is 16 px tall (below the 24 px desktop minimum).
- **Text readability:** fine in TR / DE; no truncation of meaning-carrying labels.

### What Works Well
- The compact facts strip keeps visa, relocation and last seen visible without pushing the match down.
- The offline footnote is calm and gives the next step ("You can save the job now…").
- The reason popover's number keys and equal-weight Skip / Save reason make the optional step genuinely optional.
- Delisted reads as one warning sentence with the source and date.

### Priority Recommendations
1. **Open job links through `openJobUrl`** — otherwise the main actions fail in the app.
2. **Match D19 for Not for me** — instant removal, one Undo, Why? in the toast.
3. **Don't strike through corrected gaps** — the user's correction shouldn't look like deletion.
