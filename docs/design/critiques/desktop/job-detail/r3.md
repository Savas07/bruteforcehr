## Design Critique: Jobs — job detail

### Overall Impression
The screen does its job in one glance at both window sizes: what the job is, how well it fits and why, and the one primary action labelled by where it goes. Copy is calm throughout (no "%", no verdicts, "Not for me" is the user's call, gaps are "to consider"). Nothing blocks the persona's goal; what's left is polish and taste.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| The AI block says "AI" twice: the shared "AI-assisted" badge and the label "AI summary · can be wrong". | 🟢 Minor | Keep both for now: the badge is the shared marker users learn across screens; the label carries the required disclaimer. Revisit if the user finds it noisy. |
| At 200 % zoom (640 × 400 CSS px) the fixed screen header, Back bar and prev/next bar take ~260 px before the job starts. Content still reflows without horizontal scrolling. | 🟢 Minor | Logged: candidate for a compact header in pushed mode (shared `SplitView` / shell decision). |
| First use: "Search jobs" focuses the search field, but search only filters jobs already collected; finding new jobs (sources, saved searches) arrives in M4. | 🟢 Minor | Logged: the model's first-use copy targets the M4 flow; keep. |
| List rows: salary provenance wraps to two lines at the 340 px list width ("· from / employer"). | 🟢 Minor | Logged (from r1): open taste question. |

### Visual Hierarchy
- **What draws the eye first:** "Apply on company site ↗" (filled, the only accent fill in the pane), then "Strong match · 88 of 100" and the bar. Correct for a decision screen.
- **Reading flow:** company · posted → title → chips → salary → actions → (offline note) → facts strip / rail → match → description → sources. Consistent in both engines.
- **Emphasis:** the number stays secondary, impacts are quiet tertiary text, warnings use amber text with a glyph, nothing is red.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| — | No inconsistencies found: one tag style (`SourceTag`), one impact style, shared `MatchBandPill` / `MatchBandBar`, `StatusPill` with "Not selected" in grey, shared toast with Undo + Why?. | — |

### Accessibility
- **Color contrast:** only allowed token pairings; axe (WCAG 2.1 A/AA) reports 0 violations in all 20 state × theme × engine runs.
- **Touch targets:** action row 32 px, row actions and AI feedback 24 px, sort info and source links ≥ 24 px.
- **Text readability:** body 14/20, nothing meaningful below 12 px; TR / DE wrap instead of truncating labels.

### What Works Well
- Band label first, "88 of 100" second, segmented bar with labelled segments; the basis line says which CV and how fresh.
- Every requirement and factor carries its evidence; AI output is labelled and correctable (👍 / 👎, "I have this", "Add to CV…").
- "Found on" puts the employer's own listing first, tags the one Apply uses, and footnotes fields that differ.
- Not for me is instant with one Undo and an optional "Why?"; triage continues on the next row with focus kept.
- Offline keeps the job readable and says in place why Apply waits.

### Priority Recommendations
1. **Decide the Stretch segment colour** (taste; shared component).
2. **Consider a compact header for the pushed detail** at very small widths / high zoom.
3. **Revisit salary provenance length in rows** if the user wants shorter rows.
