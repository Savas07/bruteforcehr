## Design Critique: Jobs — feed header, filter bar, list header, zero results

### Overall Impression
In English at 1280 the header is tidy: title, search, Search job sites, then Saved searches… and Add from link at the right, with eight pills and Save search on one line. It falls apart in German (three header rows, Save search alone on a fourth), the sort the header announces can't be changed, and the zero-results state hides *which* filter to relax even though the model already lists them.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| 1. Zero results by filters shows only "Remove all filters". The active filters (listed in `model.list.empty.chips`) are not rendered, so the user can't relax just the one that over-narrows (job-feed-search.md "Decision — Desktop" 7). | 🟡 Moderate | Render one removable chip per active filter between the text and the actions, each removing only its facet, with the jobs it alone brings back ("Seniority: Intern +3 ×", Zillow / Pinterest). |
| 2. "Sorted by Best match ⓘ" is a tooltip button. Newest is only reachable by editing the URL (`?sort=newest`); the research decision says "Sort: Best match ▾". | 🟡 Moderate | Make it the sort menu: `MenuContent` + `MenuRadioGroup` with `model.filterBar.sort` (Best match ✓ / Newest), navigating with the same filter params; keep the ranking note in the menu and as the trigger's description. |
| 3. DE at 1280: "Gespeicherte Suchen…" and "Aus Link hinzufügen" wrap below the search row, the pills take a third row and "Suche speichern" a fourth; the header grows from 110 to ~180 px and pushes the list down. | 🟡 Moderate | Let the search form shrink (field 192–384 px, `flex-1`), put Search job sites inside the form next to the field, 16 px gaps: one header row in EN, DE and TR. |
| 4. Save search drops to its own line whenever the pills wrap (always in DE; in EN with two long active values like "Salary: From €200,000 a year"), 40 px of mostly empty row. | 🟡 Moderate | Pills (and Clear all) wrap inside their own group; Save search stays at the right end of the first line. |
| 5. With zero results the detail pane says "Select a job to see the details · ↑ ↓ to move · Enter to open"; there is nothing to select. | 🟡 Moderate | Leave the detail pane empty while the list is empty. |
| 6. Zero results body "Try removing one, or search the job sites for more." also shows without search text, where no job-site search is offered. | 🟡 Moderate | Without search text: "Try removing one to see more of your jobs." |
| 7. Search job sites, disabled with an empty field, gives the placeholder as its reason ("Search by title, company, place or skill"). | 🟢 Minor | Say what to do: "Type a role or skill in the search field first." |
| 8. Search job sites sits 24 px from the field, the same distance as Saved searches…, so it reads as a second, separate search. | 🟢 Minor | Group it with the field (8 px) inside the `role="search"` form; Enter in the field runs it too. |
| 9. Zero results by search: "Search job sites for “zzzz”" is a full-width secondary button 40 px under the empty state's own button. | 🟢 Minor | Stack it under Clear search as a plain (text) action with its icon. |
| 10. Loading and error states have no filter bar, so the header grows ~45 px when the feed arrives. | 🟢 Minor | Log: a pill skeleton needs the facets, which come with the data. Unchanged from r1's "sidebar jumps" fix scope. |
| 11. The DE placeholder truncates at 1280 ("Nach Titel, Unternehmen, Ort oder S…"). | 🟢 Minor | Accept: the field is named "Stellen suchen" for screen readers and the placeholder is a hint; the text ellipsis is shown. |

### Visual Hierarchy
- **What draws the eye first:** the filled Save search and Apply buttons, then the selected row. Correct; the pills stay outlined until active, active pills take `accent.subtle`.
- **Reading flow:** title → search → Search job sites → filter pills → list count + sort → rows. With the fixes the header is two lines (search row, pills row) in all three languages.
- **Emphasis:** the sort is quiet secondary text with a chevron, so it doesn't compete with the count (NYT / Contractbook).

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Menus | The list header used a tooltip-only button while the CV "Change ▾" in the same pane is a `MenuRadioGroup`. | Same shared menu parts for the sort. |
| Chips | Zero-results chips should look like active pills (accent subtle, footnote, 28 px) with an ×, like the Tracker table's removable filter chips. | Same tokens; the whole chip is one button (bigger target, one Tab stop). |
| Reset | Each popover's Reset and each chip clear one facet; two code paths could drift. | One `clearFacet(state, facet)` used by both. |

### Accessibility
- **Color contrast:** only tested pairings: `accent.text` on `accent.subtle` (chips, active pills, 5.77 / 6.27 : 1), `fg.secondary` on `surface.base` (sort trigger, 7.84 : 1 light), `fg.tertiary` for the ranking note in the menu (≥ 5.18 : 1).
- **Touch targets:** pills, chips 28 px; sort trigger 24 px (`min-h-6`); buttons 32 px.
- **Text readability:** chips and pills footnote 13/18; the ranking note caption 12/16, max 240 px wide. Details in `accessibility.md` (round 5).

### What Works Well
- One-line filter bar in EN and TR at 1280; active pills say their value ("Work mode: Remote", "Seniority (2)").
- Popovers apply live and say "Show 34 jobs" (see `../jobs-search/r1.md`).
- The Tab walk is logical and every stop shows the 2 px ring: sidebar → search → Search job sites → Saved searches… → Add from link → 8 pills → Save search → sort → list (one stop) → splitter → detail.

### Priority Recommendations
1. **Render the zero-results chips** — the fastest way out of an over-narrow search.
2. **Make the sort a menu** — the header promises a choice it doesn't offer.
3. **Keep the header to two lines in every language** — shrinkable search, grouped Search job sites, Save search pinned on the first line.

## Resolution

| # | Finding | Severity | Resolution |
|---|---------|----------|------------|
| 1 | Zero-results chips not rendered | 🟡 | **Fixed**: `EmptyResults` (`JobList.tsx`) renders `RemoveChip`s from `removableChips()` (`filterBarModel.ts`); each removes one facet via `clearFacet` and shows "+n" (jobs that facet alone hides, computed in `model.ts`), focus moves to that facet's pill.
