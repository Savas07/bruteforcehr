# Settings › Job preferences (desktop) — critique round 1

Skill: `design-critique`. Context: the onboarding preferences form as a Settings pane (720 px content column, autosave per section; onboarding-signin.md addendum, D41). Stage: refinement. Focus: density in the pane, save feedback, values that came from another device.

Captures judged: `settings-job-preferences` populated (persona Deniz: four roles, five places, salary floor, four authorization answers, three languages), WebKit and Chromium, light and dark, 1280×800 and 1920×1080.

## Design Critique: Settings › Job preferences

### Overall Impression

The pane reads like the other Settings panes: a one-line intro, then labelled sections in two columns. Everything a match depends on is visible and editable in one place.

### Usability

| Finding                                                                                                                                     | Severity | Recommendation                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------- |
| "Saved" appears in the label column of the section that changed, under its helper; a quick second change in another section moves it there. | —        | Works as designed (one saver, last section).                                                  |
| Role suggestions (six chips) take a lot of height when four roles are already set.                                                          | 🟢 Minor | Log: they vanish at the limit of five; fewer would hide the fastest way to add the last role. |
| A region answered on another device but no longer among the places (e.g. US with only "United States (remote)") still gets its question.    | —        | Intended: the answer matters to matching; removing it is "Not sure".                          |
| Clearing the name and leaving the field keeps the stored name and says so ("We kept the one you had").                                      | —        | —                                                                                             |

### Visual Hierarchy

- **What draws the eye first**: the pane title, then "Your name" and the role tokens. Correct: roles drive both matching and the first saved search.
- **Emphasis**: selected chips use the accent subtle fill with ✓; no filled buttons in the pane (autosave).

### Consistency

| Element      | Issue                                                                                                                                                                                              | Recommendation |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| Section rows | Own two-column row instead of `SettingsSection` + `SettingsRow`, because each section holds several controls. Same 200 px label column as onboarding; dividers and headings match the other panes. | —              |

### Accessibility

- axe clean, both engines and themes (accessibility.md).

### What Works Well

- One component in onboarding and Settings: what the user set during setup looks the same when they come back to it.
- Salary floor keeps currency and period next to the amount, with the privacy note right there.

### Priority Recommendations

None above Minor.
