# Import a job from a link (desktop) — critique round 1

- **Screen:** "Add a job from a link" dialog over the Jobs list (`/jobs?import=1`, `features/jobs-import/ImportJobDialog.tsx`).
- **User goal:** turn a posting they found elsewhere (career page, job board, LinkedIn) into a job in their feed, with details they trust, in under a minute.
- **Persona:** active job seeker, often stressed and short on time; pastes links from the browser, keyboard-first on desktop.
- **Stage:** refinement. **Focus:** the step-1 → step-2 hand-off, trust in what was read, and the fallback when a site can't be read.
- **Captures judged** (WebKit, 1280 × 800, light + dark):
  - `pnpm --filter @bfhr/desktop capture:design jobs-import --states populated --themes light,dark --sizes 1280x800 --engines webkit` → `artifacts/screens/desktop/harness/webkit/jobs-import-populated-{light,dark}-1280x800.png` (step 1).
  - Ad-hoc Playwright on the same design dev server (link typed, Enter, then the step) → `artifacts/screens/desktop/harness/jobs-import-adhoc/r1-webkit-{reading,review,error,manual,manual-invalid,offline}-{light,dark}-1280x800.png`. The design build answers `importUrl` after ~1.2 s; a link containing `blocked` fails with `blocked_by_site`.

## Design Critique: Jobs — import a job from a link

### Overall Impression
Step 1 is calm and obvious: one field, one hint, "Read posting", Enter to read. The review form reads as a normal, editable job with a clear source line and a single quiet "Check this" on the salary. The weak spots are small: the wait shows its label twice, Back silently throws away edits, and the form leaves a half-empty row.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Reading: "Reading the posting…" appears twice, as the status line and as the primary button's loading label, so the eye bounces between them and screen readers hear it twice. | 🟡 Moderate | Keep the status line (it carries the 10 s note); the button says just "Reading…". |
| Back on the review step drops every edit without asking, while Cancel/Esc ask "Discard this job?". Same loss, two behaviours. | 🟡 Moderate | Back asks the same question when something was changed; Discard then goes back to the link. |
| "Visa sponsorship" sits alone in a row with an empty right column, and Location (often "Berlin · Munich · Remote EU") is squeezed into half a row. | 🟢 Minor | Location full width; Work mode + Employment type, Seniority + Visa sponsorship as pairs. |
| At 1280 × 800 the description starts at the bottom edge; the textarea is only seen after scrolling. | 🟢 Minor | Accept: it's the last, least-checked field and the body scrolls with the footer pinned. |
| After a failed read the link is selected again, ready to be replaced, and the alert offers "Enter it yourself". Good recovery. | — | Keep. |
| Offline: "Read posting" is disabled with its reason as tooltip and an inline "Reading a link needs a connection." with "Enter it yourself". | — | Keep (states.md rule 6). |
| Manual entry with nothing filled: the summary ("2 fields need a look") repeats the two inline errors right under it. | 🟢 Minor | Accept: same pattern as "Log an application" (summary only from 2 problems); the links move focus. |

### Visual Hierarchy
- **What draws the eye first:** the teal primary ("Read posting" / "Save job") and, on the review, the focused Role field. Correct.
- **Reading flow:** title → one-line description → provenance → form top to bottom → footer (Back · shortcut hint · Cancel · Save job).
- **Emphasis:** "Check this" is amber text with a dot, at caption size next to the label — noticeable without looking like an error. The provenance line is footnote-secondary with a globe (data) or sparkle (AI) icon.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Form controls | Same 32 px controls, footnote labels and error lines as "Log an application". | Keep. |
| Discard dialog | Same "Discard …? / Keep editing / Discard" as other editors. | Keep; extend to Back (above). |
| Low-confidence marker | `ConfidenceTag` says "Needs a look" with a filled chip; the brief asks for a quieter "Check this" next to the label. | Use the quieter inline flag here; it clears as soon as the field is edited. |

### Accessibility
- **Color contrast:** warning text (`warning.text`) on the elevated surface and danger text on inputs pass AA in both themes (token pairings). The disabled "Read posting" offline is exempt; its reason is in text.
- **Touch targets:** buttons 32 px, checkbox row 24 px min height.
- **Text readability:** callout 14/20 for controls, footnote 12/16 for hints and flags.

### What Works Well
- Local https check before any network call, with "jobs.acme.com/42" accepted as https.
- Provenance + host on every import ("Read from the page's job data · boards.greenhouse.io"); AI reads say "can be wrong".
- Every error is one sentence with the way forward; four reasons and offline offer the same form, empty, with the link prefilled.
- Footer promise "It goes to your Saved jobs." says where the job lands.

### Priority Recommendations
1. **One label for the wait** — the status line keeps "Reading the posting…", the button says "Reading…".
2. **Back asks before discarding edits** — same question as Cancel.
3. **Balance the grid** — Location full width, pairs below.

## Resolution
- Wait label: fixed — button `loadingLabel` is the new `jobs-import.dialog.readingShort` "Reading…" (TR/DE added).
- Back: fixed — Back with changes opens "Discard this job?"; Discard returns to the link step, Keep editing stays.
- Grid: fixed — Location `col-span-2`; Work mode | Employment type, Seniority | Visa sponsorship; Apply link | Apply by email.
- Description below the fold, summary repeating inline errors: accepted (see table).
