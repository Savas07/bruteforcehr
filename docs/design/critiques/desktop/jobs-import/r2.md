## Design Critique: Jobs — import a job from a link

### Overall Impression
The flow now reads as one calm path: paste → "Reading the posting…" → a balanced form that says where every value came from → "Save job · It goes to your Saved jobs." The fallback is the same form, so a blocked site never becomes a dead end.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| The wait shows "Reading the posting…" once, the button "Reading…"; after 10 s it adds "Some pages take up to 20 seconds. Closing this window stops reading." | — | Resolved (r1). |
| Back with edits now asks "Discard this job?"; without edits it returns to the link at once, link selected for replacing. | — | Resolved (r1). |
| Grid: Location full width; Work mode · Employment type and Seniority · Visa sponsorship pair up; no empty half-rows at either size. | — | Resolved (r1). |
| Loading / error states of the Jobs screen: the dialog isn't mounted until the feed is ready (owner's route wiring), so `?import=1` during loading shows only the skeleton. Reading a link doesn't need the feed. | 🟢 Minor | Owner decision (Jobs screen): mount the dialog in every state; the dialog itself only needs the repository. Logged for DesktopJobs. |
| At 1280 × 800 the description textarea starts near the bottom edge of the scroll area. | 🟢 Minor | Accepted (r1): last and least-checked field; the footer stays pinned. |
| At 1920 × 1080 the dialog stays 640 px wide and centred; all fields and the full description fit without scrolling. | — | Keep. |

### Visual Hierarchy
- **What draws the eye first:** the focused Role field and the teal "Save job"; on step 1 the link field and "Read posting". Correct.
- **Reading flow:** provenance line → identity (Role, Company, Location) → terms (mode, type, seniority, visa) → salary group with its "Check this" → apply route → description.
- **Emphasis:** only the salary carries "Check this" in the fixture (0.72 confidence); it clears once edited. The info alert "You already have this job. We'll add this link to it." appears above the form only when merging.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Footer | Back (plain) · shortcut hint · Cancel (plain) · primary, as other multi-step dialogs. | Keep. |
| Errors | One `InlineAlert` (warning tone) with one action: "Enter it yourself" or "Try again". | Keep. |
| Offline | Same offline footnote as "Log an application" on the form; "Reading a link needs a connection." on step 1. | Keep. |

### Accessibility
- **Color contrast:** axe clean in all 68 runs (20 harness + 48 ad-hoc). Harness "needs review" items are Radix focus guards and the dimmed page behind the scrim, not the dialog.
- **Touch targets:** 32 px buttons and controls; checkbox row ≥ 24 px.
- **Text readability:** callout controls, footnote hints; the amber flag is text + dot, never colour alone.

### What Works Well
- Provenance with host on every read; AI reads labelled "can be wrong" with the sparkle.
- Every error is one sentence with the next step; the four unreadable-page reasons and offline lead into the same form, empty, link prefilled.
- Keyboard: Enter reads, ⌘/Ctrl+Enter saves, Esc closes (asking first when edited); focus lands on the link, then on the first field to check.

### Priority Recommendations
1. **Mount the dialog in every Jobs state** (owner) — a link can be read while the feed loads.

## Resolution
- No Critical, no Moderate findings open. One Minor handed to the owner (mount in loading/error), one Minor accepted (description below the fold at 1280 × 800).
