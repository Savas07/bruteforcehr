- **Screen:** `jobs-search` in `apps/desktop/src/design/matrix.ts` — `/jobs?q=react&filters=1`: the Jobs feed with search text, a filter popover open over the list, and the on-demand "Search job sites" (`jobsSearch`) with its progress / result banner.

## Design Critique: Jobs search and filters

### Overall Impression
The popovers are right: titled, live, with Reset and "Show 34 jobs". But the captured screen contradicts its own URL — the list is filtered by "react" (34 of 37 jobs) while the search field is empty and Search job sites is disabled — and the live-search result says "90 postings found for “react”." next to a list of 34, without saying that none of them were new.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| 1. When the route's `q` changes while Jobs stays open (the harness's hash navigation; in the app a link, Back / Forward, or any navigation to `/jobs?q=…`), the field keeps its old text. The list is filtered by a search the user can't see or clear, and Search job sites is disabled because the field is empty. | 🔴 Critical | The field follows the route whenever `q` changes from outside; typing keeps working as before. |
| 2. `?filters=1` does nothing, so the `jobs-search` capture is the populated feed with a search text; no popover is ever reviewed in the matrix. | 🟡 Moderate | Make the open popover route state like the screen's dialogs (`?searches=manage`, `?import=1`): `?filters=<facet>` opens that pill (any other value: the first), closing removes the param. |
| 3. Done: "90 postings found for “react”." while the list shows 34 jobs; the user can't tell whether anything new arrived or where the 90 went. | 🟡 Moderate | Lead with what changed: "No new jobs for “react”" / "3 new jobs for “react”", then "Checked 90 postings, 30 already in your list." and the skipped sources. |
| 4. Running: only the title "Searching job sites for “react”…"; nothing says what will happen to the list. | 🟡 Moderate | Add "New jobs show up in the list as they're found." (Contractbook-style expectation). |
| 5. The banner's live region (`role="status"`) is created together with its first message, so the start of the search isn't reliably announced; the alert inside is a second `status` region, so updates can be read twice. | 🟡 Moderate | One polite live region that stays mounted; key each alert by state so only that region reports the change. |
| 6. The popover footer's "Show 34 jobs" and live count, Esc to close, Enter to apply, focus back on the pill. | — | Pass (Turo / Wellfound pattern). |
| 7. With search text, the zero-results state offers "Search job sites for “react”" — correct, and it uses the feed's filters. | — | Pass. |

### Visual Hierarchy
- **What draws the eye first:** the open popover, then "Show 34 jobs" (the only filled control inside it). Correct.
- **Reading flow:** pill → popover title → options → Reset · Show n jobs. The banner sits between the header and the split, full width, so it reads as the result of the header's action.
- **Emphasis:** the running and done banners use the info tone; failures use warning. Search job sites shows its spinner while running.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Overlay state | Dialogs on this screen are route state; the filter popover wasn't. | `?filters=<facet>` (finding 2). |
| Copy | "postings" (what sources return) vs "jobs" (what the list shows) were mixed in one sentence. | Title in jobs ("new jobs"), detail in postings ("Checked 90 postings"). |

### Accessibility
- **Color contrast:** `info.text` on `info.subtle` for the banner title, `fg.primary` body; popover on `surface.elevated` with `fg.primary`; "Show n jobs" `fg.onAccent` on `accent.solid` (6.51 / 4.58 : 1).
- **Touch targets:** popover rows 32 px (`min-h-8`), footer buttons 24 px (`size="sm"`, the desktop minimum), pills 28 px.
- **Text readability:** popover options callout 14/20; notes caption 12/16.

### What Works Well
- Popovers change the list live and say how many jobs it will show, so "Apply" is never a guess.
- Skipped sources are named with the reason ("no access key yet"), not counted as failures.
- Search job sites is disabled with a reason offline and while running (spinner, repeat presses ignored).

### Priority Recommendations
1. **Keep the field and the URL in sync** — otherwise the list hides jobs for no visible reason.
2. **Say what the live search changed** — new jobs first, then what was checked.
3. **Announce the live search reliably** — a persistent polite region.

## Resolution

| # | Finding | Severity | Resolution |
|---|---------|----------|------------|
| 1 | Field out of sync with `q` | 🔴 | **Fixed** (`Screen.tsx`): the field adopts `params.q` whenever it changes from outside (state adjusted during render); `showSavedSearch` no longer sets the field itself. Test: `Screen.test.tsx` "shows the route's search text…". |
| 2 | `?filters=1` ignored | 🟡 | **Fixed**: `FilterBar` popovers are controlled (`openFacet` / `onOpenFacetChange`); `Screen.tsx` reads `?filters=<facet>` (unknown value → first facet, `FILTER_FACETS`) and clears it on close. Test: `Screen.test.tsx` "opens a filter popover from ?filters…". |
| 3 | Done banner unclear | 🟡 | **Fixed**: `job-detail.view.searchDone` (new jobs) + new `job-detail.view.searchChecked` (found, already in your list) + skipped sources; EN / TR / DE. |
| 4 | Running banner without expectation | 🟡 | **Fixed**: `job-detail.view.searchingBody`. |
| 5 | Live region mounted with its message | 🟡 | **Fixed**: persistent `aria-live="polite"` wrapper, alerts keyed `running` / `done` / `failed`. |
| C1 | Overlay state | — | **Fixed** with #2. |
| C2 | postings vs jobs | — | **Fixed** with #3. |
