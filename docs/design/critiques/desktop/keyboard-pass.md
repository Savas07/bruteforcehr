# Desktop keyboard-only pass (BRIEF §9)

Date: 2026-10-24 · Build: `m6/desk-chrome` (PR #39) · Platforms: macOS (WebKit ≈ WKWebView, macOS chrome) and Windows (Chromium ≈ WebView2, Windows chrome) in the design harness; the real apps in CI E2E.

## Method

1. **Tab walk of every top-level screen**, no pointer: each screen of `designScreenPaths` (Today; Jobs list + detail, search filters, saved searches, import, apply; Tracker board, table, calendar; application page and Log an application; CVs; Mail and Connect email; Insights; all eight Settings panes) plus the signed-out window (email, check-email) and onboarding (cv, preferences, finish). Playwright presses Tab until focus returns to the first stop (max 260) and records each stop's role, name, region (sidebar / content / dialog) and whether it shows a focus indicator; every visible interactive element that was never reached is listed. Run at 1280 × 800 and 600 × 800 (rail) in both engines: 92 walks.
2. **Overlay checks**: ⌘K / Ctrl+K, Tab / Shift+Tab inside the palette, ↑ ↓, type + ↵, Esc; ⌘/ / Ctrl+/, `?`, Tab inside the sheet, Esc; `G M`; palette → a Settings pane; ⌘, / Ctrl+,; ⌘K while signed out and during onboarding.
3. **Roving widgets** checked by hand where Tab reaches one item: list rows (J / K / ↑ ↓ / ↵), Settings navigation (↑ ↓ open the pane), board cards (arrows, `M`, Mod+Shift+→/←), calendar grid (arrows, ↵), Insights weeks, segmented controls (arrows).
4. **Real apps**: `e2e/specs/app.e2e.ts` on the macOS and Windows runners (palette, ⌘1–6, sheet, and new: Esc from the palette and the sheet gives focus back to the opener). Tab itself can't be driven there: the embedded WebDriver dispatches DOM key events, which have no default action, so the Tab walk is the harness probe.

The probe scripts were throwaway (not committed); the harness's `chrome` target (`pnpm --filter @bfhr/desktop capture:design chrome --axe`) reproduces the overlay states.

## Results

No focus traps: every walk cycled back to its first stop, and in dialogs focus stays inside until Esc or a close action (intended modal behaviour). No invisible focus stops.

## Kept

- Nine sidebar stops before the content on every Tab cycle: ⌘1–6 / `G` sequences jump to a section and focus its title; `nav` and `main` landmarks exist.
- Row-level actions shown on hover (`tabIndex=-1`) where a single-key shortcut does the same (Jobs S / D / O, Mail C / M, board `M`).
- macOS without "Keyboard navigation": Tab reaches fields and links only. That's the platform's own setting (System Settings › Keyboard › Keyboard navigation); the app doesn't override it.
