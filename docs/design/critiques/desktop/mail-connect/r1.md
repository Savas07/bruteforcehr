# Connect your email (desktop) — critique round 1

Skill: `design-critique`. Context: the connect dialog (`features/mail-connect`), opened from Settings › Mail accounts, the Mail empty state and Today's first-use card. Who: an active, stressed job seeker who wants replies from employers found without handing over a password lightly. Stage: refinement (first build). Research: connect-email.md "Decision — Desktop" and the "M5 desktop supplement" (Mobbin: Bonsai, AirOps, HubSpot, Dovetail tiles; Flodesk, Ditto, TheyDo, Qatalog "not available yet"). Reality the UI must handle: the Google and Microsoft OAuth clients aren't configured, so `mailConnectStart` answers `provider_not_configured`; IMAP with app passwords works.

Captures judged (browser harness on the design build, WebKit ≈ WKWebView, 1280×800, light and dark; `?connect=` states from `src/design/mail-connect.tsx`):

- `picker`, `imap` (iCloud), `oauth-unavailable` (Gmail), `imap-error` (Yahoo, `auth_failed`), `scanning` (`?scan=running`), each light and dark.

## Design Critique: Connect your email

### Overall Impression
The flow is calm and honest: eight providers in two columns read at a glance, the side column says what we read before anything is asked, and "Gmail sign-in is coming in an update" is neutral with a working way forward. The biggest problems are focus and headings: the dialog opens with focus (and its tooltip) on Close, and every step stacks two titles.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Every step opens with keyboard focus on the ✕ Close button, which also shows its "Close" tooltip over the corner. Keyboard users start at the wrong end and must Tab back; the tooltip reads as a stray label. | 🟡 Moderate | Focus the step's first empty field (address, else password), else the selected provider tile, else the first action; never Close. Move focus the same way when the step changes. |
| Each step shows two headings: the dialog title "Connect your email" and a step title ("Connect iCloud Mail", "Connect Gmail") right under it. The eye has to skip one; screen readers announce both. | 🟡 Moderate | One heading per step: the dialog title names the step ("Connect iCloud Mail", "Connect Gmail", "Connected to …"), "Connect your email" only on the picker. |
| Scanning: "1,240 of 3,100 emails checked" appears under the first stage and again in the line under the bar. | 🟢 Minor | Keep the count under the stage; the line under the bar says only "9 applications found so far". |
| Gmail "not available yet": the side column still lists the four promises, which matter less once nothing can connect through sign-in. | 🟢 Minor | Log: the promises also apply to the app-password path the state offers, so they stay. |
| Picker: Gmail is pre-selected with an empty address. | 🟢 Minor | Log: a radio group needs a selection; Gmail is the most common inbox, and domain detection changes it as soon as an address is typed. |

### Visual Hierarchy
- **What draws the eye first**: the selected tile and the primary button, then the "What we read" card. Correct for a choose-then-continue step.
- **Reading flow**: title → optional address → tiles → look back → Continue; the side column is read once and then ignored, which is fine.
- **Emphasis**: one filled button per step (Continue / Test and connect / Use an app password instead / Done). Errors use the field's own message in danger text, never a red dialog.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Dialog chrome | Matches Log an application (scrim, elevated surface, footer with Cancel + primary). | — |
| Field errors | Same pattern as Log an application (`aria-invalid`, message under the field). | — |
| Status icons | The scanning checklist uses the shared stage icons; colors follow tokens in both themes. | — |

### Accessibility
- **Color contrast**: body and caption text on the elevated surface pass in both themes (axe run in accessibility.md); the selected tile adds a ring, not color alone.
- **Touch targets**: tiles are 56 px tall; buttons 32 px.
- **Text readability**: helper text wraps; nothing truncates at 1280×800.

### What Works Well
- `provider_not_configured` reads as a plan, not a failure: clock icon, "coming in an update", and the app-password alternative right there.
- The help card puts the three provider steps next to the password field (AirOps help-first).
- The trust line under the password says exactly what happens to it.

### Priority Recommendations
1. **Initial focus on the step's first field** — keyboard-first desktop; also removes the tooltip artefact.
2. **One heading per step** — the step title becomes the dialog title.
3. **No repeated counter in scanning** — less noise while waiting.

## Resolution

- Initial focus: fixed. `onOpenAutoFocus` and a step-change effect focus the first empty field, else the first field, else the selected tile, else the first button in the step or footer (`MailConnectDialog.tsx`).
- Headings: fixed. The dialog title follows the step; the step-level titles are gone.
- Repeated counter: fixed (`ScanProgress.tsx`, full variant).
- Side promises on the unavailable state and the Gmail default: logged, unchanged (reasons above).
- Found while fixing: the waiting state had two "Cancel" buttons (inline and footer) doing different things; the inline one was removed (r2 checks it).
