Skill: `design-critique`. Context: Mail review, the desktop core screen where the user confirms or corrects how we sorted job emails. User goal: clear the review queue quickly and trust every change. Persona: an active job seeker, often stressed and short on time, switching between phone and desktop. Stage: refinement. Focus: the review loop (list → card → Confirm / Change… / Not job mail), trust cues (proposal + reason + evidence, Undo), states.

## Design Critique: Mail review

### Overall Impression
The three-pane layout reads immediately as "email, but only the job ones": folders nested under Mail in the sidebar, a calm list, and the review card on top of the email it judges. The proposal + reason + quoted evidence + Confirm / Change… / Not job mail block does the trust job well. The biggest opportunities are a factual contradiction in the card (application shown as "No application found" while the details say it is linked), the correction popover covering the very proposal it corrects, and hover actions colliding with the row's time.

### Visual Hierarchy
- **What draws the eye first**: the amber re-auth callout at the top of the list, then the selected row and the card headline. The callout is right to be noticed (we can't check that inbox), but it is four lines tall and takes ~130 px of a 800 px window on every folder.
- **Reading flow**: title → folder → callout → rows; right side: Review later / Open in Gmail toolbar → card headline → proposal → evidence → fields → actions → email → details → activity. Logical and top-down.
- **Emphasis**: Confirm is the only filled button; Change… is secondary; Not job mail is a text button with "We'll forget this email." under it — the right weighting. Pending rows use a semibold sender, done rows medium; good quiet distinction. In the details rail, "Application" appears twice (row + the summary block heading).

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Hint bar copy | "H Later" while the button and shortcuts sheet say "Review later". | Use "Review later" everywhere. |
| Details rail | "Application" row and "Application" summary heading repeat the same fact. | In the rail, drop the row when the summary block is shown. |
| Correction popover | The Application summary row truncates "Nordlicht Mobility · Frontend Engineer, Ri…"; research copy notes say the application name must not truncate. | Let the summary values wrap. |
| Re-auth callout | First draft put the address as the bold title and the whole sentence as body. | Title = "iCloud needs you to sign in again", body = consequence + fix (Customer.io pattern); done in the model before this capture. |

### Accessibility
- **Color contrast**: body and secondary text pass on base, sunken and selected surfaces in both themes (token pairs are contrast-tested in `@bfhr/ui-tokens`). Amber health dot always has text ("Needs reconnecting") as tooltip and accessible name. Full pass in accessibility.md.
- **Touch targets**: desktop pointer targets: rows ≥ 64 px tall, buttons 32 px, hover icon buttons 24 px (with C / M keyboard equivalents).
- **Text readability**: callout 15 px for rows, body for the email; line lengths in the reading pane are capped (max-w 760 px).

### What Works Well
- Proposal sentence + reason + quoted evidence on one card: the user sees what we'd do, why, and the line of the email that made us think so, before deciding.
- No "Confirm all" anywhere; every decision moves focus to the next email and shows a past-tense toast with Undo (⌘Z).
- Decisions read calmly: the Decision category, "Not selected" in grey, "Cadence Analytics has decided not to move forward".
- Updates list puts the automatic change first with Undo and "Mark as seen", then the email it came from.

### Priority Recommendations
1. **Fix the card/detail contradiction** — the user is asked to confirm a fact the screen states two ways.
2. **Move the correction popover beside the card** — correcting needs the evidence in view.
3. **Separate hover actions from the time** — the row's time is clipped into "7 ho".
