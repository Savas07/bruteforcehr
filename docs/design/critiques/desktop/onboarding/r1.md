# Onboarding wizard (desktop) — critique round 1

Skill: `design-critique`. Context: first-run wizard after sign-in (onboarding-signin.md "Decision — Desktop", D40–D42), for a stressed job seeker setting up in about two minutes. Stage: refinement (built, design build). Focus: step layout, the preferences form inside the wizard column, what Finish promises, skip paths.

Captures judged (browser harness `pnpm --filter @bfhr/desktop capture:design onboarding`, design build, WebKit and Chromium, 1280×800 and 1920×1080, light and dark): `cv`, `cv-imported`, `cv-existing`, `preferences`, `preferences-cv`, `preferences-filled`, `finish`, `finish-empty`, `setup-failed`.

## Design Critique: Onboarding wizard

### Overall Impression

Calm and quick: one question per step, a labeled stepper, nothing required. The biggest issue is the preferences step: inside the 560 px column the two-column form collapses to labels stacked over controls, which doubles the scroll length of the longest step.

### Usability

| Finding                                                                                                                                                                                                                   | Severity    | Recommendation                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------- |
| Preferences: at 560 px the label column (200 px) and the control column (min 288 px) don't fit next to each other after the 32 px side padding, so every section stacks. The research asks for 200 + 360 px side by side. | 🟡 Moderate | Widen the column for this step only (664 px), keep 560 px for CV and Finish.                        |
| Finish: "Skip for now" next to "Start searching" doesn't say what it skips. It finishes setup without creating the search, which a user can't infer.                                                                      | 🟡 Moderate | Label it "Finish without a search" (TR "Arama olmadan bitir", DE "Ohne Suche abschließen").         |
| Setup failure: in development (React StrictMode) the discarded first attempt to create the profile logs an unhandled rejection next to the handled one. Not user-visible, but noise that hides real errors.               | 🟢 Minor    | Attach a no-op catch where the attempt is created; the effect still reports the failure.            |
| With four roles picked, six role suggestions still show under the input.                                                                                                                                                  | 🟢 Minor    | Log: suggestions are the fastest way to add the fifth role; they disappear at five.                 |
| Tab from the focused step title goes through the content and footer before the header (Back, Sign out).                                                                                                                   | 🟢 Minor    | By design: focus starts on the title so a screen reader announces the step; Shift+Tab reaches Back. |

### Visual Hierarchy

- **What draws the eye first**: the step title, then the first option row or section. Correct.
- **Reading flow**: stepper → "Step n of 3" → title → body → content → footer actions, right-aligned with the primary last.
- **Emphasis**: one filled button per step (Continue / Start searching); Skip is plain. On the CV step without a CV, Skip is the only action and is a secondary button, so it doesn't look like a dead end.

### Consistency

| Element                | Issue                                                                                                                 | Recommendation |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- | -------------- |
| Chips, tokens, selects | Same `Chip`, `SegmentedControl`, native select and field styles as Settings and the job filters.                      | —              |
| Copy                   | Matches the research strings and the ux-copy rules (sentence case, no exclamation marks, "you" voice; TR siz, DE du). | —              |

### Accessibility

- axe-core (WCAG 2.1 A + AA): 0 violations in every state, both engines and themes (accessibility.md).
- Stepper: `nav` "Setup steps", current step `aria-current="step"`, finished steps read "{step}, done"; "Step n of 3" is visible text.

### What Works Well

- The Finish summary card says exactly what will be created (Looking for · In · Workplace · Alerts) before anything runs.
- "From your CV" tags show which sections were pre-filled and vanish once edited.
- Every step can be skipped; nothing blocks reaching Today.

### Priority Recommendations

1. **Widen the preferences step** — so the form reads in two columns as researched.
2. **Rename Finish's skip** — "Finish without a search".
3. **Silence the discarded setup attempt** — keep the console meaningful.

## Resolution

- Preferences column widened to 664 px on that step (`max-w-166`); CV and Finish stay 560 px. Verified in r2.
- Finish secondary action renamed "Finish without a search" (EN/TR/DE); E2E helper and tests updated.
- Setup attempts get a no-op catch at creation; the failure still shows the alert (unit test "says when the profile couldn't be created").
- Suggestions with four roles and the Tab order: logged, by design.
