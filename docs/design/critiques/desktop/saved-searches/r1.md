# Saved searches (desktop) — critique round 1

- **Screen:** Saved searches manage dialog over Jobs (`/jobs?searches=manage`) and the Save search button + alert popover in the Jobs filter bar (`/jobs?q=react&remote=remote`, Mod+S).
- **User goal:** keep a search running in the background and hear about good new matches, without having to come back and search again; adjust or stop alerts later.
- **Persona:** active job seeker, often stressed and short on time, switching between phone and desktop.
- **Stage:** refinement. **Focus:** the save flow (one keystroke, Undo), the alert choices, the manage list at 1280 × 800, and Run now feedback.

## Design Critique: Jobs — saved searches

### Overall Impression
Calm and legible: the list reads like Zillow's Updates (name, criteria, alert, last check, on/off), and the editor keeps filters read-only with one clear way back to Jobs. The biggest problems are focus landing on Close (with its tooltip) when the dialog opens, the Run now result appearing below the fold of the editor, and a "Daily digest" radio shown as selected for a search whose list row says "Daily" (no digest).

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| On open, focus lands on the Close button and its "Close" tooltip covers the corner; arrow keys do nothing until the user tabs into the list. Keyboard-first users start in the wrong place. | 🟡 Moderate | Focus the selected row on open (`onOpenAutoFocus`), so ↑ / ↓ work at once; Close stays reachable with Esc and Tab. |
| Run now's result ("Checked just now · No new jobs · 30 seen before · Adzuna, Jooble, USAJOBS and Reed skipped: no key") renders at the end of the scrolling editor. At 1280 × 800 it is below the fold, so pressing Run now looks like nothing happened. | 🟡 Moderate | Show progress, result and errors in the footer, directly above Run now (basis-full line), so the answer is next to the question. |
| "Berlin & Amsterdam" is a daily search without the digest. The row says "Daily · Score 75 and above", but the editor's radio selects "Daily digest — We check once a day and send one summary." Two answers to "what will I get?". | 🟡 Moderate | When a daily search has no digest, the daily option reads "Daily — We check once a day and tell you about each new match." (`cadenceOption`). Picking it again sets the digest. |
| With Off selected, the threshold hint says "Turn alerts on to choose which matches you hear about." while the control is still usable, which reads like it's locked. | 🟢 Minor | "Applies once alerts are on again." Keep the control editable (choice is remembered). |
| "Edit filters in Jobs" and "Show results" do the same thing (close the dialog and open the search in Jobs). | 🟢 Minor | Accept: the labels match two intents (change filters vs. look at matches) and the brief asks for both; both close the dialog and apply the search. |
| Run now on a search whose alerts are Off still runs. | 🟢 Minor | Accept: Run now is an explicit request; Off only stops scheduled checks and alerts. |
| Save search popover focuses and selects the Name field. Typing right away renames the search. | 🟢 Minor | Accept: renaming is the most likely first edit; Esc / Done keep the derived name. |

### Visual Hierarchy
- **What draws the eye first:** the selected row (accent subtle) and the filled teal "Run now". Correct: the dialog is about one search at a time and running it is the main action; Delete is the quiet destructive fill bottom-left (Zillow's placement).
- **Reading flow:** title + one-line explanation → list (name, criteria, alert, last check) → editor: Name / Search for → Filters (read-only, "Edit filters in Jobs") → Alerts (status line, cadence radios with what each does, threshold) → footer.
- **Emphasis:** criteria lines are secondary, alert and last-check lines tertiary; the row switch is the only colour in the list besides the selection. The cadence radios each explain themselves, so no "?" tooltip is needed.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Switches | Same Radix switch styling as Reminders (`application-detail`). | Keep. |
| Field styling | Name / Search for match the Log an application dialog fields (`h-8`, `line.control`). | Keep. |
| Threshold labels | "Strong matches / Good and above / All" use the band thresholds (80 / 65 / 0) from `MATCH_BAND_THRESHOLDS`; DE uses "Starke Treffer" to match the app's "Stark" band instead of the draft "Sehr passend". | Keep; the copy table draft is superseded for consistency with the band names. |
| Toast | "Search saved · Undo ⌘Z · Edit" uses the D19 secondary action. | Keep. |

### Accessibility
- **Color contrast:** text uses `fg.primary / secondary / tertiary` on `surface.elevated`, accent text on `accent.subtle` for the selected radio row, `fg.onAccent` on `accent.solid` for Run now; all in the tested pairings.
- **Touch targets:** list rows ≥ 72 px, switches 36 × 20 inside a 32 px row band, radios have the whole option row as the label target, footer buttons 32 px.
- **Text readability:** callout 14/20 for names and values, footnote 12/16 for criteria and hints; DE strings wrap within the popover (384 px) and the threshold segmented control fits ("Starke Treffer · Gut und besser · Alle").

### What Works Well
- Saving is one keystroke (Mod+S) with the default alert from decisions.md (Good and above, daily digest), a toast with Undo and Edit, and the popover open for the two decisions that matter.
- A search that's already saved shows "Saved · Edit alert" instead of creating a duplicate (case, spacing and list order don't matter).
- Every cadence says what it does ("We check every hour and tell you about each new match."); Off keeps the search in the sidebar and remembers its schedule.
- Run now explains partial results by source and reason ("Adzuna, Jooble, USAJOBS and Reed skipped: no key") instead of a bare count.
- Delete is undoable twice over: an inline "Deleted “…” · Undo" bar inside the modal (toasts sit behind the modal's inert layer) and the toast / Mod+Z after closing.

### Priority Recommendations
1. **Run now result next to Run now** — the feedback must be visible where the user acted.
2. **Initial focus on the selected row** — keyboard-first, arrow keys work immediately.
3. **Truthful daily option** — the radio and the list must describe the same alert.

## Resolution
- Run now progress, result and error moved into the footer above the buttons (`SavedSearchesDialog.tsx`, Editor footer). ✅
- `onOpenAutoFocus` focuses the selected row (`[aria-current="true"]`); Close remains in the Tab order. ✅
- `cadenceOption(cadence, search, intl)` in `model.ts`: a daily search without digest shows "Daily — We check once a day and tell you about each new match." (+ TR/DE). ✅
- Threshold-off hint copy changed to "Applies once alerts are on again." (+ TR/DE). ✅
- Minor items "Edit filters in Jobs" vs "Show results", Run now while Off, and the focused name field: accepted as designed (reasons above).
- Also from this round's accessibility pass: cadence radios are named by their label and described by their hint (`aria-labelledby` / `aria-describedby`) instead of reading label + hint as one name. Naming the list rows by the search name alone was tried and reverted (axe `label-content-name-mismatch`, WCAG 2.5.3); rows keep their full visible text as the name.
