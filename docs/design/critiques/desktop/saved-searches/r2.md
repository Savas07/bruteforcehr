## Design Critique: Jobs — saved searches

### Overall Impression
The r1 issues are gone: the dialog opens on the selected search with its focus ring, the daily search without a digest reads "Daily — We check once a day and tell you about each new match." in both the list and the editor, and Run now answers right above the button ("Checked just now · No new jobs · 30 seen before · Adzuna, Jooble, USAJOBS and Reed skipped: no key"). Offline, Run now is disabled in place with the tooltip and a footnote that says edits are kept on this device.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Loading and error states: the Jobs design route renders its own skeleton / "We couldn't load your jobs" pane and does not mount the dialog, so the dialog's own skeleton and error pane ("We couldn't load your saved searches" + Try again) are covered by unit tests but not by captures. | 🟢 Minor | Owner decision (Jobs screen owns state precedence; a whole-screen error correctly wins). Logged for DesktopJobs. |
| DE "Gespeichert · Bearbeiten" is shorter than EN "Saved · Edit alert". The saved button also carried an `aria-label` ("Saved as “react · Remote”. Edit alert") that didn't contain the visible label (WCAG 2.5.3 Label in Name). | 🟢 Minor | Fixed: the `aria-label` is gone, the visible label is the name (the search's name is the popover's first field). DE label kept short so the filter bar stays on one line at 1280. |
| Empty state keeps the dialog at its full 640 px height, so the "No saved searches yet" block sits in a large empty card at 1920. | 🟢 Minor | Accept: a fixed height keeps the dialog from jumping when the first search is saved from another device; the copy and "Back to Jobs" are centred in the first third. |
| "Edit filters in Jobs" and "Show results" both open the search in Jobs (carried over from r1). | 🟢 Minor | Accept (r1). |

No Critical or Moderate findings.

### Visual Hierarchy
- **What draws the eye first:** the selected row with its focus ring, then "Run now". Correct.
- **Reading flow:** list → Name / Search for → Filters → Alerts (status line, cadence, threshold) → footer (result line, Delete · Show results · Run now).
- **Emphasis:** the result line uses the accent check icon and medium "Checked just now", the rest regular; skipped sources are plain text, not warnings (they're expected without keys).

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Offline footnote | Same pattern and icon (`CloudOff`, footnote, full width above the buttons) as Log an application. | Keep. |
| Disabled Run now | `Button disabledReason` + `NeedsConnection` ("Needs a connection") like every server-only action. | Keep. |
| Dark mode | Selected radio row uses `surface.selected`; switch thumb `surface.base` on `accent.solid` reads clearly. | Keep. |

### Accessibility
- **axe:** 0 critical · 0 serious · 0 moderate · 0 minor in all 20 runs (details in `accessibility.md`).
- **Contrast:** all text in tested token pairings; disabled Run now is exempt and explained in text.
- **Targets:** ≥ 24 px everywhere; radios take the whole option row.

### What Works Well
- One keystroke to save, Undo + Edit in the toast, no duplicates.
- Each cadence explains itself; Off is reversible and keeps the schedule.
- Run now tells the user what happened per source, in plain words.
- Delete has an inline Undo inside the modal and Mod+Z / toast Undo after it closes.

### Priority Recommendations
1. **(Owner)** Decide whether the dialog should mount over the Jobs loading/error panes; it already handles both itself.

## UX copy review
Checked against `skill://ux-copy` and job-feed-search.md "Copy notes" (EN source; TR formal *siz*, DE *du*).

| Element | Copy | Note |
|---|---|---|
| CTA | "Save search" → "Saved · Edit alert" | Verb first; the saved state names what the click does. |
| Toast | "Search saved" · Undo · Edit | Copy table "Search saved · Edit"; Undo added (every automatic save is undoable). |
| Cadence | As they arrive · Daily digest · Weekly · Off, each with one sentence ("We check every hour and tell you about each new match.") | Copy table; DE "Sofort · Tägliche Übersicht · Wöchentlich · Aus", TR "Geldikçe · Günlük özet · Haftalık · Kapalı". |
| Threshold | "Notify me for" Strong matches / Good and above / All, hint "Matches scoring 65 or more" | DE "Starke Treffer" (matches the band "Stark") instead of the draft "Sehr passend". |
| Empty | "No saved searches yet" / "Save a search from Jobs to get new matches here." / "Back to Jobs" | What + how to start; brief's sentence verbatim. |
| Errors | "You've run a lot of searches today. Try again in a little while." · "No job sources are available right now, so nothing could be searched. Try again later." · "We couldn't run this search. Check your connection and try again." | What happened + what to do; no codes, no blame. |
| Run result | "12 new jobs · Adzuna skipped: no key" | Brief's example; reasons are short lower-case fragments so they read inside the sentence. |
| Offline | "Run now needs a connection. Changes you make here are saved on this device and sync when you're back online." | States rule 6: why disabled + reassurance. |

Localization: counts are ICU plurals (`{count, plural, …}`); lists use `Intl.ListFormat` ("Adzuna and Jooble", "Deutschland und Niederlande"); country names come from `Intl.DisplayNames`; money from `Intl.NumberFormat`. DE strings were checked in the popover (384 px) and the filter bar at 1280.
