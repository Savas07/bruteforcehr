## Design Critique: Keyboard shortcuts sheet (desktop) — round 1

Context: the sheet opened with ⌘/ / Ctrl+/ or `?`, the sidebar's "Keyboard shortcuts", the palette and Help → Keyboard Shortcuts… (`src/components/ShortcutsSheet.tsx`). It lists the app-wide shortcuts (`src/lib/shortcuts.ts`) and then every key the open screen registered. Research: `docs/design/research/desktop-chrome.md` → "Keyboard shortcuts sheet" (Circle, Notion Mail, Teams) and the M6 addendum (Obvious, Relume, Teams, Slite). Stage: final polish.

Captures judged: `pnpm --filter @bfhr/desktop capture:design chrome --axe` (+ `--locale tr|de`), states `shortcuts` (over Today) and `shortcuts-panel` (over the tracker table with an application's details panel open), WebKit (macOS chrome) + Chromium (Windows chrome), light + dark, 1280 × 800: `artifacts/screens/desktop/harness/{webkit,chromium}/{,tr/,de/}chrome-shortcuts*-{light,dark}-1280x800.png`; 600 px in the keyboard probe.

### Overall Impression

Clear rows (label left, keycaps right, platform modifiers) and the right content. But once screens started registering their own keys the sheet outgrew its single 480 px column, and the same keys appeared twice with near-identical names.

### Usability

| Finding                                                                                                                                                                                                                  | Severity    | Recommendation                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| "Next item" (J / ↓, lists) and "Next record" (J, details panel) — and their "Previous" twins — read like duplicates. They do different things: one moves through the list, the other changes the record the panel shows. | 🟡 Moderate | Lists say what moves: "Move down the list" / "Move up the list". The panel's J / K / Esc go under the panel's own heading.          |
| The panel's keys were split across two groups ("Lists" for Esc / J / K, "Application panel" for M / H / D / Mod+Enter), the panel rows carried "(panel)" suffixes, and Mod+Enter was listed twice (table and panel).     | 🟡 Moderate | One "Application panel" group; drop the suffixes (the heading says it); the table's Mod+Enter isn't listed while the panel owns it. |
| At 1280 × 800 the list scrolled (Today cut at "Open in detail pane", the tracker much more), with no scrollbar on macOS to say so.                                                                                       | 🟡 Moderate | Two columns from 800 px wide (Obvious, Relume), groups never split.                                                                 |
| Closing the sheet put focus on `<body>`.                                                                                                                                                                                 | 🟡 Moderate | Return focus to where it was opened from (shared with the palette).                                                                 |
| It opened with a focus ring on ✕, the loudest thing in the dialog.                                                                                                                                                       | 🟢 Minor    | Focus the dialog itself (it reads the title and description), or the list when it scrolls.                                          |
| Keys that can't fire right now stay listed (Undo with nothing to undo, "Back to the list" in a wide window).                                                                                                             | 🟢 Minor    | Keep: the sheet teaches what exists (`KeyBinding.enabled` is documented that way).                                                  |
| "CV editor" group heading stayed English in TR/DE; German had "Verschieben nach…" and "Verschieben nach …" side by side.                                                                                                 | 🟢 Minor    | Translate the group; one spelling ("nach …").                                                                                       |

### Visual Hierarchy

- **What draws the eye first**: the title, then the first group heading. Correct.
- **Reading flow**: two columns, top to bottom; app-wide groups (Navigation, General) on the left, the screen's own groups follow.
- **Emphasis**: keycaps are quiet sunken boxes; "or" between alternatives is tertiary text.

### Consistency

| Element       | Issue                                                                                                                                                                         | Recommendation |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| Wording       | List keys now match Teams-style "move" labels; the panel's labels match the full application page ("Move to…", "Later (snooze the suggestion)", "Not needed / Keep waiting"). | —              |
| Dialog chrome | Same overlay, radius, title scale and ✕ as the update dialogs.                                                                                                                | —              |

### Accessibility

See [accessibility.md](accessibility.md): axe found a scrollable region that couldn't be reached by keyboard, and group ids built from names with spaces broke `aria-labelledby`.

### What Works Well

- One source for keys: the handler, the sheet, the palette and the native menu can't drift.
- Platform modifiers (⌘ vs Ctrl) with spoken labels.
- Screen keys appear only while that screen is open.

### Priority Recommendations

1. **Disambiguate J / K** by heading and verb.
2. **Fit a laptop window** with two columns.
3. **Return focus** on close.
