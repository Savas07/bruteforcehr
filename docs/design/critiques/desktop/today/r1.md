## Design Critique: Today (desktop) — round 1

Context: Today, the desktop home. User goal: see what needs attention and clear it fast. Persona: active job seeker, often stressed and short on time, switching between phone and desktop. Stage: refinement. Focus: calm hierarchy, trust (source + reason + Undo), keyboard-first flow.

### Overall Impression
The screen reads as a calm, ordered inbox: title + date, then Next up as a quiet hero card, then short sections. The biggest opportunity is trust inside "To review": emails that only *propose* a status look exactly like changes that were already applied.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| To review rows for emails awaiting confirmation show the proposed status as a filled status pill ("Screening", "Acknowledged"), identical to the pills on automatic changes that already happened. A stressed user will read "Screening" as done. | 🟡 Moderate | Review rows show when the email arrived instead; the proposed move stays in the detail pane's proposal sentence. |
| To review mixes "needs your decision" rows and FYI automatic changes in one undivided list; the header says "· 3" but six rows follow, so the count looks wrong. | 🟡 Moderate | Split the section: decisions first, then a quiet sub-heading over the automatic changes that says they can be undone. |
| Deadline row title "Reply to the offer by" is a sentence fragment; in the row the date sits top-right, so the title ends in mid-air. | 🟡 Moderate | Retitle to "Offer reply due" (matches "Assessment due"); the chip carries the date. |
| Deadline detail reads "Due In 5 days" (mid-sentence capital from the relative label). | 🟡 Moderate | Show the relative label alone, then the absolute date in secondary text. |
| After snoozing from the menu (H → 1–4), focus lands on the Snooze button of the next item (WebKit) or on the page body (inline mode, Chromium): keyboard users lose their place. | 🟡 Moderate | Move focus to the next row after the menu has closed (next frame), from any origin; focus the title when the list empties. |
| First-run (empty) shows the Open / Later filter although nothing can be snoozed yet. It's a control with no purpose and pulls the eye away from the one card. | 🟡 Moderate | Show the filter only once there are items or snoozed items. |
| Inline mode: the first Esc inside the expanded detail only closes the button tooltip (Radix consumes it), the second collapses. | 🟢 Minor | Shared `Hint` behaviour; logged, not changed here. |
| Keyboard letters (C, E, H, D, O, S) are visible only in tooltips and the shortcuts sheet. | 🟢 Minor | Acceptable for refinement (IA rule 4: tooltips + menus + sheet). Context menus show them too. |

### Visual Hierarchy
- **What draws the eye first**: the Next up card (tinted when selected, bordered otherwise) — correct, it's the most time-bound item.
- **Reading flow**: title → date → Next up → To review → Follow-ups → Deadlines → New matches; the detail pane on the right mirrors the selected row. The agenda rail at 1920 is quiet and secondary, as intended.
- **Emphasis**: status pills in To review over-emphasise proposals (see Usability). Section titles are callout-semibold, quieter than the large title; good.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Status pills | Same pill used for "proposed" and "applied" states | Pills only on applied changes |
| Auto-change glyph | 10 px bolt on the monogram is faint, especially in dark | Kept as a secondary cue now that the sub-heading carries the meaning |
| Automatic-change row title | "Moved to Offer — from an email by Lumenpay" repeats the company already shown above it | Keep: the source must be named in the sentence (trust principle, D11) and the same string is used outside the row |

### Accessibility
- **Color contrast**: text uses fg-primary/secondary tokens; selected row tint keeps fg-primary text. Formal check in the accessibility review (`--axe`).
- **Touch targets**: rows ≥ 56 px tall; buttons 32 px (desktop pointer).
- **Text readability**: callout 15/20 body, footnote for meta; long German/Turkish strings wrap (no truncation).

### What Works Well
- No greeting, no counters beyond the one D01 count, no red: the page feels calm even with 13 items.
- Every action is optimistic with a toast and Undo (Mod+Z); automatic changes keep a durable Undo in their detail.
- J/K moves selection and the detail follows; Enter jumps into the pane and Esc returns to the row.

### Priority Recommendations
1. **Stop showing proposed statuses as pills** — the trust principle requires that only applied changes look applied.
2. **Split To review into decisions and automatic changes** — the count then matches what it counts, and FYIs read as FYIs.
3. **Keep keyboard focus on the list after every action** — the flow is keyboard-first; losing focus breaks it.
