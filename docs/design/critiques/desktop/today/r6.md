Context: final round after the round 5 fixes. Scope: the full design matrix on the M3 builder and actions, plus the real-data states from round 5.

Captures judged:
- `pnpm --filter @bfhr/desktop capture:design today --axe` (WebKit + Chromium; populated, empty, loading, error, offline × light, dark; 1280×800 and 1920×1080): 40 screenshots in `artifacts/screens/desktop/harness/{webkit,chromium}/today-*-{1280x800,1920x1080}.png`, 20 axe reports in `artifacts/a11y/desktop/today-<state>-<theme>-<engine>.json`.
- Real-data states (round 5 probe, after the fixes), both engines, light + dark: `artifacts/screens/desktop/harness/{webkit,chromium}/today-live-{answered,later,reminder}-{light,dark}-1280x800.png`, axe in `artifacts/a11y/desktop/today-live-<state>-<theme>-<engine>.json`.

### Overall Impression
Populated, loading, error and offline look as in round 4 except Deadlines, which now lists the user's reminders (5 rows, no duplicates). Empty is the production M3 first run: one card, one working action. Later view and Done today hold up in both themes.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Deadlines mixes the user's reminders with dates from emails under one title. Each row still says what it is (reminder text vs "Assessment due"), and the detail labels reminders "Your reminder". | 🟢 Minor | Keep one Deadlines section (today-home's fixed order); revisit if users ask for a separate "Reminders" group. Logged. |
| Offline (populated): the banner, "Updated 10:05" next to the date and "Offline · 2 changes waiting to sync" in the sidebar; Today's actions stay available because writes are kept on the device and sync later (only Join needs a connection). | — | Pass. |

### Visual Hierarchy
- **What draws the eye first**: Next up (populated, offline), the first-use title (empty), the error card (error). Correct.
- **Reading flow / emphasis**: unchanged from round 4; reminder rows use the shared deadline chip ("Tomorrow, 10:30", "In 2 days").

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Dark theme | Later notice (info tone), Done today and the first-use button use the dark tokens; no hard-coded colours added. | — |

### Accessibility
axe: 0 critical · 0 serious · 0 moderate · 0 minor in all 20 matrix runs and all 12 real-data runs. WebKit "needs review": the shell's ⌘ keycap ("Jump to…", every state) and, in the empty state, the ⌘ keycap inside "Add application ⌘N" ("Element content contains only non-text characters"); both are decorative next to the spoken label.

### What Works Well
- One view model in the app and the design build; the design captures still show mail and matches from the fixtures, production shows only what M3 stores.
- Every action M3 stores persists with Undo; nothing on Today is session-only in production.
