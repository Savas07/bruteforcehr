## Design Critique: Tracker board (desktop), round 3

### Overall Impression

The board and drag flow hold up in every engine, theme and language. Opening the panel on a record with a follow-up suggestion crashed the screen, which is the one thing a stressed user must never see.

### Usability

| Finding                                                                                                                                                                                                          | Severity    | Recommendation                                                                                                |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------- |
| Opening Quill Docs (a record with an "Up next" follow-up suggestion) replaces the whole app with a "Something went wrong" error: the panel formats an undefined message (`messages.upNext` was lost in an edit). | 🔴 Critical | Restore the message; add a render test that opens the panel for every populated application in EN, TR and DE. |
| A deep link (or J/K in the panel) to a card in a column that's scrolled out of view leaves the board showing other columns, so the highlighted card and its neighbours aren't visible next to the panel.         | 🟡 Moderate | Scroll the selected card into view (nearest) whenever the selection changes.                                  |
| At 1280 the 480 px panel left ~1.7 columns (r1 #8).                                                                                                                                                              | 🟢 Minor    | Shared `DetailSidePanel` now opens at 400 px below 1440 (main); verify after merge.                           |
| Offline: cards with local changes show the sync glyph after the company, the panel's status pill shows it too, "Updated 10:05" sits top-right, and the sidebar says "2 changes waiting to sync".                 | ✅          | —                                                                                                             |
| The follow-up suggestion reads "Applied 9 days ago · no reply yet" with "Draft follow-up" and "Not needed"; no guilt, no red.                                                                                    | ✅          | —                                                                                                             |
| DE drag: "Abschließen als" zones and long status names ("Eingang bestätigt", "Vorstellungsgespräch") fit 272 px; header names wrap rather than truncate.                                                         | ✅          | —                                                                                                             |

### Visual Hierarchy

- **What draws the eye first:** in the panel, the role title, then the status pill and "Up next". Correct: the suggestion is the one thing to act on.
- **Reading flow:** header → Up next → Timeline → Application summary. Matches tracker.md "Record detail".
- **Emphasis:** the suggestion card is outlined, not filled; its primary is a secondary button (system.md: Tracker keeps one primary elsewhere).

### Consistency

| Element    | Issue                                                                                   | Recommendation |
| ---------- | --------------------------------------------------------------------------------------- | -------------- |
| Nudge card | Shared `NudgeCard`, same as Today.                                                      | —              |
| Summary    | Shared `ApplicationSummaryBlock` ("Not recorded", "None attached"), same as Job detail. | —              |

### Accessibility

- **Color contrast:** unchanged; axe in the accessibility review.
- **Touch targets:** unchanged.
- **Text readability:** DE/TR fit without truncating status names.

### What Works Well

- The board works as a home for the follow-up and no-response suggestions without a separate list.
- Offline state is honest at three levels (card, panel, shell) without alarming colour.

### Priority Recommendations

1. **Fix the crash and guard it with a render test over every record.**
2. **Keep the selected card visible next to the panel.**
