## Design Critique: Tracker board (desktop), round 5

### Overall Impression

On the real apps the board renders as in the harness, but two edges send the wrong signal: at 1920 the half-visible Interviewing column ends in a hard vertical cut right beside the Closed rail, so it reads as hidden behind the rail rather than "scroll for more". On Windows the empty board shows a scrollbar for columns that hold nothing.

### Usability

| Finding                                                                                                                                                                                                                                                                                               | Severity    | Recommendation                                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| At 1920 × 1080 (macOS) the Interviewing column is cut at about two-thirds width, flush against the Closed rail. Nothing says the board continues (Offer is off-screen), so the rail looks like it covers the column. The trackpad hides the scrollbar on macOS, which removes the only remaining cue. | 🟡 Moderate | Fade the board into the page on the side where more columns continue (and on the leading side once scrolled), so the cut reads as "more to the right". Keep the rail as a separate block beside the scroller (already true).                             |
| Windows, empty board: a horizontal scrollbar under seven empty 272 px columns at 1280, for content that is only empty wells.                                                                                                                                                                          | 🟡 Moderate | On first use, let the columns share the board's width (up to 272 px each) instead of fixed widths. Keep the explainer as a centered card over the wells so it doesn't force the first column wide. Same for the load-error board (nothing to scroll to). |
| Empty board, collapse buttons on every header: there is nothing to fold away on first use, and the buttons cost width.                                                                                                                                                                                | 🟢 Minor    | Hide the collapse buttons on the first-use board.                                                                                                                                                                                                        |
| Loading board keeps fixed columns, so it still scrolls on Windows.                                                                                                                                                                                                                                    | 🟢 Minor    | Keep: the skeletons stand in for the real board, which scrolls the same way once it loads (no layout jump). Log.                                                                                                                                         |

### Visual Hierarchy

- **What draws the eye first:** the title and the stage headers; on the empty board the centered explainer. Correct.
- **Reading flow:** left to right across stages; the trailing fade now ends the row softly before the Closed rail.
- **Emphasis:** the fade only touches the partly visible column; full columns are untouched.

### Consistency

| Element         | Issue                                                                                                                 | Recommendation                                                     |
| --------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Fade            | Uses `surface.base` (the content pane), so it matches light and dark without new tokens.                              | —                                                                  |
| Empty explainer | Centered card at every width (states.md's below-1200 variant), so the first-use board looks the same on every window. | Note the change from "explainer in the first column at ≥ 1200 px". |

### Accessibility

- The fades are decorative (`aria-hidden`, `pointer-events: none`); clicks and focus pass through.
- The error board no longer has a scroll area, so its scroller drops its tab stop; the loading board keeps its focusable scroller.
- axe (WCAG 2.1 A/AA), both engines, both themes, 1280 and 1920: 0 critical · 0 serious on all 20 pages.

### What Works Well

- The rail stays a separate, always-visible drop target; nothing overlaps.
- Empty columns now fit the window in English and Turkish at 1280, with headers on one line.

### Priority Recommendations

1. **Make the board's cut edge read as "more to the right".**
2. **Let empty boards fit the window.**

## Resolution

| #   | Finding                                        | Severity | Resolution                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --- | ---------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Interviewing cut off at the Closed rail (1920) | Moderate | **Fixed** in `dfdad0a`. Measurements show there's no overlap (last column ends 8 px before the rail at scroll end), so no width is reserved. Instead the board fades into the page (64 px, `surface.base`) on the trailing side while columns continue, and on the leading side once scrolled. The fades are re-measured on scroll, resize and every render. Verified at 1280 and 1920 in WebKit and Chromium, light and dark.                                                                                   |
| 2   | Scrollbar on the empty board (Windows)         | Moderate | **Fixed** in `dfdad0a`. First-use and load-error columns are `fluid`: `flex: 1 1 0`, at most 272 px, never narrower than their longest header word. Measured: no overflow at 1280 and 1920 in EN and TR (`scrollWidth = clientWidth` = 959 / 1599), and at 1920 in DE. In DE at 1280 the board still overflows by 100 px ("Hinzufügen" footers and "Vorstellungsgespräch" don't fit 7 × 130 px). That's real content, not empty space, so it scrolls. The first-use explainer is a centered card at every width. |
| 3   | Collapse buttons on the empty board            | Minor    | **Fixed** in `dfdad0a`: not shown on first use.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 4   | Loading board scrolls                          | Minor    | **Logged**, by design (shape-matched skeletons; no jump when data arrives).                                                                                                                                                                                                                                                                                                                                                                                                                                      |

The shared scrollbar styling on Windows comes from DesktopFoundation; this round only removes overflow where there was no content.

Round result: **0 Critical, 0 unresolved Moderate.**
