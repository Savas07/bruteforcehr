# Tracker reminders · desktop · critique round 1

- **Surfaces:** the reminder parts of the application detail (full page; the side panel shares the components): the suggestion card in **Up next** (follow-up due, no-response due), its snoozed state and the none state; the user's own reminder in **Reminders** (line + inline editor); the device switch "Interview prep reminders on this computer" in its four permission states (granted, default, denied, unsupported). Research: `research.md` (11 candidates, 6 kept).
- **User goal:** decide in one step what to do with a nudge (do it, say it's not needed, or push it to a better time), keep one personal reminder per application, and know whether this computer will warn before an interview.
- **Persona:** active job seeker, stressed, keyboard-heavy on desktop; calm tone required (no red time, no guilt, Undo everywhere).
- **Stage:** refinement. **Method:** `skill://design-critique` + `skill://ux-copy` + `skill://accessibility-review`. States were driven by a throwaway Playwright script against the design build (deleted afterwards): keys `H`, `1`–`4`, `D`, buttons, the editor's fields, and, for the permission states, a stub of the Tauri shell (`isTauri`, the notification plugin's permission check and request) so the real `useInterviewReminderSetting` paths run. axe-core (WCAG 2.1 A/AA) on every state; a focus probe recorded where focus lands after each action.

## Design Critique: Tracker reminders (desktop)

### Overall Impression
The vocabulary is right and calm: "Applied 9 days ago · no reply yet" with **I followed up / Not needed**, "No reply in 26 days. Mark as no response?" with **Mark as no response / Keep waiting**, a quiet clock for Later, a dashed "Follow-up suggestion snoozed until Tomorrow, 09:00 · Show now" line instead of a silent disappearance, "Was due 20 Oct, 17:00" in plain grey, and a switch whose rule is spelled out under it. The biggest problems were keyboard ones: every answer, snooze or restore dropped focus to the page, and "Pick a date…" in WebKit — the engine of the macOS app — opened its dialog with focus left behind the scrim.

### Usability

| Finding | Severity | Recommendation |
|---------|----------|----------------|
| **Pick a date… in WebKit:** the date dialog opens but focus stays on the Snooze button behind the scrim (`webkit key4: dialogs=1 focus=BUTTON button "Snooze" inDialog=false`), and Esc doesn't close it (`after Esc dialogs=1`). In Chromium the dialog works, but after Esc focus falls to `<body>`. Same with a modal or non-modal menu, so it isn't the r2 menu change. Cause: the dialog mounts while the menu is closing, and the menu's focus restore lands after the dialog's autofocus. | 🔴 Critical | Open the date dialog only after the menu has closed and returned focus to its trigger (shared `SnoozeMenu`: "Pick a date…" fires from `onCloseAutoFocus`); the dialog remembers that trigger and returns to it on close (shared `SnoozeDateDialog`). Fixes Today, mail review and the detail page in one place. |
| Answering the card (I followed up, Not needed, Mark as no response, Keep waiting, or `D`), snoozing it, or **Show now** drops focus to `<body>`: 14 of 14 probes in both engines. Keyboard users restart from the top; in the side panel the panel's own `M`/`H`/`D` stop working because they only act while focus is inside the panel. | 🟡 Moderate | Move focus to what replaced the control: after a snooze → **Show now**; after Show now → the card's first answer; after an answer (Up next empty) → the page title (`ScreenTitle`, `tabIndex=-1`), or the panel itself in the side panel. Only when focus was lost, never stealing it from elsewhere. |
| The inline reminder editor (Save / Cancel / Esc) and **Remove** remove the focused control; focus fell to `<body>`. | 🟡 Moderate | Return focus to the line's first button (Change, or Set a reminder after Remove), once the line shows the expected state (Save and Remove land through the store). |
| **Denied:** after the OS refuses, the alert says "Turn them on in System Settings › Notifications › BruteForceHR, then switch this on again." — but the switch is disabled (60 % opacity) until the page reloads, so the instruction can't be followed. | 🟡 Moderate | Keep the switch enabled when denied: switching on asks again (`enable()` → `requestNotificationPermission`); only a plain browser (unsupported) or the first unknown moment disable it. Describe the switch by the alert too. |
| Editor, empty Time field: WebKit paints its grey placeholder with the current time ("12:30 PM", `rem-editor-new`) right above "Without a time, it's 09:00." The field seems to say 12:30. | 🟡 Moderate | When a day is picked and Time is empty, fill Time with 09:00 (the default the hint names) so the field shows what will happen; the user can still change it. |
| With the snooze menu open, axe reports `aria-hidden-focus` (serious ×9): Radix's modal menu hides the app from assistive tech while it still holds tabbable controls. | 🟡 Moderate | Non-modal menu (`modal={false}`) on the shared `SnoozeMenu` (APG menu button: Tab stays blocked inside, Esc / outside click close, focus returns to the trigger). |
| Kiez Health: card "No reply in 26 days", header "27 days in Screening". | 🟢 Minor | Log: different facts (since their last message vs since the move; D15). |
| Later is an icon-only clock at the card's far right; its name ("Snooze") and `H` are in the tooltip only. | 🟢 Minor | Log: shared `NudgeCard`, same as Today; the shortcuts sheet lists "Later (snooze the suggestion)". |
| "Pick a date…" body: "The suggestion for Quill Docs comes back on this date." The snoozed line then says "until Tomorrow, 09:00": the time appears only afterwards. | 🟢 Minor | Log (ux-copy): "comes back at 09:00 on this day" if testers ask when. |
| After **Keep waiting** / **Not needed** the card leaves no trace on the page; only the toast ("Still waiting · Kiez Health · Undo") says what happened. | 🟢 Minor | Log: answered suggestions are done (D19); Undo is on the toast and ⌘Z / Ctrl+Z. |
| Changing an existing reminder toasts "Reminder set · Brightwave", the same as a new one. | 🟢 Minor | Log: true either way; "Reminder changed" would be more exact. |
| A past date is accepted without a word and shows as "Was due 20 Oct, 17:00". | 🟢 Minor | Log: lets the user record a missed step; grey, no alarm (calm rule). |
| The prep switch is a per-computer setting shown on each application. | 🟢 Minor | Log: the line says "Applies to all your applications"; the same switch belongs in Settings when that screen lands. |
| After a restart, a permission the OS denied reads as "default" until the user switches on (the plugin's check can only say granted or not). | 🟢 Minor | Log: switching on asks again and shows the denied alert at once. |

### Visual Hierarchy
- **What draws the eye first:** the card's question ("Applied 9 days ago · no reply yet"), then the outlined primary answer. With a suggestion due the header has no teal primary, so the card is the one ask on the page. Correct.
- **Reading flow:** question → answer → decline verb (plain) → clock (quiet, far right). Snoozed: one dashed line, clock icon, Show now at the end. Reminders: "Your reminder" → line (what · due) → Change / Remove → the device switch with its rule.
- **Emphasis:** time never turns red ("Was due" is the only overdue cue); the denied alert is the one warning-tinted surface, and only in that state.

### Consistency

| Element | Issue | Recommendation |
|---------|-------|----------------|
| Card | Same shared `NudgeCard` as Today (`hideApplication` on its own page), same verbs (D15/D19), same toasts with Undo + ⌘Z / Ctrl+Z. | — |
| Snooze | Same four presets with 1–4 keycaps as Today and mail review; same date dialog. | — |
| Switch | Radix `Switch`, labelled by its title, described by the rule (and by the denied / unsupported line). | — |

### Accessibility
- **Contrast:** the reminder line's "Due Wednesday, 17:00" (`fg-secondary` on `surface-sunken`) 6.93:1 / 8.87:1; Change / Remove 6.18:1 / 8.64:1; denied alert text 4.61:1 / 5.16:1; switch track off (`line-control`) 3.76:1 / 3.96:1 against the page. Details in `accessibility.md`.
- **Targets:** 20 × 36 px switch, 24 px clock button, 32 px buttons; desktop minimum met.
- **Keyboard:** `H`, `1`–`4`, `D`, Esc; see `accessibility.md`.

### What Works Well
- "Show now" keeps a snoozed suggestion visible and recoverable in one line.
- The denied state names the exact path per OS ("System Settings › Notifications › BruteForceHR" on macOS, "Settings › System › Notifications › BruteForceHR" on Windows).
- The prep rule is one sentence with real times ("the evening before at 18:00 and an hour before each interview, never between 22:00 and 08:00").
- Every change (snooze, answer, set, change, remove) has Undo on the toast.

### Priority Recommendations
1. **Make Pick a date… work from the keyboard in WebKit** — it's the macOS engine.
2. **Keep focus where the user was** after answers, snoozes, the editor and Remove.
3. **Let the denied switch be switched on again**, and show 09:00 when a day is picked.

## Resolution

| Finding | Status |
|---------|--------|
| Pick a date… focus (WebKit) / focus loss (Chromium) | **Fixed** — `shared/ui/SnoozeMenu.tsx`: "Pick a date…" (click or `4`) is deferred to the menu's `onCloseAutoFocus`; `shared/ui/SnoozeDateDialog.tsx`: remembers the element focused at open and returns there on close. Probe after the fix: `webkit key4: dialogs=1 focus=INPUT date inDialog=true` → `after Esc dialogs=0 focus=BUTTON "Snooze"`; same for click and in Chromium. |
| Focus lost after answers / snooze / Show now / `D` | **Fixed** — `Screen.tsx` (and `ApplicationPanel.tsx`): when Up next changes and focus was lost, focus goes to Show now, the card's first answer, or the title (panel: the panel). Probe after the fix, both engines: `I followed up` / `Not needed` / `Keep waiting` / `Mark as no response` / `D` → `H1 "Frontend Engineer"`; `snooze Tomorrow` → `BUTTON "Show now"`; `Show now` → `BUTTON "I followed up"`. |
| Editor / Remove focus loss | **Fixed** — `Reminders.tsx`: focus returns to the line's first button once the line shows the expected state. Probe: `focus after save: Change`, `focus after Remove: Set a reminder`, `focus after editor Esc: Set a reminder` (URL unchanged: Esc closed the editor, not the page). |
| Denied switch disabled | **Fixed** — `Reminders.tsx`: disabled only for `unsupported` / `unknown`; described by the alert. `rem-toggle-denied-{light,dark}` shows the switch at full strength; accessibility tree: `switch "Interview prep reminders on this computer"` (not disabled) followed by `status: Notifications are turned off for BruteForceHR …`. |
| Grey current time in an empty Time field | **Fixed** — `Reminders.tsx`: picking a day fills an empty Time with 09:00 (`time value: 09:00` in both engines); saved as "Due Tuesday, 09:00" (`rem-editor-date-picked`). |
| axe `aria-hidden-focus` with the menu open | **Fixed** — `modal={false}` on `SnoozeMenu` (and `InteractiveStatusPill`, the More menu): `a11y rem-snooze-menu-light-webkit: 0 critical · 0 serious · 0 moderate · 0 minor · 3 needs review (aria-valid-attr-value×1, color-contrast×2)`. |
| 26 vs 27 days · icon-only Later · date-dialog copy · no trace after answers · "Reminder set" on change · past dates · per-computer switch on each page · denied after restart | **Logged** (Minor). |

Final axe over every state above after the fixes, light + dark × WebKit + Chromium: 0 critical · 0 serious in all 80 reports (quoted in `accessibility.md`).
