## Design Critique: Tracker table

### Overall Impression
A calm, dense list that answers "where does everything stand" in one scan: status pills carry the meaning with dot + label, dates read relatively where recency matters ("Last activity: yesterday") and absolutely where a date is the fact ("Applied on 14 Oct"). The first pass had one real accessibility defect (the row's open button announced a different name than it showed) and a few minor layout points.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| The company cell button had `aria-label="Open Kervan Teknoloji, Product Engineer"` while it shows "KT Kervan Teknoloji": axe `label-content-name-mismatch` (WCAG 2.5.3) on every row; voice-control users saying "click Kervan Teknoloji" may miss it. | 🟡 Moderate | Name from content: visible company name + a screen-reader-only ", {role}" suffix; monogram stays decorative. |
| At 1280 px the toolbar wraps: search, Columns, Import CSV and Export… drop to a second line under the title. Everything stays reachable and aligned right; the table still starts above the fold. | 🟢 Minor | Accept for v1; an overflow (•••) for Columns / Import CSV is the next step if more toolbar items arrive. |
| Nine default columns exceed 1280 px, so Location and part of Next action need horizontal scroll; the sticky company column keeps rows identifiable. | 🟢 Minor | Accept (research: "Optional columns come from Customize columns"); the chooser lets users hide Source / CV used. |
| Bulk "Set status" lists every status with how many of the selection can move there ("Accepted · 1"); refused targets are greyed with the D16 reason. Bulk Undo is one toast for the whole batch (Mod+Z works). | — | Keep. |
| Research's bulk *Add reminder* and *Delete* aren't in the bar. | 🟢 Minor | Later: reminders arrive per application in the detail; bulk delete needs its own Undo design (events are append-only). |

### Visual Hierarchy
- **What draws the eye first**: the status pills (the only tinted elements per row), then company names in medium weight.
- **Reading flow**: title → view switch → count ("18 of 25 applications") → filters → rows. Sort direction shows on the active header only (other headers show a faint ↕).
- **Emphasis**: no red anywhere; closed outcomes use the neutral Closed tone ("Not selected").

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Status pill / Move to… | Shared `InteractiveStatusPill` + `StatusMenu` (same targets and reasons as the board). | — |
| Filter chip | Sentence chip "Status is Screening, Interviewing ×" per research (Browserbase). | — |
| Export | Shared `ExportButton` (Mod+E), CSV of the current view; bulk bar exports the selection. | — |
| Empty / no results | Shared `EmptyState` (`firstUse`: Add application ⌘N + Import CSV; `noResults`: Clear filters). | — |

### Accessibility
- **axe (WCAG 2.1 A/AA)**: after the fix, 0 critical · 0 serious · 0 moderate in every state × theme × engine.
- **Keyboard**: one tab stop in the grid (roving company buttons); ↑/↓, J/K, PageUp/PageDown, Home/End move; Enter opens the detail panel; Mod+Enter full page; X selects; Mod+A selects all; M opens Move to… (bulk menu when rows are selected); Esc clears the selection; `/` focuses search; 1/2/3 switch views. All registered in the shortcuts sheet.
- **Semantics**: real `<table>` with `aria-rowcount` / `aria-rowindex` (virtualized), `aria-sort` on headers, labelled checkboxes ("Select Kervan Teknoloji, Product Engineer"), live count.
- **Contrast**: pills and secondary text use system tokens checked in system.md (≥ 4.5:1 in both themes).

### What Works Well
- One Undo for a bulk move, and the toast says how many moved.
- Insights drill-downs land on exactly the applications behind the number, with a removable "From Insights: …" chip.
- Preferences (scope, status filter, columns, sort) persist per device; search and selection don't.

### Priority Recommendations
1. **Name the open button from its visible text.**
