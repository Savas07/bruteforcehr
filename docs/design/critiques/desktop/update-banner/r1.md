## Design Critique: Update banner, "Check for Updates…" and "Update required" (desktop) — round 1

Context: M1 in-app updates for the Tauri desktop app (BRIEF §7, ADR 0004 §3). Research: `docs/design/research/desktop-chrome.md` → "Update-available banner" (n8n sidebar footer, Campsite card, Gumloop release-notes dialog). Persona runs 0.1.0, is offered 0.1.1; the gate requires 0.2.0. Stage: first implementation, English.

Captures judged: `pnpm --filter @bfhr/desktop capture:design update --axe` — all 17 update states (`updateDesignStates` in `src/design/matrix.ts`: ready, ready-later, ready-rail, notes, save-first, restarting, install-failed, checking, up-to-date, downloading, check-ready, check-failed, download-failed, required-downloading / -ready / -failed / -unavailable) × WebKit (macOS chrome) + Chromium (Windows chrome) × light + dark = 68 PNGs in `artifacts/screens/desktop/harness/{webkit,chromium}/update-*.png` (1280×800; the rail state at 600×800), 68 axe reports.

### Overall Impression
The card sits where the research put it, quiet and persistent, and nothing interrupts Today. The restart is never alarming (teal, not red). The biggest problems are in the edges: the narrow rail loses its "something's waiting" signal, and the collapsed line cuts off its own meaning.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Rail (window < 640 px): the dot that marks a ready update is drawn inside the arrow icon (`right-4` on a 36 px button) and disappears in both themes. The rail then shows an unexplained teal icon. | 🟡 Moderate | Anchor the dot to the icon itself (`-top-0.5 -right-1`, `size-2`, ring in the sidebar colour). |
| Collapsed card ("Later"): the line reads "Update ready: versio…" at 232 px; the version, the only new information, is truncated. | 🟡 Moderate | Show "Update ready" + the version as a quiet trailing label (then check TR/DE length). |
| Behind the "Update required" screen, ⌘K/Ctrl+K, ⌘1–5 and the keymap still fire: the palette opens above the gate and navigation happens underneath. | 🟡 Moderate | The shell ignores its commands while the gate blocks (only "Check for Updates…" still works); the keymap listener detaches. |
| Downloading dialog repeats itself: headline "Version 0.1.1 is downloading", then "Downloading version 0.1.1… 45%" right under it. | 🟢 Minor | The progress line carries numbers only: "25.6 of 56.9 MB · 45%"; the gate adds its own sentence above the bar. |
| Dialogs open with focus on the close ✕ (Radix default). | 🟢 Minor | Safe default for a non-destructive dialog; keep. |

### Visual Hierarchy
- **What draws the eye first**: the teal "Restart to update" in the sidebar footer, then the card title. Correct: it's the one action, and it's outside the content.
- **Reading flow**: title → "Later" (top right, plain) → sentence → primary → "What's new". Natural.
- **Emphasis**: one primary per surface everywhere (card, dialog, gate). The gate is deliberately sparse: icon, title, one paragraph, one action area.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Progress track | `surface-sunken` on the gate's `surface-canvas` is nearly invisible in light mode. | Track in `line-subtle`. |
| Card vs. dialog failure titles | Card says "Update didn't install", the dialog "Couldn't install the update". | One phrase: "Couldn't install the update" (round 2, copy pass). |
| Dialog chrome | Same overlay, radius, title scale and ✕ as the shortcuts sheet. | — |

### Accessibility
- **Color contrast**: axe 0 violations in all 68 runs. "Needs review" items are text over the modal scrim (axe can't compute through `bg-surface-scrim`) and the shell's ⌘ keycap; the dialog text itself sits on `surface-elevated` (token pairs covered by `@bfhr/ui-tokens` contrast tests).
- **Targets**: card buttons 24 px high (`sm`) like the rest of the sidebar's compact controls; dialog and gate buttons 32–40 px.
- **Text readability**: footnote 12/16 in the card, callout in dialogs, body on the gate.

### What Works Well
- Nothing blocks work until a minimum version really requires it; even then the screen covers the shell instead of unmounting it, so an open editor keeps its edits.
- Every step of a manual check has its own honest state, including "the update isn't available in the app yet" when the gate is up but the manifest hasn't caught up.
- Restart and quit both install; the card says so ("or it installs when you quit").

### Priority Recommendations
1. **Rail dot** — the only signal in the rail; fix its anchor.
2. **Collapsed line** — keep the version readable.
3. **Shortcuts behind the gate** — the gate must actually block.
