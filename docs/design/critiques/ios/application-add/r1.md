## Design Critique: Log an application (iOS, M3) — r1

Captures: `artifacts/screens/ios/iter/add.png` (first build), `artifacts/screens/ios/tracker-audit/tracker-board-add{,-ax}.png`, `tracker-board-added.png` (after Add), `artifacts/screens/ios/tracker-live/tracker-e2e-add.png` (live).

### Overall Impression
A native form sheet that asks only for what identifies the application (company, role) and lets the rest default sensibly (Applied, today). The first build repeated each label as the placeholder and clipped picker values at AX5.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Empty fields showed the label twice ("Company" above a "Company" placeholder) | 🟡 Moderate | Show no placeholder unless it's an example ("Berlin, Remote…") |
| At AX5 "Applied via · Not set" and "Stage · Applied" were clipped beside their labels | 🟡 Moderate | At accessibility sizes, a navigation row (label above value) that pushes the option list |
| Add is disabled until company and role are filled, with no inline error | 🟢 Minor | The footer says so up front ("Company and role are needed to add it.") |
| Cancel with typed text discards silently | 🟡 Moderate | Ask "Discard this application?" and block swipe-to-dismiss while there are edits |
| The date label follows the stage ("Applied on" vs "Since") | 🟢 Minor | Good; the footer explains that suggestions count from it |

### Visual Hierarchy
- **What draws the eye first**: Company, the first field. Correct.
- **Reading flow**: identity → where it stands → notes, as three grouped sections.
- **Emphasis**: Add is the only accent action; Cancel is secondary.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Field labels | Same floating-label convention as the CV editor (`TrackerFormField`) | — |
| Footers | Fg.secondary footers measured low in the audit; investigation showed a measurement offset (accessibility.md) | Footers use Fg.primary at footnote size |

### Accessibility
- **Color contrast**: passes; one documented false positive (accessibility.md, M3).
- **Touch targets**: ≥ 44 pt rows; the AX picker rows are full-width buttons with label and value.
- **Text readability**: everything wraps at AX5.

### What Works Well
- Opens the new application's detail right away, with a quiet toast ("Acme · added to Applied").
- Points to desktop for spreadsheets (empty Pipeline), so iPhone stays one-at-a-time (D35).

### Priority Recommendations
1. **No duplicated placeholders** — done.
2. **AX picker rows** — done (`TrackerPickerRow`).
3. **Discard confirmation** — done.

## Resolution
- `TrackerFormField` shows no placeholder unless an example is given; `TrackerPickerRow` at AX sizes; discard confirmation with `interactiveDismissDisabled`.
- `testLogApplication` (audit, both sizes) and `testLogApplicationFlow` (Add disabled → enabled → detail + toast) pass; the live check logs a real application.
- Open: 0 Critical, 0 Moderate.
