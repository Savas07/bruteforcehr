## Design Critique: Apply sheet

### Overall Impression
The sheet follows the research shape well: one checklist with sensible defaults, the job pinned
in the header, the bottom button naming the next step, a kit that tells you where your files are,
and the Handshake-style question on return. One finding breaks the core promise "nothing goes out
that you haven't seen and that isn't true": the email draft claims a cover letter that isn't
attached.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Email review: the default message says "My CV and cover letter are attached." while Cover letter is "None" and Attachments lists only the CV PDF — an untrue sentence goes to an employer if the user doesn't read the body | 🔴 Critical | Two default bodies: "My CV is attached." without a letter, "My CV and cover letter are attached." with one; an untouched default follows the cover letter choice when the user goes Back and changes it; an edited body is never replaced |
| Email review: Subject has no visible label (From and To do); once filled it's just a line of text between To and the message | 🟡 Moderate | A small "Subject" label above the field (visual only; the field keeps its accessibility label) |
| Send button wraps the address mid-word ("lighthouse-" / "learning.example") | 🟢 Minor | Research: never truncate the verb; the address wraps at the hyphen, which is the system's line break. Acceptable; log |
| Kit footer: "…so the form's file picker finds them." with one file in the list | 🟢 Minor | "…can find your files." (TR/DE adjusted) |
| Kit has Files only; research's Answers section (work authorization, notice period…) is missing | 🟢 Minor | The answers library has no data model yet (apply.md OQ1); out of M4 scope. Log |
| Checklist CV row: "Base CV — English" + "EN · Default" repeats the language | 🟢 Minor | The title is user-chosen; the tag is the CV's language field. Log |
| Checklist recruiter row: the placeholder is the only label and is light grey (system placeholder) | 🟢 Minor | Standard iOS text field; the "Use" button is disabled until the address is valid. Log |
| Kit / email header: role truncates ("Senior Frontend Engi…") between Back and Close | 🟢 Minor | Company stays readable; the checklist shows the full role. System inline title. Log |

### Visual Hierarchy
- **What draws the eye first**: the full-width teal primary at the bottom ("Open company site" / "Send to …"), then the checked rows — right: the sheet is a review before one action.
- **Reading flow**: header (role, company) → CV → Cover letter → Send via → primary. On return, the question card leads ("Did you submit your application to Lighthouse Learning?").
- **Emphasis**: "Yes, I applied" is the filled button, "Not yet" outlined, "I'm not applying" a text button — Monarch's three honest answers with the right weights.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Copy | Matches apply.md copy notes ("Open company site", "Did you submit your application to …?", "Yes, I applied", "Not yet", "I'm not applying"); TR uses siz in sentences; DE du | None |
| Match pill | The CV row reuses `MatchBandPill` ("Strong match") as in the feed | None |
| Footers | All section footers `Fg.secondary`, as in Job detail | None |

### Accessibility
- **Color contrast**: primary label `Fg.onAccent` on `Accent.solid` 6.5 / 4.6:1; From value (accent) 8.7 / 9.0:1; footers `Fg.secondary` 7.0 / 9.5:1 on grouped background.
- **Touch targets**: Cancel/Back/Close, radio rows, Share, the three answers all ≥ 44 pt.
- **Labels**: Subject lacked a visible label (fixed); message editor has the "Message" accessibility label.

### What Works Well
- One review screen with defaults (LinkedIn review) instead of a five-step wizard.
- "opens here in Safari" under each site route — honest about where the user lands.
- "Sent from your connected account. You can undo for 10 seconds after Send." states the undo window before the tap.

### Priority Recommendations
1. **Never send a false sentence** — the default body must match the attachments.
2. **Label Subject** — every field of the outgoing email identifiable.
3. Polish the kit footer copy.

## Resolution

| Finding | Severity | Resolution |
|---------|----------|------------|
| Body claims a cover letter that isn't attached | 🔴 Critical | **Fixed** in 5c5df20 (`apply.email.defaultBody` / `defaultBodyWithLetter` en/tr/de; `ApplyModel.beginEmailApplication` follows the letter choice for an untouched default; tests `emailFromAccount`, `emailBodyFollowsLetter`) |
| Subject unlabeled | 🟡 Moderate | **Fixed** in 5c5df20 |
| Kit footer "them" | 🟢 Minor | **Fixed** in 5c5df20 (`apply.files.footer` en/tr/de) |
| Send button wraps the address | 🟢 Minor | **Rejected**: verb kept, system line break |
| No Answers section | 🟢 Minor | **Rejected for M4**: no answers library yet (apply.md OQ1) |
| Language repeated on CV row | 🟢 Minor | Logged |
| Recruiter placeholder | 🟢 Minor | Logged |
| Header role truncates | 🟢 Minor | **Rejected**: system inline title; full role on the checklist |

`swift test`: 215 tests in 23 suites passed (214 before + `emailBodyFollowsLetter`).
