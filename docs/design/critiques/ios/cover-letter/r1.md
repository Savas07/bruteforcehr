# Cover letter editor (iOS) — critique round 1

- **Screen / goal / persona / stage:** the Apply sheet's cover letter page (BRIEF §4.4.2, research/apply.md "Decision — iOS"): pick a template or draft with AI (`coverLetterDraft`), fill the fields, use the letter. Final round for M4 Apply on iPhone.
- **Captures judged:** `capture.sh --screen apply --arg -BFHRApplyStep --arg letter|letter-draft` on iPhone 17e, light and dark (4 captures). Live: `apply-live-check.sh` drafted a letter through the real callable (check "Letter: drafted by AI and pinned (or a gap kept it out)" PASS).

## Design Critique: Cover letter editor (iPhone)

### Overall Impression

Template, Tone and Language sit as menu rows above "Draft with AI", with the AI disclosure under them; the letter follows as an editable text area. After a draft, a banner says it came from the CV and the job, how many sentences were left out, and offers Dismiss / Undo. Unfilled fields block "Use this letter" with the reason in one line above the button.

### Usability

| Finding                                                                                            | Severity | Recommendation                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. A template's merge tokens (`{role}`, `{company}`) show raw in the editor before they're filled. | 🟢 Minor | Kept: the bar names the next field to fill ("Fill in "Hiring manager"…"), and Insert field / Fields to fill resolve them; showing the token keeps the template honest. |
| 2. "Draft again" replaces the letter.                                                              | 🟢 Minor | Kept: Undo in the banner restores the previous text.                                                                                                                   |
| 3. Placeholders like "[A relevant result and its impact]" block sending.                           | —        | Works as designed: the reason line names the placeholder.                                                                                                              |

### Visual Hierarchy

- **First:** the three menu rows, then "Draft with AI" with its AI-assisted badge.
- **Emphasis:** one filled primary ("Use this letter") in the sticky bar; Undo is the banner's primary right after a draft.

### Consistency

| Element   | Issue                                                   | Recommendation |
| --------- | ------------------------------------------------------- | -------------- |
| Menu rows | Same pattern as CV Studio's template and language rows. | —              |
| AI banner | Same tone and layout as CV Studio's assist banner.      | —              |

### Accessibility

- **Color contrast:** semantic tokens in both themes; the AI badge uses the info tone pair.
- **Touch targets:** rows and buttons ≥ 44 pt.
- **Text readability:** see `../tailor-review/accessibility.md` (shared Apply audit suite).

### What Works Well

- "1 sentence was left out because your CV or the job doesn't support it" explains grounding in plain words.
- Figures the CV can't support stay as `[X]` for the user to fill, instead of being guessed.

## Resolution

Zero Critical, zero Moderate. Minors kept with reasons above.
