# iOS CV editor — critique round 1

Skill: `design-critique` (refinement stage). Inputs: captures on iPhone 17e, light, default and AX5 text size, of the populated CV (Edit), the empty list, Preview, the item edit sheet, ✦ Improve, Version history, Reorder sections, the "…" menu and the DE variant (`artifacts/screens/ios/iphone-17e/cv-editor-*.png`, from `capture.sh` and `CVEditorAccessibilityAuditTests` with `BFHR_CV_SHOTS`).

Context given to the critique: **screen** CVs tab › selected CV (Edit · Preview); **user goal** keep one honest CV current and tailor variants quickly, check how the page will look; **persona** active job seeker, often stressed and short on time, switching between phone and desktop; **stage** refinement; **focus** HIG-native editing (sections → sheets), AI suggestions that never overwrite silently, Preview fidelity, Dynamic Type.

## Design Critique: CV editor (iOS)

### Overall Impression
The screen reads as a calm, native iOS document editor: CV name and save state in the bar, Edit · Preview right under it, inset-grouped sections whose rows show real content. Preview is the strongest part — a real single-column page with the CV's own accent that a recruiter's ATS would read in the same order. The biggest opportunity is the ✦ Improve sheet at large text sizes, where the pinned action bar eats most of the screen, plus one data-honesty slip on the page (a one-off talk shown as "Apr 2025 – Present").

### Usability
| Finding | Severity | Recommendation |
|---|---|---|
| ✦ Improve at AX5: the pinned bar (blank note + Use suggestion + Keep mine + Edit before using) covers ~70 % of the sheet; the suggestion being judged is barely visible. | 🔴 Critical | At accessibility sizes let the actions scroll with the content as the last section; keep the pinned bar at default sizes. |
| A talk with only a date prints "Apr 2025 – Present" on the page and in the Edit row, and its sheet shows "Ongoing" switched on. The CV states something untrue. | 🟡 Moderate | Treat a custom-section item with a start date and no end as a one-off: show one date, "Ongoing" off. |
| Item sheet Cancel without edits did not close the sheet in the UI test (the discard confirmation is attached to a toolbar button, where iOS 26 doesn't reliably present it). | 🟡 Moderate | Attach the discard `confirmationDialog` to the form, not the toolbar item; assert in the UI test that an unchanged sheet closes without asking. |
| The "…" menu's "Versions of this CV" rows show only titles; the kind ("Deutsch variant", "Base CV") is dropped because an inline `Picker` doesn't render subtitles. | 🟢 Minor | Use a titled menu section with buttons (title + subtitle) and a checkmark on the open CV. |
| Variant banner title "Variant of Base CV — English · Deutsch variant" says "variant" twice. | 🟢 Minor | "Deutsch variant of Base CV — English". |
| Reorder (↑↓) in the toolbar and "Reorder sections" in "…" are two reorder entry points. | 🟢 Minor | Keep: ↑↓ shows item drag handles in place (EditButton role), the menu item reorders whole sections in a sheet with Header/Summary pinned. Different scopes, both labelled. |

### Visual Hierarchy
- **What draws the eye first**: the name in the Header card, then the segmented control — correct: the user confirms "this is my CV" and sees the two modes.
- **Reading flow**: bar (title + "Saved · Oct 10 at 10:30 AM") → Edit · Preview → Header → Summary (4 lines) → Experience cards (role, company · dates, first bullet). The item cards give enough to pick the right one without opening it.
- **Emphasis**: section "+ Add" in accent is quiet but findable; destructive actions live only in swipe/sheet. Preview's page is visually distinct from UI chrome (paper on grouped background, raised shadow).

### Consistency
| Element | Issue | Recommendation |
|---|---|---|
| Section headers | System list headers at every size; at AX5 "Header" grows large but wraps cleanly. | Keep. |
| Colour | Tokens only for UI; the page uses paper ink + the CV theme accent (user data). | Keep; documented in code (`CVPaperInk`). |
| Toasts | Remove → "Removed “Pazarbox — Frontend Engineer”" + Undo; suggestion → "Suggestion applied" + Undo — same pattern as other screens. | Keep. |

### Accessibility
- **Color contrast**: tokens throughout; automated audit findings handled in `accessibility.md`.
- **Touch targets**: rows, "+ Add" (min 44 pt), ✦ icon buttons (`IconButton`, 44 pt), chips (44 pt).
- **Text readability**: Dynamic Type everywhere in the editor; the page is fixed-size print by design with "Actual size" zoom and VoiceOver reading the real text.

### What Works Well
- Item cards with role, company · dates and the first bullet make the list scannable and reorderable.
- The suggestion diff never relies on colour alone (strike-through + underline), VoiceOver reads "replaced “Led” with “Drove” …", and blanks like `[X%]` block "Use suggestion" until the real figure is typed — the AI can't invent numbers.
- Variant banner names which base sections changed (Projects, Certificates, Talks) and offers "Open base CV".
- Version history uses the existing change sentences with source + time and a "Current" tag.

### Priority Recommendations
1. **Scroll the ✦ Improve actions at accessibility sizes** — the decision must stay readable while choosing.
2. **One-off dates for custom items** — the page must never claim something the user didn't write.
3. **Reliable discard confirmation** — Cancel with no edits closes; with edits it asks once.
