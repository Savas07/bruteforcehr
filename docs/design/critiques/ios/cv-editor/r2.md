# iOS CV editor — critique round 2

Skill: `design-critique` (refinement stage). Inputs: the full capture matrix after round 1 — iPhone 17e and iPhone 17 Pro Max × populated / empty / loading / error / offline × light / dark × default / AX5 (`artifacts/screens/ios/<device>/cv-editor-<state>-<theme>[-ax].png`) — plus pane captures from `CVEditorAccessibilityAuditTests` (item sheet, ✦ Improve incl. blank filled and applied, Remove + Undo toast, Version history, Reorder sections, "…" menu, DE variant, Preview; light on 17e, dark on Pro Max).

Context: same as round 1 (CVs tab › selected CV; stressed job seeker switching phone/desktop; refinement; focus on states, dark mode, large text and the trust patterns).

## Design Critique: CV editor (iOS), round 2

### Overall Impression
Round 1's fixes hold: the ✦ Improve actions scroll at AX5, the talk prints as "Apr 2025", Cancel on an untouched sheet closes. The states read calmly in both themes and both sizes. What's left is polish: the loading skeleton lost the Edit · Preview bar (layout jumps when data arrives), the first-use list showed a "+" that duplicated the empty state's only action, and an all-archived account would have landed on "No CVs yet".

### Usability
| Finding | Severity | Recommendation |
|---|---|---|
| Loading: the skeleton has no Edit · Preview bar, so the content jumps down when the CV arrives; the bar is the screen's main control. | 🟡 Moderate | Show the real (disabled) segmented bar over the skeleton. |
| Empty list: toolbar "+" (one item, Start from scratch) repeats the empty state's single button. Two identical paths on a first-use screen add noise. | 🟢 Minor | Hide "+" on first use. |
| If every CV is archived, the list said "No CVs yet" and hid the filter, so archived CVs were unreachable. | 🟡 Moderate | First use = no CVs including archived; otherwise show the filter and "All your CVs are archived. Choose Archived in the filter to see them." |
| Error (pushed CV): "Try again" was missing, only "Go back" — the reload action didn't reach the pushed screen. | 🟡 Moderate | Hand the reload action and the clock to the navigation destination explicitly. |
| Section headers ("Header", "Summary", "Highlights") used the system grey, which the audit measured just under 4.5:1 on the grouped background. | 🟡 Moderate | Headers and footers in the `fg.secondary` token (≈ 7.5:1 light). |
| Summary and first-bullet previews were cut at 4 / 2 lines; at AX5 this hid most of the text and the audit reported clipping. | 🟢 Minor | Show the full text; the rows stay scannable because each item is its own card. |
| Edit-sheet fields were single-line and could clip long values and accented capitals at large sizes. | 🟢 Minor | Fields grow vertically; single-value fields drop line breaks so Return can't split a role. |

### Visual Hierarchy
- **What draws the eye first**: light and dark — the name, then the teal "+ Add" and toolbar icons; offline adds the neutral banner first, which is right (it explains why "Saved on this device" would appear).
- **Reading flow** at AX5: the segmented bar and the header card dominate the first screen; the rest scrolls. Acceptable: nothing is truncated and every row keeps its chevron.
- **Emphasis**: Pro Max shows Header, Summary and two experience cards above the fold; the item card's three lines stay distinct (headline / subheadline / footnote).

### Consistency
| Element | Issue | Recommendation |
|---|---|---|
| Error state | Same `PaneError` as other screens, with Try again + Go back on a pushed screen. | Keep. |
| Offline | Shared `ConnectionBannerSection` as the first list item; ✦ Improve disabled with `NeedsConnectionNote`. | Keep. |
| Dark mode | Page in Preview stays white paper with dark ink (it previews a document); UI chrome follows the system. | Keep; documented. |

### Accessibility
- **Color contrast**: header/footer greys moved to the token; remaining audit items are system chrome or content under translucent bars (see `accessibility.md`).
- **Touch targets**: unchanged, ≥ 44 pt.
- **Text readability**: no truncation left in the editor at AX5.

### What Works Well
- Dark mode needs no special casing: tokens and system materials carry it; the teal reads well on black.
- The error and offline states keep the CV's chrome (title, back), so the user knows which CV they're on.
- Undo toasts sit above the tab bar and name the exact entry removed.

### Priority Recommendations
1. **Keep the segmented bar in the skeleton.**
2. **Reachable archive when everything is archived.**
3. **Try again on the pushed error.**

## Resolution

| Finding | Status |
|---|---|
| Skeleton without Edit · Preview | Fixed: disabled segmented bar over `CVFormSkeleton` (`CVDocumentView`). |
| "+" on first use | Fixed: hidden while there are no CVs at all (`CVEditorScreen`). |
| All CVs archived | Fixed: first use requires no archived CVs either; otherwise the filter stays and the list explains where the CVs are (new string `cvEditor.list.allArchived`, en/tr/de). |
| Try again missing on pushed error | Fixed: `bfhrReload` and `bfhrNow` passed into the navigation destination. |
| Header grey contrast | Fixed: `cvListHeader()` / `cvListFooter()` use `BFHRColor.Fg.secondary`. |
| Truncated previews | Fixed: line limits removed from Summary and item rows. |
| Single-line fields | Fixed: vertical-axis fields with line breaks dropped for single values (`CVLabeledField`). |

Round 2 leaves no Critical and no unresolved Moderate finding; round 3 (`r3.md`) checks the fixes on fresh captures.
