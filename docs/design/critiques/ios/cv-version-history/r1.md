## Design Critique: Version history and version viewer

### Overall Impression
History rows read as sentences ("Edited Experience · Pazarbox", "Restored the version from …"); tapping one shows what restoring would change and the page. Clear and calm.

### Usability
| Finding | Severity | Recommendation |
|---|---|---|
| Medium detent shows only two change rows before the Restore bar | 🟢 Minor | Large detent is one drag away; keep |
| "Now" value struck through might read as "deleted" | 🟢 Minor | Labels "Now" / "This version" carry the meaning; colour isn't the only cue |

### Visual Hierarchy
- **First**: timestamp title, then Changes | Page, then Restore (single filled action).

### Consistency
| Element | Issue | Recommendation |
|---|---|---|
| Restore confirm | Uses system confirmation dialog with the reassurance copy from research | — |

### Accessibility
- Contrast/targets pass; each change row is one VoiceOver element (field, before, after).

### What Works Well
- Restore writes a new version; the copy says the current one stays.

### Priority Recommendations
None blocking.

## Resolution
No change needed beyond shared token styles. `testRevisionViewer` (default + AX5) and `testRestoreFlow` pass.
