# Job detail (iOS) — critique round 1

Method: `skill://design-critique` applied to the captures below. Context given to the critique:
screen **Job detail** (pushed on Jobs); user goal: decide in under a minute whether this job is
worth applying to and act on it (apply, save, or hide); persona: an active job seeker, often
stressed and short on time, switching between phone and desktop; stage: **refinement**; focus:
honest match explanation (no false precision), correctable gaps, trust in sources, the Apply route.

## Design Critique: Job detail — Lighthouse Learning · Senior Frontend Engineer

### Overall Impression
Calm and readable: the first viewport answers "what is it, where, how much, how well does it fit"
before anything else, and the match reads as a band with "84 of 100" as a quiet caption. The
biggest opportunity is polish in the action rows: the gap buttons and the capsule badges are
laid out loosely, which makes the most actionable part of the screen (correcting a gap) look
unfinished.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Gap buttons: "I have this" wraps to two lines ("I have / this") with a large checkmark far from the text, next to "Add to CV…" with a large doc icon; the pair looks broken and the primary correction is harder to read | 🟡 Moderate | Text-only secondary buttons; measure the side-by-side layout at its ideal width so it falls back to stacking instead of wrapping inside a button |
| Skills in the breakdown show raw keys ("react", "typescript", "vue") while reasons and gaps say "React", "TypeScript", "Vue.js": the same skill reads two ways | 🟡 Moderate | Display each skill as the gap label or the posting's own spelling; keep the key only as a fallback |
| Not for me reason sheet lists "Role or skills" first (enum order); the research order puts hard filters first (Location, Salary, Seniority…), which is what people usually mean | 🟢 Minor | Use the job-feed-search.md order |
| Hidden state shows the banner and the "Hidden from your feed · Undo" toast at the same time with the same words | 🟢 Minor | Keep: the toast confirms the act (and announces it), the banner is the persistent state after the toast goes. Log only |
| Empty state (no match yet) has no Save button: saving needs a match document in the current model | 🟢 Minor | Log for M4 (save should work without a match); out of scope for the design checkpoint |
| "See full breakdown" row with an up chevron: clear that it opens something | — | Works |

### Visual Hierarchy
- **What draws the eye first**: the job title, then the teal "Strong match" — correct order for the goal.
- **Reading flow**: company → title → where/when → chips → salary → match → counts → breakdown link → reasons → gaps → AI summary → details → description → sources → Not for me. Logical; the sticky Apply bar is always one thumb away.
- **Emphasis**: band label is emphasized, the number is secondary, the bar is a quiet context strip — matches the "band first, no false precision" rule. Salary uses emphasized subheadline, which is right for the second most asked question.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Capsule badges in list rows ("✨ AI summary · can be wrong", "Direct from employer", "Used for Apply", skill chips) | The default label style inside a `List` row puts the title in the row's text column, leaving a wide gap after the icon | Compact label style (icon + 4 pt + title) for every capsule; ask IosFoundation to build it into `AiBadge` / `SourceTag` |
| Details rows | "Where they hire" wraps to two lines while its value has room; other labels stay on one line | Keep labels on one line at default sizes, let the value wrap |
| Status glyphs | Met (filled teal check), partly (half circle), gap (dashed circle) — consistent across card, breakdown and gap rows | Works |

### Accessibility
- **Color contrast**: body and secondary text on white cards pass; teal band label and buttons use accent text tokens. Tag text (`Fg.secondary` on `Surface.sunken`) to verify in the accessibility pass.
- **Touch targets**: Apply, bookmark, thumbs and gap buttons are ≥ 44 pt; source rows are full-row links.
- **Text readability**: body 17 pt, evidence footnotes 13 pt secondary — readable; check at AX5 in the next round.

### What Works Well
- Band first with "84 of 100" as a caption and the labelled segmented bar: no gauge, no "%".
- "Based on “Base CV — English” · updated 7 hours ago" answers "against what, and how fresh" right under the score.
- Every reason carries its evidence ("Posting: “Remote — Europe, UK and Türkiye”") and an impact tag in words.
- Gaps are phrased about the CV, not the person ("Not in your CV yet: Vue.js"), with two ways to correct it.
- The Apply button names the route ("Apply on company site ↗") and the source list marks the row it uses.
- "Not stated" is neutral in Details, never a gap.

### Priority Recommendations
1. **Fix the gap action buttons** — they are the screen's main correction affordance; text-only, no wrapping, stack when they don't fit.
2. **One spelling per skill** — use the gap label or the posting's spelling in the breakdown chips.
3. **Compact capsule badges** — tighten icon/title spacing so the AI label and source badges read as one tag.

## Resolution

| Finding | Severity | Resolution |
|---------|----------|------------|
| Gap buttons wrap / loose icons | 🟡 Moderate | **Fixed** (commit "feat(ios): job detail r1 fixes…"): text-only `bfhrSecondary` buttons; the side-by-side variant is measured at its ideal width (`fixedSize`) so `ViewThatFits` stacks them instead of wrapping |
| Raw skill keys in the breakdown | 🟡 Moderate | **Fixed** (same commit): `ScoredMatch.skillLabels` / `label(forSkill:)` use the gap label, else the posting's spelling; tested in `JobDetailModelTests.skillLabels` |
| Capsule badge spacing | 🟡 Moderate | **Fixed** (same commit) with a private `CompactLabelStyle` applied to `AiBadge`, source badges and skill chips; shared fix requested from IosFoundation |
| "Where they hire" wraps | 🟢 Minor | **Fixed** (same commit): labels keep one line below AX sizes |
| Reason order | 🟢 Minor | **Fixed** (same commit): `DismissReasonSheet.reasonOrder` follows job-feed-search.md |
| Toast + banner say the same thing | 🟢 Minor | **Rejected**: the toast is the transient confirmation with Undo (announced to VoiceOver); the banner is the persistent state once the toast has gone |
| No Save without a match | 🟢 Minor | **Logged** for M4: the save write needs a match document in the current data model (`canToggleSave`) |
