## Design Critique: Job detail — full matrix

### Overall Impression
The screen now holds together across the matrix: the same reading order (job → fit → why → gaps →
summary → details → posting → sources) at every size, dark mode keeps the teal hierarchy without
glare, and AX5 keeps the content in charge with a two-line Apply bar. What remains is polish on
shared pieces (skeleton contrast, the progress note's spinner alignment) rather than this
screen's layout.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Populated (both devices, light/dark): first viewport answers title, company, scope, posted date, work mode, contract, seniority, salary with provenance, band, "84 of 100", basis and freshness, counts; Apply stays one tap away | — | Works |
| Empty (no match yet, no description): "Working out your match…" with a plain promise instead of a 0; "This posting has no description" with Open original posting; Apply still works; More disappears (nothing to hide yet) | — | Works |
| Error: "We couldn't load this job" + why + Try again (VoiceOver focus) + Go back + Copy details; Try again replays the load in design mode | — | Works |
| Offline: neutral banner scrolls with the content (foundation rule), cached job fully readable, Save / Not for me queue | — | Works |
| Loading: the skeleton keeps the real section shapes and reserves the Apply bar, but the redacted text lines are very faint on white cards mid-shimmer | 🟢 Minor | Shared `bfhrSkeleton` contrast; raise with IosFoundation (not this screen's code) |
| Empty, default size: in `ProgressNote` the spinner sits below the title's baseline | 🟢 Minor | Shared component; raise with IosFoundation |
| AX5 reason sheet: the inline title truncates to "What did…" between Skip and Save reason | 🟢 Minor | System behavior for inline titles; the subtitle below still says what to do. Log |
| AX5 hidden state: the toast covers the lower half of the screen for 6–10 s | 🟢 Minor | Shared large-target toast by design (decisions.md D12); it can be swiped away. Log |

### Visual Hierarchy
- **What draws the eye first**: the job title, then the teal band label — on both devices, both themes. On the Pro Max the extra width keeps every meta line on one line.
- **Reading flow**: top-down single column; the "See full breakdown" row ends the match card and the explainer footer sits right under it, so the score is never read without its caveat.
- **Emphasis**: band label (title3, emphasized, accent) > "84 of 100" (subheadline, secondary) > bar (decorative) — consistent in light, dark and AX5.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Tokens | Every color comes from `BFHRColor` / `BFHRTone`; system `.bar` material for the sticky bar, system grouped list backgrounds | None |
| Status glyphs / tags | Same glyph set and rounded tags in the card, the breakdown and the gap rows | None |
| Copy | "Not for me", "Hidden from your feed · Undo · Tell us why", "Not in your CV yet: …", "Matters most / some" match decisions.md D19 and job-detail.md copy notes; TR buttons use the bare form, sentences siz; DE du | None |

### Accessibility
- **Color contrast** (token pairs, computed): primary text 17.4:1 / 15.2:1 (light / dark), secondary 10.1:1 / 10.9:1, secondary on tag fill 8.9:1 / 12.1:1, accent text 8.7:1 / 9.0:1, Apply label on accent 6.5:1 / 4.6:1, AI badge 4.6:1 / 5.3:1, control borders 5.4:1 / 5.8:1 — all ≥ 4.5:1 (text) and ≥ 3:1 (non-text).
- **Touch targets**: Apply, Save, thumbs, gap buttons, toolbar buttons ≥ 44 pt at every size.
- **Text readability**: no truncated meaning at AX5 on either device (the bar and the band legend are capped with the band stated at full size above them; Large Content Viewer on the bar).

### What Works Well
- Honest score: band first, "of 100", labelled bar, basis + freshness, "a rough guide … not a prediction of your chances" — in every theme and size.
- Corrections in place: "I have this" (confirm haptic, toast with Undo) and "Add to CV…" opening the CV the score is based on.
- Sources: direct-from-employer first with its badge, "Used for Apply" on the row the button uses, differing salary shown per source.

### Priority Recommendations
1. **Shared skeleton contrast** — the loading state should read as "content is coming" at a glance (IosFoundation).
2. **ProgressNote alignment** — center the spinner on the title's first line (IosFoundation).
3. Nothing blocking for this screen.
