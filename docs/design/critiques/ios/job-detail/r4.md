## Design Critique: Job detail — submit prompt and application block

### Overall Impression
Both additions land in the right place without disturbing the approved layout: the question sits
above the job (inline, never a modal), and once applied the job shows what happened and where to
track it, then gets out of the way.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Prompt: "Did you submit your application to Northstar Maps?" with Yes, I applied (filled) / Not yet (outlined) / I'm not applying (text) at the top, Apply bar unchanged below | — | Works (Handshake + Monarch) |
| Applied: "Your application" block — status pill, Applied via Company site, Applied 8 days ago, CV link — above "How it fits"; the bar reads "Applied Oct 14" + View in Tracker | — | Works (LinkedIn) |
| The block says "8 days ago" and the bar "Oct 14" for the same date | 🟢 Minor | Both true; relative in the block (`RelativeTimeText`), absolute on the bar. Log |
| Research's quiet "What usually happens next" line under the block is missing | 🟢 Minor | Needs per-stage copy and data (Mercury); log for the Tracker pass |
| Design mode could only show the featured job, so these states were never captured before | 🟢 Minor | **Fixed**: `-BFHRJobId <id>` |

### Visual Hierarchy
- **What draws the eye first**: the prompt's question (headline, bold) on the prompt state; the job title on the applied state. Right in both cases.
- **Reading flow**: prompt → job header → fit; applied: header → your application → fit.
- **Emphasis**: one filled button per state (Yes, I applied / Apply), the applied bar uses a secondary button so nothing pushes a second application.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Shared components | `SubmitPrompt`, `ApplicationSummaryBlock`, `StatusPill` from the catalogue | None |
| Copy | Same strings as the Apply sheet's prompt (apply.md copy notes) | None |

### Accessibility
- **Color contrast**: status pill `Accent.text` on `Accent.subtle` 7.2:1; "Not yet" border `Line.control` 5.4 / 5.8:1.
- **Touch targets**: all three answers and View in Tracker ≥ 44 pt.
- **Text readability**: covered in the r5 matrix (AX5).

### What Works Well
- The prompt never blocks reading the job; "Not yet" defers it until the next open (D02 flow).
- The applied block names the channel and the CV that went out — the evidence the user needs later.

### Priority Recommendations
1. Nothing blocking. Log the "what happens next" line for the Tracker work.
