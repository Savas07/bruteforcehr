## Design Critique: Job detail (live)

### Overall Impression
The live additions sit naturally in the existing structure: the prompt card is first while the
job is Preparing, the application block comes right after the header once applied, and the Apply
bar turns into "Applied Oct 14 · View in Tracker". Nothing new competes with the match section.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Preparing: the Apply bar still shows "Apply on company site ↗" with the external-link arrow, but it now opens the Apply sheet first | 🟢 Minor | The sheet opens Safari one tap later; the arrow still describes the destination. Log |
| AX5 prompt card fills the first viewport; "I'm not applying" sits under the bar until scrolled | 🟢 Minor | List scrolls; all three answers reachable and audited. Keep |
| "Your application" shows "Applied via Company site" and the pinned CV name | — | Matches apply.md "After applying" |

### Visual Hierarchy
- Prompt (when asked) → header → application block (when applied) → match → facts → description → sources.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| SubmitPrompt / ApplicationSummaryBlock | Shared components, same as the Tracker detail | None |

### Accessibility
- `JobDetailAccessibilityAuditTests` (5 tests) pass on this build; see `accessibility.md` (r3 policy unchanged).

### What Works Well
- One Save concept: the bookmark creates the Saved application the Tracker shows (live run PASS).
- The prompt never blocks; it only appears for Preparing jobs.

### Priority Recommendations
None blocking.
