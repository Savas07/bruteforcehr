## Design Critique: Connect email sheet

### Overall Impression
The flow follows the research closely: OAuth providers first with a quiet "Recommended" tag, app-password providers below, a trust footer, numbered help before the fields, and a checklist while the inbox is checked. The weakest spots are a duplicated action on the "not set up yet" screen and a result summary that buries the numbers in sentences.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| "Signing in with Google isn't set up yet" shows "Use an app password" twice: as the card's action and as the primary button right below | 🟡 Moderate | The card only explains; the bottom bar holds the actions (Use an app password · Choose another provider) |
| A failed connection test shows the error under the password field, but VoiceOver users whose focus is on Connect don't hear it | 🟡 Moderate | Announce the error message when the test fails |
| With an auth error the caption "Not your regular password…" repeats the error's own advice right under it | 🟢 Minor | Show the error instead of the caption |
| The email and password fields sit in an unlabelled group; once filled, nothing says what they are | 🟢 Minor | Section header "Your account" |
| Providers list "Recommended" on Gmail/Outlook even though the live project answers `provider_not_configured` today | 🟢 Minor | Kept: the client can't know until it asks, and the answer is calm (r1 screen above) with the app-password route. The row shows "Not set up yet" once the session has learned it |

### Visual Hierarchy
- **What draws the eye first**: on the providers list, the body sentence, then Gmail. Correct.
- **Reading flow**: help steps → Your account → Look back → Server settings → Connect → trust line; the help comes before the fields (AirOps reference).
- **Emphasis**: the inbox-check result reads "Applications found: 14" as running text; numbers don't line up and are hard to scan.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Scan stage rows | The spinner sits lower than the ✓ and ○ symbols (baseline vs. centre) | Fixed-height symbol column centred on the title's first line; small spinner |
| Result rows | Sentences with numbers | `LabeledContent` label + trailing number (monospaced digits) |
| Info vs. warning | "Not set up yet" uses the info tone, errors the warning tone, nothing uses red | Correct; kept |

### Accessibility
- **Color contrast**: teal on light/dark surfaces, amber error text and the info card pass (tokens; audited).
- **Touch targets**: show/hide password eye is 44×44; rows ≥ 52 pt.
- **Text readability**: all copy wraps; the provider list fits the 17e without truncation.
- Secure field content is blank in simulator screenshots (iOS hides secure text from captures); on device it shows dots.

### What Works Well
- `provider_not_configured` reads as "not set up yet" with a working alternative, not as an error.
- Per-provider help with a link to the provider's own app-password page, and GMX/WEB.DE get the extra "turn on IMAP" step.
- Permission to leave during the check ("You can keep going"), matching the server-side backfill.

### Priority Recommendations
1. **One action per intent on the not-set-up screen** — drop the card's action.
2. **Speak connection errors** — `AccessibilityNotification.Announcement` on failure.
3. **Numbers as values in the result** — `LabeledContent`.

## Resolution
- Not set up yet: the `InlineAlert` has no action; the bar keeps Use an app password (Google) and Choose another provider.
- `AppPasswordForm` posts the error as an announcement when the test fails; the error replaces the caption; header "Your account" (`imap.section.account`).
- `ScanStageRow`: symbols in a fixed-height column on the first line, `.controlSize(.small)` spinner.
- Result: `LabeledContent` rows (`scan.result.*Label` keys replace the sentence keys).
- The form body was split (`accountSection`, `passwordField`, `formError`) so the type checker stays fast.
