# Mail review (iOS): critique round 2

Context: Mail tab after round 1; user goal "check what the app wasn't sure about and confirm or correct it in seconds"; persona: active job seeker, often stressed and short on time, switching between phone and desktop. Stage: refinement. Focus: every chip (To review, Updates, All job mail + Category), the review sheet and Change…, the loading / error / offline states, and the largest accessibility text size. Screens (iPhone 17e, light): `mail-review-{populated,offline,loading,error}-light.png`; interaction captures from `MailReviewAccessibilityAuditTests.testCaptureInteractionScreens`: queue scrolled, review sheet (medium detent), Change…, Updates, All job mail (top + scrolled), and the AX versions of the queue and Updates.

## Design Critique: Mail review — all chips, sheet and states

### Overall Impression
Round 1's fixes landed: the scope reads "All accounts ▾ · Checked 6 min. ago", addresses are plain text, and the review sheet is a clear proposal → reason → evidence → Change… / Confirm. The remaining problems are the edges: the loading and error states drop the chips (chrome should stay), the largest text size breaks the sync line into a hyphenated column and lets the Reconnect card take a full screen, and the job-alert bundle says "1 emails".

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Loading and error states replace the whole list, chips included. states.md: "chrome always renders" — the user can't tell where they are or switch to Updates while it loads. | 🟡 Moderate | Keep the chip row in the skeleton and above the pane error ("To review" without a count while it's unknown). |
| At AX sizes "All accounts ▾" and "Checked 6 min. ago" share one row, so "All accounts" hyphenates into four lines ("All / ac- / count / s"). | 🟡 Moderate | Stack scope and time vertically at accessibility sizes; keep the side-by-side line otherwise. |
| At AX sizes the Reconnect card (title + body + button) fills more than a screen, pushing the queue (the reason to open the tab) two screens down. | 🟡 Moderate | One sentence instead of title + body: "We can't check deniz.aksoy@example.net until you sign in again." + Reconnect. Still non-dismissible, still first. |
| Job-alert bundle reads "1 emails". | 🟡 Moderate | Put the count in the title like the chips: "Job alerts (1)"; no plural noun to get wrong in EN/TR/DE. |
| In the review sheet at the medium detent, "Not job mail" sits below the evidence and is only reachable by scrolling or dragging to large. | 🟢 Minor | Logged: intentional separation (research: "kept separate from Confirm, because it removes the message from storage"); Confirm and Change… are pinned. |
| The "To deniz.aksoy@example.com" chip repeats on every row when all queued emails come from the same inbox. | 🟢 Minor | Logged: it disappears as soon as one account is selected; keep it in All accounts because the second inbox exists and needs a sign-in. |
| Updates shows the "More" (•••) button only on that chip, so the toolbar changes when switching chips. | 🟢 Minor | Logged: matches Notion (bulk housekeeping lives where it applies); "Mark all as seen" must never be near To review. |

### Visual Hierarchy
- **What draws the eye first**: the selected chip and the bold proposal line in each row. Correct.
- **Reading flow**: scope + freshness → chips → health card → section header → rows. In the sheet: proposal (headline) → reason → "Needs a look" → evidence block → pinned Change… / Confirm. Good order for a decision.
- **Emphasis**: Updates rows lead with the result ("Moved to Offer") and keep Undo as a quiet trailing text button — right weight for an FYI list. All job mail uses a bold category + muted filing line + amber "To review" state; the state line is easy to scan.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Counts | Chips use "To review (3)", bundle used "1 emails" | "Job alerts (1)" |
| Health card | Two text blocks vs other InlineAlerts with one | One sentence |
| Swipe tints | Confirm accent, Change accent text, Not job mail neutral grey — never red | Keep |

### Accessibility
- **Color contrast**: the automated audit (XCUITest `performAccessibilityAudit`) reports contrast issues on populated screens; details are being logged per element in the next run and handled in `accessibility.md`.
- **Touch targets**: chips and the scope menu ≥ 44 pt; Undo in Updates rows is a ≥ 44 pt text button.
- **Text readability**: AX5 queue rows wrap without truncating the proposal; the sync line and health card fixed above.

### What Works Well
- The sheet's sentence always describes what Confirm will write; after a correction it updates (draft-backed), and Confirm disables itself until category and application are set.
- Updates explain source and reason for every automatic change, each with Undo.
- Error copy names the cause and offers Try again plus Copy details, no blame.

### Priority Recommendations
1. **Chrome in loading / error** — keep chips visible.
2. **AX layout** — stacked sync line, one-sentence health card.
3. **Count copy** — "Job alerts (1)".

## Resolution

| Finding | Severity | Resolution |
|---|---|---|
| Chips missing in loading / error | 🟡 | Fixed: `chipsOnlyHeader` in the skeleton and above `PaneError`; new key `mail.chip.toReviewPlain`. |
| AX sync line hyphenation | 🟡 | Fixed: `AnyLayout` stacks scope and time at accessibility sizes. |
| AX health card height | 🟡 | Fixed: one-sentence title (`mail.reconnect.title`), body removed. |
| "1 emails" | 🟡 | Fixed: `mail.jobAlerts` = "Job alerts (%lld)"; separate count line removed. |
| Not job mail below the fold | 🟢 | Logged (intentional separation). |
| Repeated inbox chip | 🟢 | Logged. |
| Toolbar ••• only on Updates | 🟢 | Logged (intentional). |
