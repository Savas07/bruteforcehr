## Design Critique: Onboarding

### Overall Impression

Calm and short: one question per step, the step named in text and in the bar, Skip for now always in the same place, and the CV read in the background so Continue never waits. The CV-filled Preferences step mostly asks the user to confirm. Round 1 found two moderate problems that came from real use (the number pad can't be closed; the CV line said "Found 1 roles") and two moderate visual ones on Finish (busy button washed out; the Where value wrapped awkwardly).

### Usability

| Finding | Severity | Recommendation |
| --- | --- | --- |
| The salary amount uses the number pad, which has no Return key. Once open it covered Work authorization and Continue; in the live run the "Yes" tap for EU / EEA landed on the keyboard and the answer was never saved. | 🟡 Moderate | A **Done** button above the number pad (`ToolbarItemGroup(placement: .keyboard)`), shown only while the amount is edited. |
| The CV status line read "Found 1 roles and 4 skills" (live run). The string catalogs have no plural variants. | 🟡 Moderate | Compose from singular / plural phrases ("1 role", "3 roles"); "Read your CV" when it found neither. |
| A skill group's name ("Languages", "Frontend") was saved as a skill next to its keywords (live run: `languages`, `swift`, `kotlin`, `sql`). | 🟡 Moderate | When a group lists keywords, only the keywords are skills. |
| With no role and no place, Start searching created an empty "Jobs for you" search that matches everything; D40 (agreed with the desktop afterwards) says to offer Back to preferences and Go to Today instead. | 🟡 Moderate | `canSearch`; the `finish-nothing` state shows the explanation, **Back to preferences** (primary) and **Go to Today**. |
| Step 1 shows no Continue until a choice is made; Skip for now is the way past it. | — | Keep: research (a choice or an explicit skip), and the three rows are the actions. |
| A failed write on Finish keeps the step with a calm warning; offline, Finish moves on after 15 s and the writes sync later. | — | Keep. |

### Visual Hierarchy

- **What draws the eye first**: the step bar and the title ("Start with your CV" / "What are you looking for?" / "Start your first search"), then the options or the first section — correct.
- **Reading flow**: Step label → title → one-line reason → content → the sticky primary button. On Preferences the sections follow the research order (Roles, Seniority, Where, Salary floor, Work authorization, Languages).
- **Emphasis**: "Setting up your search…" used the disabled button style (grey label on grey), so the one moment the app is working looked like it had stopped. 🟡 Moderate → keep the primary colors and ignore taps while busy.
- **Finish summary**: LabeledContent put a long Where value ("Germany, Netherlands, and United Kingdom") in a ragged right-aligned block under its label. 🟢 Minor → title over value rows, left-aligned, like Settings › Job preferences.

### Accessibility

See `accessibility.md` (XCUITest `performAccessibilityAudit` on every state at the default and AX5 sizes, TR and DE, VoiceOver notes).

### What Works Well

- The CV is read while the user moves on; the found line is the "aha" without a review step (D44).
- Work authorization follows the places: one EU / EEA question for EU picks, none for Remote worldwide.
- The same section editors are reused in Settings › Job preferences, so nothing is learned twice.

### Priority Recommendations

1. **Done above the number pad** — the live run lost an answer to it.
2. **Plural-safe found line and keyword-only skills** — both visible in the first live run.
3. **D40 nothing-to-search state** — no empty search that matches everything.
4. **Busy Finish button keeps its colors; Where summary as title over value.**
