## Design Critique: Saved searches

### Overall Impression
The list is the strongest of the Jobs screens: each row says what the search is ("“react
typescript frontend” · Remote · Last 14 days · €55K+"), how often it runs and what's new, exactly
the Glassdoor + Realtor.com pairing. The editor and the load states need work.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Editor › Search: two text fields with no visible labels ("Istanbul · hybrid", "frontend"); once filled, nothing says which is the name and which the keywords | 🟡 Moderate | A small label above each field ("Name", "Keywords"), as the import review does; the keywords field keeps "Role, skill or company" as its placeholder |
| Editor › Filters: the summary is right-aligned and wraps raggedly ("… · Mid-" / "level, Senior"), and the row has no chevron, so it doesn't look tappable | 🟡 Moderate | Label on top, summary under it left-aligned as a sentence, trailing chevron |
| Loading / error states: the list has no load phase — while the feed loads it would say "No saved searches yet" (and Hidden jobs "Jobs you hide with Not for me show up here."), a false empty (states.md) | 🟡 Moderate | Wrap both screens in `PhaseContainer` on the feed model's phase: skeleton rows, then `PaneError` with Try again |
| Hidden jobs: "Show in feed" is a swipe (also context menu and VoiceOver action), with the footer "Swipe right to show one again" | 🟢 Minor | Opening the job also offers Undo on its hidden banner; a button inside a NavigationLink row would fight the row tap. Log |
| Footer "Saved searches run on their schedule, even when the app is closed." sits under a search whose row says "Alerts off" | 🟢 Minor | True for searches with alerts on; the row states the exception. Log |
| Delete saved search is a red row at the end of the editor; no confirmation, Undo toast after | 🟢 Minor | Matches the eBay Undo pattern (trust principle); log |

### Visual Hierarchy
- **What draws the eye first**: the search name (headline), then the teal "New: 4" badge — right for "which search has news".
- **Reading flow**: name → criteria → cadence; "+ New saved search" ghost row ends the list; Hidden jobs is a separate group with its count.
- **Emphasis**: only the badge and the ghost row use accent; cadence in footnote secondary.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Copy | "Hidden jobs", "Saved searches" match D10; "Your reasons: Role or skills and Salary" reuses Job detail's reason labels | None |
| Badges | "New: 2" uses the plural-free "Label: N" form like the feed | None |
| Editor | Toggle tint `Accent.solid`; destructive row uses the system red | None |

### Accessibility
- **Color contrast**: name `Fg.primary`, criteria and cadence `Fg.secondary` (≥ 10:1); badge `Accent.text` on `Accent.subtle` 7.2:1; section headers `Fg.secondary` on grouped background 7.0 / 9.5:1.
- **Touch targets**: rows full width; ghost row and Hidden jobs row ≥ 44 pt.
- **Labels**: editor fields lacked visible labels (above); VoiceOver gets "Name" / the placeholder — fixed together with the visible labels ("Keywords").

### What Works Well
- Criteria in plain text per row (Realtor.com), cadence and threshold in one line ("Every day · Strong matches").
- Hidden jobs keeps the reasons the user gave and promises the dedupe ("Hidden jobs don't come back from other sites").
- Alerts off is explained in the editor footer ("The search stays saved. It won't run on its own or notify you.").

### Priority Recommendations
1. **No false empty while loading** — `PhaseContainer` on both screens.
2. **Label the editor's fields** — the name/keywords ambiguity.
3. **Filters row as a sentence with a chevron** — readable and obviously tappable.
