## Design Critique: Share Extension — "Save job" sheet (iOS), round 1

Input: captures of `JobImportShareSheet` (design host `-BFHRShareSheet`, iPhone 17e) in the states ready, ai, existing, saved, blocked, manual, signed-out and reading, light and dark, default and AX5 text size. Research: `docs/design/research/job-import-share.md`. Stage: refinement.

### Overall Impression
It's calm and quick to read. The source line says where the job came from and how it was read before you're asked to check anything. Two full-width actions make the choice clear. The biggest problem: at accessibility sizes the pinned buttons cover most of the sheet, and in hand entry the "Not stated" placeholder reads like data.

### Usability
| Finding | Severity | Recommendation |
|---|---|---|
| At AX5 the pinned Save / Save and log as applied take ~30 % of the screen. Role, company and location sit below the fold behind them, and you can't scroll them clear of the buttons. | 🟡 Moderate | At accessibility sizes, put the actions in a final Form section that scrolls with the fields. Keep them pinned at default sizes. |
| Hand entry: the empty Location field shows "Not stated", which reads as a fact about a posting, not as a hint. | 🟡 Moderate | Use "Optional" as the placeholder in hand entry. Keep "Not stated" for an imported posting with no place. |
| Hand entry: Save is disabled while role and company are empty, but the footer only talks about the notes. Nothing explains the disabled button. | 🟡 Moderate | While role or company is missing, show "Role and company are needed to save it." as the footer (the same rule Log an application uses). |
| The blocked state offers only "Add it by hand" (Cancel is in the bar). Try again is rightly hidden, since a wall doesn't go away. | 🟢 Minor | Keep. |
| Existing job: the read-only rows and the info alert explain the merge. "Save" then adds an application only if none exists, and the saved state says so. | 🟢 Minor | Keep. |

### Visual Hierarchy
- **What draws the eye first**: the source card ("From jobs.ashbyhq.com"), then the fields. That's correct, because trust comes before confirming.
- **Reading flow**: source → (merge note) → role / company / location → footer → actions. It's linear and short.
- **Emphasis**: the primary is Save (teal), which is the right default. "Save and log as applied" is secondary, so logging is a deliberate choice.

### Consistency
| Element | Issue | Recommendation |
|---|---|---|
| Fields | They use `TrackerFormField` (labels above values), like Log an application. | — |
| Buttons | `.bfhr(.primary/.secondary, fullWidth:)`, stacked, as in Pocket's save sheet and BFHR's `ButtonPair` rule for German. | — |
| AI | The AI-assisted badge plus a check-the-details line, as in decisions.md D13. | — |
| Failure screens | The glyph, title and body pattern centred in a scroll view matches `EmptyState`'s anatomy. | — |

### Accessibility
- **Color contrast**: body text, footers and buttons use token pairs (Fg.primary / Fg.secondary, accent primary). Light and dark both read clearly in the captures.
- **Touch targets**: buttons are full width and ≥ 44 pt; Cancel is the system bar button.
- **Text readability**: at AX5 the host wraps ("jobs.ashby-hq.com") and fields grow. Only the pinned actions were a problem (fixed below).
- **VoiceOver**: the source card is one element ("From jobs.ashbyhq.com, Read from the page's job details"). The saving spinners carry "Saving…". Failure titles are headers.

### What Works Well
- Saying how the fields were found ("Read from the page's job details" vs "Read by AI … Check the details.") answers "can I trust this?" without extra UI.
- Every failure ends in an action (Add it by hand) and calm copy that doesn't blame the person or the site.
- A merge into an existing job is visible, and the sheet never creates a duplicate.

### Priority Recommendations
1. **Scroll the actions at accessibility sizes**, so people using large text can see what they're saving.
2. **"Optional" placeholder in hand entry**, so it reads as a hint, not data.
3. **Explain the disabled Save in hand entry** with the required-fields footer.

## Resolution

- **AX actions**: `JobImportShareSheet.form` puts the actions in a last Form section when `dynamicTypeSize.isAccessibilitySize`. They stay pinned (`safeAreaInset`) otherwise.
- **Placeholder**: hand entry uses the new `share.optional` ("Optional" / "İsteğe bağlı" / "Optional"). Imported jobs keep "Not stated".
- **Footer**: the footer shows `share.requiredFooter` whenever role or company is empty, in both import and hand entry. Otherwise it shows the import or hand-entry explanation.
- Re-captured the full matrix: 10 states × light/dark × default/AX5 × iPhone 17e and 17 Pro Max. `ShareSheetAccessibilityAuditTests` covers every state at both sizes and the main states in TR and DE (see `accessibility.md`).
- Open after r1: none Critical, none Moderate.
- After the a11y audit (accessibility.md): an already-saved job's values use `readOnlyRow` (primary color, label above). "Add it by hand" is now the navigation title instead of a low-contrast section header. The source line wraps.
- Live capture: the real extension, from Safari on iPhone 17 Pro (`apps/ios/scripts/share-live-check.sh`): Safari ⋯ → Share → BruteForceHR → fields read by `jobImportUrl` → Save and log as applied. It wrote the job, an Applied application and a user `created` event, then deleted them.
