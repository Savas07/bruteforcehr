# Sign-in (iOS) — critique round 1

Context: passwordless sign-in with Firebase Authentication's email link (ADR 0003, owner decision 2026-10-23: no Brevo, Firebase sends the link). Signed out, the app shows a full-screen takeover instead of the tabs: email → "Check your email" → the emailed link opens the app (universal link) → tabs. Extra states: a link opened on a device that didn't ask for it (confirm the address), expired / used links, offline or server failures, a disabled account. Audience: the owner and invited testers; job hunting is stressful, so the flow stays calm, plain and short. Stage: refinement (first implementation). Research: [onboarding-signin.md](../../../research/onboarding-signin.md) (email step, waiting state, errors), adapted from a 6-digit code to a link.

## Design Critique: Sign-in (iOS), round 1

### Overall Impression

The flow reads in two seconds on every step: a glyph, a plain title, one sentence, and one primary action at the thumb. It is calm (no hype, no exclamation marks) and the "Open it on this iPhone" line covers the main way an email link fails. The biggest problems are two rendering bugs: the example address in the field and in the error turns into a blue `mailto:` link, and the address the link went to doesn't stand out.

### Usability

| Finding | Severity | Recommendation |
|---|---|---|
| The placeholder `name@example.com` and the example in "Enter a full email address, like name@example.com." render as **blue mailto links** (SwiftUI turns addresses in localized strings into links). In the field it looks like typed text in the wrong color; in the error a tap would open Mail. | 🔴 Critical | Render both with `Text(bfhrPlain:)` (foundation-ios.md: strings with addresses never use plain `Text(resource)`). |
| "Check your email": the address is plain body text, so it doesn't jump out when the user checks for a typo. | 🟡 Moderate | Bold the address (Mesh); keep "Use a different email" as the fix. |
| The confirm step ("This link was requested on another device") uses `person.crop.circle.badge.questionmark`: the question badge sits outside the circle and reads as "unknown person", slightly alarming for a routine step. | 🟢 Minor | Use `envelope.open` — the same mail family as the email and check steps, and it says "you opened the link". |
| The problem states (expired, used, offline, disabled) draw their glyph in the teal accent, which elsewhere means "all good / do this". | 🟢 Minor | Draw problem glyphs in the secondary text color; the primary button stays the only accent. |
| A long address at the largest text size scrolls sideways inside a one-line field (the audit flags "Text clipped"). | 🟡 Moderate | Make the field vertical so the address wraps; Return still sends. |
| Disabled "Resend link (0:42)" is grey on white. | 🟢 Minor | Keep: disabled controls are exempt from contrast, the countdown is in the label, and VoiceOver hears "Resend link, Available in 42 seconds". |
| Large empty middle between the text and the pinned buttons on every step. | 🟢 Minor | Keep: content top-aligned where reading starts, actions where the thumb is (same as the update gate); at AX sizes the actions follow the text. |

### Visual Hierarchy

- **What draws the eye first**: the large title, then the teal primary button. Correct on every step.
- **Reading flow**: glyph → title → sentence → field (email steps) → primary → legal (email) or secondary actions (check, problems).
- **Emphasis**: one primary per step. On "Check your email" Open Mail is primary, Resend is secondary (outlined), "Use a different email" is a plain text button — matches how often each is needed.

### Consistency

| Element | Issue | Recommendation |
|---|---|---|
| Layout | Same scaffold as `UpdateRequiredScreen` (title1 emphasized, body, 24 pt margins, canvas, pinned actions at default sizes, inline at AX). | Keep. |
| Field | Custom bordered field: `Surface.base`, `Line.control` 1 pt, `Line.focus` 2 pt focused, `danger.solid` 2 pt with an error. Tokens only. | Keep. |
| Errors | Send failures use the shared `InlineAlert` (error / warning tone); field errors are an inline danger label with a glyph, so color isn't the only signal. | Keep. |
| Success line | "We sent another link" uses `success.text` with a ✓ glyph. | Keep. |

### Accessibility

- **Color contrast**: body `fg-primary` and secondary `fg-secondary` on `surface-canvas` (16.26:1 / 7.31:1 light), primary button `fg-on-accent` on `accent-solid` 6.51:1, legal links `fg-link`. The XCUITest audit (default size, English, every state) passed after the fixes below.
- **Touch targets**: buttons ≥ 44 pt (shared `BFHRButtonStyle`), field ≥ 48 pt.
- **VoiceOver**: the title is a header and takes focus on each step; the field is labelled "Email"; field errors are announced; the countdown is a value, not a changing label.
- **Text readability**: default size fine; AX captures come in round 2.

### What Works Well

- One idea per step and plain copy: "We'll email you a link to sign in. No password needed."
- Every problem state has a way forward ("Send a new link", "Try again", "Get help") and a way out ("Use a different email"); offline says the link still works, so nobody requests links in a loop.
- The other-device case explains *why* the address is asked again instead of failing.

### Priority Recommendations

1. **Plain text for example addresses** — the mailto bug.
2. **Bold address on Check your email** — the typo check.
3. **Wrapping field** — the AX clipping.

## Resolution

1. Placeholder and field errors render with `Text(bfhrPlain:)`.
2. `signIn.check.body` bolds the address (`**%@**` in en/tr/de).
3. The email field is a vertical `TextField` (wraps); a line break from Return submits instead of being inserted, and `.onSubmit` stays for the Send key.
4. Confirm step glyph → `envelope.open`; problem glyphs use `Fg.secondary`.
5. XCUITest found the step identifiers missing: a `Group` hands its modifiers to each child, so the screen's identifier replaced each step's. The screen root is a `ZStack` container and each step's identifier sits on its title.
