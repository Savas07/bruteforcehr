## Design Critique: Sign-in (iOS), round 2

### Overall Impression

The r1 fixes hold on both devices and both themes: plain example addresses, the bold address on "Check your email", calmer problem glyphs, a wrapping field. Dark mode reads well (teal primary on near-black, secondary text legible). What's left is the largest accessibility size: the placeholder truncates, and long words hyphenate.

### Usability

| Finding | Severity | Recommendation |
|---|---|---|
| AX5: the placeholder "name@example.com" truncates to "name@exa…" (17e) / "name@exampl…" (Pro Max). A placeholder can't wrap. | 🟡 Moderate | At accessibility sizes, drop the example placeholder; the "Email" label above names the field (SwiftUI then shows the label as a short placeholder). |
| AX5: the address on "Check your email" breaks inside the token ("deniz.aksoy@ex / ample.com"). | 🟢 Minor | Keep: at AX5 the address is wider than the screen on any layout; it stays bold and complete, and VoiceOver reads it whole. |
| AX5 17e: the title hyphenates the app name ("Brute- / ForceHR"). | 🟢 Minor | Keep: system hyphenation of a long word at the largest size, same as other titles; nothing is cut. |
| Account menu (signed in): "Signed in as {email}" header + "Sign out" with the system glyph. One tap away, no confirmation. | 🟢 Minor | Keep: signing out loses nothing (data is in the cloud; the address is pre-filled on the sign-in screen afterwards); a confirmation would add a step to a rare, deliberate action. |
| Disabled "Resend link (0:42)" is shortened in TR/DE to "Tekrar gönder (0:42)" / "Erneut senden (0:42)". | 🟢 Minor | Keep: the countdown variant has to fit on one line next to the time; the enabled label and VoiceOver name stay the full "Bağlantıyı tekrar gönder" / "Link erneut senden". |

### Visual Hierarchy

- **What draws the eye first**: the title, then the teal primary; on problem states the neutral glyph no longer competes with the button.
- **Reading flow**: unchanged from r1; at AX5 the actions follow the text, so the explanation reads top to bottom before the buttons (same rule as the update gate).
- **Emphasis**: correct on both devices; the Pro Max adds width, not new elements.

### Consistency

| Element | Issue | Recommendation |
|---|---|---|
| Copy (EN/TR/DE) | TR uses *siz* in sentences ("E-postanızı kontrol edin", "Kendinize yeni bir bağlantı gönderin") and the short imperative on buttons ("Bağlantı gönder", "Mail'i aç"), matching the update gate ("TestFlight'ı aç"). DE uses *du* ("Schau in dein Postfach", "Prüf deine Verbindung"). | Keep. |
| Account menu | Native `Menu` from the avatar (IA.md updated: the avatar opens the account menu; Settings joins it when the sheet lands). | Keep. |

### Accessibility

- **Color contrast**: the XCUITest audit passed on every state at the default size and AX5 in English (17e light, Pro Max dark) and in Turkish and German.
- **Touch targets**: unchanged, ≥ 44 pt.
- **Text readability**: every line visible at AX5 in all three languages (German hyphenates: "Anmel-dung", "abzu-schließen"). The audit's German "Text clipped" predictions are a known false positive (see [accessibility.md](accessibility.md)).

### What Works Well

- The live run proves the copy promise: the emailed link opened the app, signed in, and the account menu named the address.
- Offline and server failures keep the link ("Your link still works"), so people don't request new links in a loop and hit the send limit.

### Priority Recommendations

1. **Drop the placeholder at accessibility sizes.**

## Resolution

1. `EmailStep` passes no prompt at accessibility sizes (`dynamicTypeSize.isAccessibilitySize`); the default size keeps `name@example.com`.

Exit criteria: no critical or moderate finding open; audits green ([accessibility.md](accessibility.md)).
