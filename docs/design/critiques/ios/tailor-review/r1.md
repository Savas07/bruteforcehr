## Design Critique: Tailor review (iPhone)

### Overall Impression

The flow reads in the right order on a 4.7-inch screen: "How much to change" (Light / Thorough) with the AI disclosure, then one card per suggestion with its location ("Experience · Pazarbox · bullet 1"), the struck original, the suggestion and "Why". Decided cards collapse to "Accepted · Decide again", so what is left stands out. The sticky bar holds one primary ("Save as new version") and the two bulk actions.

### Usability

| Finding                                                                                                                                                                         | Severity    | Recommendation                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Each card's container id replaced the ids of its Accept / Keep original buttons, so VoiceOver-driven automation (and the live test) couldn't address a single card's action. | 🟡 Moderate | **Fixed:** the card is an `accessibilityElement(children: .contain)` container with its own id; the buttons keep theirs (`TailorReviewView.swift`).           |
| 2. An Accept half under the sticky bar sits where a tap lands on "Keep original for the rest".                                                                                  | 🟢 Minor    | Kept: the List scrolls the card fully into view before a person can read it; the live test now taps only unobstructed buttons and verifies each card's state. |
| 3. "Accept all" exists although research/apply.md argued against it.                                                                                                            | 🟢 Minor    | Owner request, decisions.md **D44**: skips suggestions with a `[gap]`, nothing is saved before "Save as new version", every decision can be changed.          |
| 4. The checklist shows two rows named "Base CV — English" after saving.                                                                                                         | 🟢 Minor    | Kept: the tailored one says "Tailored for this job" with the AI-assisted badge and is the selected row.                                                       |
| 5. AI off: a single info card with "Open AI settings"; the daily limit uses the existing AI limit copy.                                                                         | —           | Works as designed (no request is sent).                                                                                                                       |

### Visual Hierarchy

- **First:** the job title in the navigation bar, then "5 suggested edits" with the tally, then the first card.
- **Reading flow:** location → original (struck, secondary) → suggestion (primary text) → Why → decision.
- **Emphasis:** one filled button (Save); Accept all / Keep original for the rest are outlined; per-card Accept is the primary of the card's pair.

### Consistency

| Element       | Issue                                                                  | Recommendation                                                     |
| ------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Section chips | Wrap to two lines (All · Summary · Experience / Skills) on iPhone 17e. | Kept: ChipFlow is the app's filter pattern (Jobs, Saved searches). |
| Preview       | The CV renders as paper (white) in dark mode.                          | Correct: it is the document as sent, same as CV Studio's preview.  |

### Accessibility

- **Color contrast:** text uses the semantic tokens; "Reworded" / "New order" badges use the info tone pair (checked in both themes).
- **Touch targets:** card buttons and bar buttons are ≥ 44 pt.
- **Text readability:** Dynamic Type through AX5 — see `accessibility.md` (XCUITest audits on CI).

### What Works Well

- The struck original next to the suggestion makes each change checkable without leaving the card.
- "Based on" names the CV source of a suggestion, so a person can see nothing was invented.
- Tally + "to decide" count in the bar tell you how much is left.

### Priority Recommendations

1. **Card ids** — done (Moderate 1).
2. Keep "Accept all" under D44 and watch whether people still read each card (owner sign-off).

## Resolution

Zero Critical, zero open Moderate. Moderate 1 fixed in `TailorReviewView.swift` and verified by the live check (2 suggestions accepted, an `ai_tailor` revision with `jobId` and `basedOnRevisionId` saved and pinned on the application). Minors 2–4 kept with reasons above.
