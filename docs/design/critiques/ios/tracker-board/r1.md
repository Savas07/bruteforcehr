# iOS Tracker board — critique round 1

Skill: `skill://design-critique` (with `ux-copy` for wording). Date: 2026-10-22.
Context: Tracker tab › Pipeline and the pushed Application detail. User goal: see where every application stands and move one forward in seconds. Persona: active job seeker, often stressed and short on time, switching between phone and desktop. Stage: refinement. Focus: the three move paths, closed-outcome tone, AX5.
Screens reviewed (iPhone 17e, light): `tracker-board-{populated,empty,loading,error,offline}-light.png` from `capture.sh`, plus the flow shots from `TrackerBoardAccessibilityAuditTests` (scrolled Pipeline, Closed scope, context menu, Move to… sheet, leading swipe, Undo toast, Pipeline at AX5, row tap).

## Design Critique: Tracker › Pipeline + Application detail

### Overall Impression
The Pipeline reads as one calm, scannable list: scope tabs, a stage strip with counts, then stage sections with a dot, label and count. Rows carry exactly one "what's next" line, and the closed outcomes are grey with "Not selected". The biggest problem is that a tap on a row doesn't open the Application detail at all, so the timeline (and its automatic-change Undo) can't be reached.

### Usability
| Finding | Severity | Recommendation |
|---------|----------|----------------|
| Tapping a row highlights it but nothing is pushed: the value-based `NavigationLink(value:)` can't land in the tab's typed `[DesignScreen]` navigation path. The detail, timeline and Undo of automatic changes are unreachable. | 🔴 Critical | Use a destination-based `NavigationLink { detail } label: { row }`, which works with any stack. |
| Sticky section headers are transparent: when a row scrolls under "Preparing 2" both texts overlap ("Frontend Gelistirici" under "Acknowledged 3"). | 🟡 Moderate | Give the pinned header an opaque system-background fill across the full width. |
| Move to… sheet at the medium detent is iOS 26 glass: the Pipeline's rows show through the status rows, and the sheet doesn't say which application it moves. On a long list that's a real risk of moving the wrong one. | 🟡 Moderate | Solid grouped background; title "Move to…" with the application ("Aire Digital Health · Frontend Engineer") as a subtitle. Same for Close…. |
| AX5: the 36 pt monogram scales to about 90 pt and squeezes the role into hyphenated syllables ("Front-end Engi-neer"). | 🟡 Moderate | At accessibility sizes, drop the decorative monogram (its envelope badge moves next to the day count) so the role keeps whole words. |
| The Close… sheet's dismiss button reads "Close" right above "Close application" outcomes: two meanings of one word in one sheet. | 🟡 Moderate | Use the system ✕ close button (`Button(role: .close)`), keep "Close…" only for the outcome action. |
| The Active list doesn't show the phase grouping (Shortlist / In progress) from the research decision; stages read as one flat list of seven. | 🟡 Moderate | A small uppercase phase caption above the first stage of each phase (not in Closed, where it would repeat the tab). |
| The most time-critical row (Kervan, interview today 15:00) sits about four screens down below Saved and Preparing. | 🟢 Minor | Keep status order (the user's mental model of the pipeline); the stage strip reaches Interviewing in one tap and Today's Next up owns time-critical items (IA: one home per object). Logged as an open question for the user. |
| Empty Pipeline offers only "Find jobs"; states.md also lists "Add application". | 🟢 Minor | No manual-add flow exists in M0; a button that does nothing would break data honesty. Add it with the Log-an-application sheet. |
| Loading skeleton redacted the stage names and dropped the scope tabs (states.md: real headers with "–" counts). | 🟢 Minor | Keep the scope tabs and stage headers real (`unredacted`), skeleton only the rows. |

### Visual Hierarchy
- **What draws the eye first**: the large title, then the stage strip chips. Correct: the strip is the overview ("where do things stand").
- **Reading flow**: scope → strip → stage header → rows. Each row: role (headline) → company (secondary) → next step (footnote with a glyph). Clear.
- **Emphasis**: the interview line is the only accent-colored text on a row, which is right: it's the one thing with a time. Staleness ("No reply in 9 days") stays neutral with an hourglass, never red.

### Consistency
| Element | Issue | Recommendation |
|---------|-------|----------------|
| Section spacing | ~50 pt between a stage header and its first row plus the inter-section gap; only three rows fit above the fold on the 17e. | Header rows get zero list insets and own padding; the remaining gap is the system plain-list section spacing (accepted). |
| Closed rows | Trailing meta switches from "12 d" (active) to "13 days ago" (closed). | Accepted: for closed rows the day it ended is the useful fact; VoiceOver reads the full date for both. |
| Disabled reason in Close… | "Accepted and Declined come after an offer." repeats under both rows (shared `StatusMenu`). | Minor, shared component; logged for IosFoundation rather than forked here. |

### Accessibility
- **Color contrast**: labels use `Fg.primary/secondary` and the status tone text; to be measured by the XCUITest audit (accessibility.md).
- **Touch targets**: strip chips, section headers and toast Undo are ≥ 44 pt.
- **Text readability**: Dynamic Type through `Font.bfhr`; AX5 problem above.

### What Works Well
- One list instead of a column pager: every stage is named and counted, nothing hides behind a swipe.
- The three move paths share one action list (`bfhrRowActions`): leading swipe "Move to Preparing", trailing Move to… / Close…, the same items in the long-press menu and the VoiceOver rotor.
- Rejection is calm: grey tone, "Not selected", and the toast "marked as not selected. Your notes stay here." with Undo.
- Offline keeps the list and adds the neutral banner; errors keep the title and offer Try again.

### Priority Recommendations
1. **Make rows open the detail** — without it the timeline, source/reason and Undo of automatic changes are unreachable.
2. **Opaque sticky headers and a titled, solid Move to… sheet** — both prevent acting on the wrong application.
3. **AX5 row layout** — whole words for the role at the largest sizes.
