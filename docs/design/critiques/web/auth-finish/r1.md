## Design Critique: Sign-in link landing

### Overall Impression

The structure is right (state title, the browser-prompt hint, one primary action, a quiet fallback block), but three defects stop it shipping: missing spaces between the inline sentences of the fallback, a display-size headline that shouts on a transient page, and German hyphenation splitting the product name.

### Usability

| Finding                                                                                                                                                                                 | Severity    | Recommendation                                                                         |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | -------------------------------------------------------------------------------------- |
| "Didn't open?Make sure…" and "computer.Download BruteForceHR": Astro's HTML compression drops the whitespace between the inline `span`/`a` elements. Reads as a typo in every language. | 🔴 Critical | Add explicit `{" "}` between the inline elements.                                      |
| The footnote "This browser doesn't sign in." is ambiguous (sounds like an error).                                                                                                       | 🟡 Moderate | "You won't be signed in to this browser. You can close this tab once the app is open." |
| No-JS / bare `/auth/finish` shows "This link isn't complete" with a path to help. Correct and non-blaming.                                                                              | 🟢 Minor    | Keep.                                                                                  |

### Visual Hierarchy

- **What draws the eye first:** at 1440 the 2-line `display` headline "Opening BruteForceHR" dominates; the primary button is visually second. For a page people see for a second, the headline should be a label, not a hero.
- **Reading flow:** title → browser hint → button → fallback. Good.

| Finding                                                                       | Severity    | Recommendation                                             |
| ----------------------------------------------------------------------------- | ----------- | ---------------------------------------------------------- |
| `md:text-display` headline is marketing-sized and wraps to two lines at 1440. | 🟡 Moderate | `title1` at all widths, like the app's own sign-in titles. |

### Consistency

| Element                 | Issue                                                                                              | Recommendation                                                         |
| ----------------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Buttons, links, colours | Site tokens (`button-primary button-large`, `prose-link`, `fg-*`), wordmark header as on the site. | —                                                                      |
| German copy             | "Brute-ForceHR herunterladen": `:lang(de) { hyphens: auto }` splits the brand name.                | 🟡 Moderate — `hyphens-manual` on the brand-bearing sentence and link. |

### Accessibility

- **Contrast:** axe (wcag2a/aa, wcag21a/aa, best-practice) 0 violations in all states, both themes.
- **Keyboard:** wordmark → Return to BruteForceHR → Download link (hand-off); wordmark → Get help (incomplete). One visible focus ring (site default).
- **Language:** `<html lang>` follows the copy shown (`tr`/`de`), so screen readers switch voice.
- **Targets:** primary button 52 px high, links inline in text.

### What Works Well

- The hint "Your browser may ask to open the app. Choose Open…" (Zoom) prepares people for the browser's own dialog, which is the main source of confusion on hand-off pages.
- One primary action; download and device guidance stay secondary.
- Copy follows the app language via Firebase's `lang` parameter; TR uses "siz", DE "du".

### Priority Recommendations

1. Restore spaces in the fallback sentence.
2. Headline to `title1`.
3. Stop hyphenating the product name in German; clarify the footnote.
