## Design Critique: Changelog (`/changelog/`)

### Overall Impression

Clean and quiet: version, date and a Beta badge on the left at 1440, notes on the right, one entry per release with a link to GitHub. Drafts and the updater channel release stay hidden. Two issues: the first note heading sits lower than the version heading, and the empty state doesn't say how to hear about the first release.

### Usability

| Finding                                                                                                                                           | Severity    | Recommendation                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------- |
| Empty state: "No releases yet" + "Follow the project on GitHub" doesn't tell people how GitHub notifies them, and differs from the Download page. | 🟡 Moderate | Add "select Watch, then Custom, then Releases" and use the Download page's "Open BruteForceHR on GitHub". |
| At 1440 the notes column starts 24 px lower than the version heading (the first note heading keeps its top margin).                               | 🟢 Minor    | Zero the first child's top margin.                                                                        |
| Release-note headings arrive as `h1` / `h2` from GitHub.                                                                                          | —           | Shifted to `h3` and below at build time, so the outline stays h1 page → h2 version → h3 notes.            |
| The feed link shows even while the feed is empty.                                                                                                 | 🟢 Minor    | Keep: subscribing before the first release is exactly when a feed helps.                                  |
| website.md's month grouping (more than ~10 entries) isn't built.                                                                                  | 🟢 Minor    | Log: there are no releases yet; add it when the list passes ten entries.                                  |

### Visual Hierarchy

- **What draws the eye first:** "Changelog", then the newest version heading. Correct.
- **Reading flow:** version → date + Beta → custom title (only when it differs from the tag) → notes → "Version X on GitHub".
- **Emphasis:** the Beta badge uses `info` colours, not the accent, so stable releases stay the default.

### Consistency

| Element | Issue                                                                                                                | Recommendation |
| ------- | -------------------------------------------------------------------------------------------------------------------- | -------------- |
| Dates   | Same `en-GB` long date as the Download page and Home.                                                                | —              |
| Prose   | `.release-notes` mirrors the legal prose (underlined links, mono `code` on `surface.sunken`, tertiary list markers). | —              |

### Accessibility

- **Color contrast:** Beta badge `info.text` on `info.subtle` 4.64:1 light / 5.27:1 dark; links 6.53:1 / 8.40:1.
- **Touch targets:** "Version X on GitHub" links stand alone in their own paragraph but were only as tall as their text (~20 px). 🟢 Minor → **fixed** before r2: 44 px (`min-h-11`).
- **Text readability:** notes ≤ 68 ch, prose size.

### What Works Well

- Every entry has a stable anchor for deep links from the apps.
- No release data is invented: today's page is honestly empty.

### Priority Recommendations

1. **Empty state copy** — tell people how to get notified.
2. **Align the notes column** — polish.
