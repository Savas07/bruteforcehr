## Design Critique: Download (`/download/`)

### Overall Impression

Trustworthy and matter-of-fact: version and date up top, one row per installer with size and the full SHA-256 and a Copy button, the unsigned-build steps exactly where a visitor needs them, and an iPhone card that's clear about "invite only". The detected primary button was missing on Chromium Macs (shared OS-detection bug), and a few strings wrap awkwardly.

### Usability

| The detected "Download for Mac" primary didn't show on Chrome / Edge Macs (`userAgentData.platform` is "macOS").                                              | 🟡 Moderate | Shared fix with Home: case-insensitive `^mac` / `^win`.                                                                                                             |

### Visual Hierarchy

- **What draws the eye first:** "Download BruteForceHR", then the filled "Download for <OS>". Correct.
- **Reading flow:** version · date · What's new → primary + "Read this before you open it" → rows (name, requirements · file type · size, Download) → SHA-256 → first-launch note → iPhone card → "Check your download".
- **Emphasis:** first-launch notes use `info.subtle`, not warning amber: the warning is expected, not a fault.

### Consistency

| Element | Issue                                                                           | Recommendation                                    |
| ------- | ------------------------------------------------------------------------------- | ------------------------------------------------- |
| Wording | "Windows protected your PC" → More info → Run anyway, identical to Support.     | —                                                 |
| Wording | "Apple Account" (Apple's current name) here, "Apple ID email" on Support.       | Use "Apple Account email address" on Support too. |
| Buttons | Row Download buttons are secondary; the detected one is the only filled button. | —                                                 |

### Accessibility

- **Color contrast:** `fg.secondary` on `info.subtle` 6.85:1 light / 6.83:1 dark; link on `info.subtle` 6.11:1 / 6.65:1.
- **Touch targets:** Download and Copy buttons 44 px; the TestFlight link is inline in a sentence (exempt).
- **Text readability:** SHA-256 in mono at footnote size, wrapping anywhere, fully selectable.

### What Works Well

- Checksums come from the release's own `SHA256SUMS.txt` and are cross-checked against GitHub's asset digest at build time; a mismatch fails the build instead of publishing a wrong hash.
- The "No release yet" state is the honest truth today and tells people how to hear about the first one.
- The Copy button appears only when the Clipboard API exists and announces "Checksum copied" politely.

### Priority Recommendations

1. **OS detection** (shared with Home).
2. **One empty-state message on Download and Changelog.**
3. **Command wrapping and the Apple Account wording** — small polish.
