## Design Critique: Features (`/features/`)

### Overall Impression

Clear and calm: a title, one sentence, six jump chips, then one spotlight per part of the app, each a short bold-lead list beside real screens. Every claim maps to something that ships today. The biggest gap is that a page promising "iPhone, Mac and Windows" shows no iPhone at all.

### Usability

| Finding | Severity | Recommendation |
| --- | --- | --- |
| No iPhone screenshot anywhere, although the lead and two quality cards name iPhone. An iPhone visitor can't see their app. | 🟡 Moderate | Add iPhone captures (`apps/ios/scripts/capture.sh`, design mode) to Jobs, CV Studio, Tracker and Mail, and the share sheet to Jobs. |
| Alternate spotlights put the media in the narrow (5fr) column at 1440, so CV Studio's stacked cards and the Tracker screens shrink to ~430 px while the copy gets the wide column. | 🟡 Moderate | Swap the column ratio with the side, so media always gets 7fr. |
| Keyed job sources carry a "circle with arrow" glyph that reads as ♂ rather than a key. | 🟡 Moderate | Use the lucide `key-round` shape (same icon family as the app) and keep the sr-only "(needs an access key)". |
| Desktop screenshots at 375 are too small to read (≈ 340 px wide). | 🟢 Minor | Accept as on Home: alt text carries the content; captions say what each shows. |
| Jobs has three screenshots; the third ("Add a job from a link", a small dialog over a dimmed list) carries little information. | 🟢 Minor | Replace with the iPhone share sheet once captured, which also shows "save from anywhere" on the second platform. |
| The closing call to action repeats Home's download block. | 🟢 Minor | Keep: visitors who scrolled the whole page shouldn't scroll back (Granola pattern). |

### Visual Hierarchy

- **What draws the eye first:** the "Features" title, then the jump chips. Correct for a reference page; the chips set expectations (six parts) before the long scroll.
- **Reading flow:** each spotlight reads eyebrow → statement → four bold leads → "How … works" → screens; at 1440 the copy column is sticky, so the bold leads stay beside the screens they describe.
- **Emphasis:** bold leads with an accent rule carry the scan path; body text stays secondary. Screens have the raised shadow, the CV stack the overlay shadow on its front card, so the stack reads as layered.

### Consistency

| Element | Issue | Recommendation |
| --- | --- | --- |
| Eyebrows, section titles | Mono accent eyebrow + display `section` title, same as Home. | — |
| Jump chips | Same pill as Support's topic chips (44 px, `line.control` border). | — |
| Qualities grid | Same ruled grid as Home's promises; titles use `headline` instead of Home's `title1` because the cells are narrower (4 columns). | Accept: the grid is a summary, not a promise list. |
| Captions | "**Device.** What it shows." on every figure; the CV stack's caption names the card behind it at ≥ 768 only, where it's visible. | — |
| Links to the guide | Every spotlight ends with "How … works", underlined `prose-link`, 44 px tall. | — |

### Accessibility

- **Color contrast:** token pairs only (`fg.primary/secondary/tertiary` on `surface.canvas/base`), the same pairs Home passes with; axe (WCAG 2.1 A/AA) reports **0 violations** at 375, 768 and 1440 in light and dark.
- **Touch targets:** every link and chip ≥ 44 px (Playwright scan at 375/768/1440: none smaller outside running text).
- **Text readability:** prose 17/26, lists ≤ 60ch; headings balance; German/Turkish not applicable (English page).
- **Images:** every visible screenshot has alt text naming device, screen and content; the cards behind the CV stack are `aria-hidden` with empty alt and hidden below 768.

### What Works Well

- Honest: no "coming soon", no invented capabilities; Gmail/Outlook are named without promising when Google/Microsoft sign-in is switched on.
- The source chips are generated from `@bfhr/jobs-connectors`, so the list can't drift from what Jobs searches.
- Lighthouse 13.5 (local build): **100 / 100 / 100 / 100** mobile and desktop.

### Priority Recommendations

1. **Add iPhone screenshots** — the page's own promise; capture in design mode.
2. **Give media the wide column on every spotlight** — screens are the evidence.
3. **Replace the ambiguous key glyph** — a mis-read icon undermines the "needs a key" legend.
