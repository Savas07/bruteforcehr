## Design Critique: Features (`/features/`)

### Overall Impression

### Visual Hierarchy

- **What draws the eye first:** title, then the jump chips; inside a spotlight, the statement, then the lead desktop screen.
- **Reading flow:** desktop screens first (the richer view), then the phones in a row, so each spotlight ends on the device a visitor may be holding.
- **Emphasis:** phones use the same border and raised shadow as the desktop screens; the CV stack keeps the only overlay shadow.

### Accessibility

- **Color contrast:** unchanged token pairs; axe **0 violations** at 375 / 768 / 1440, light and dark, after the change.
- **Touch targets:** none smaller than 44 px outside running text.
- **Reflow:** no horizontal scroll at 320 px (header fix from r1 applies) or 640 px.
- **Images:** each iPhone screen has its own alt text (device, screen, content); dark mode swaps to the dark capture.

### What Works Well

- Every screen is a real capture of the current build; nothing is mocked or promised for later. The Apply spotlight describes applying as it ships (company site, email with Undo); AI tailoring and cover-letter drafting are left out until their screens ship.
- Lighthouse 13.5.0 (local build): **100 / 100 / 100 / 100** mobile and desktop.
