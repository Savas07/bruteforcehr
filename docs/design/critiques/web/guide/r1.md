## Design Critique: User guide (`/guide/…`)

### Overall Impression

Reads like the app: the same names in bold, short numbered steps, platform differences inline. The topic layout is familiar (breadcrumb, title, one-line lead, screenshot, sections, previous / next). Two rendering slips and one bit of jargon are the only things that break the calm.

### Usability

| Finding | Severity | Recommendation |
| --- | --- | --- |
| On macOS Chrome the Return keycap (↩) renders as a colour emoji in the shortcut tables, unlike every other key. | 🟡 Moderate | Append U+FE0E (text presentation) to arrow-block glyphs when rendering keycaps. |
| Overview lead reads "Start withGetting started": the space before the link is dropped by the template. | 🟡 Moderate | Explicit `{" "}` before the link. |
| Shortcuts intro says "Mod-number keys", a keymap term readers don't know. | 🟢 Minor | "The numbers follow the order of the sidebar." |
| At 1440 the topic column nests the current page's sections (44 px rows), so on Mail (9 sections) the later topics sit below the fold of the sticky column. | 🟢 Minor | Accept: the column scrolls on its own, previous / next sit at the end of every page, and 44 px is the project's target size. |
| "Lists and panels" lists both "Next record / Previous record" (J / K in a detail pane) and "Next item / Previous item" (J / K or arrows in a list). The labels come from the app and read like duplicates out of context. | 🟢 Minor | Desktop copy, not the guide: log for the desktop shortcuts sheet. The guide renders the app's labels verbatim on purpose. |
| No search. | 🟢 Minor | Accept for 11 topics: the overview lists every section and the browser's find works on each page (Craft's search-first home rejected in research). |
| First-run setup and Job preferences describe screens landing in this wave (DesktopOnboarding, IosOnboarding). | 🟢 Minor | Labels confirmed with both owners on 2026-10-24; re-check the Getting started and Settings pages against the merged copy. |

### Visual Hierarchy

- **What draws the eye first:** the page title, then the screenshot; on the overview, the topic cards in reading order with "Getting started" first.
- **Reading flow:** breadcrumb → title → lead → "On this page" (below 1280) → screenshot → sections; each section opens with what it's for, then steps.
- **Emphasis:** UI labels in bold, so a skimming reader finds the button names; tip boxes (`surface.selected`) only for the two things that commonly go wrong (invite-only sign-up, sending permission, Google/Microsoft sign-in not yet on).

### Consistency

| Element | Issue | Recommendation |
| --- | --- | --- |
| Layout | Same shape as the legal layout (sticky column ≥ 1280, inline box below), without legal numbering. | — |
| Header nav | "Guide" is marked current on every topic (`aria-current="true"`), "page" on the overview. | — |
| Keycaps | Drawn like the app's `Keycaps` (⌘ ⇧ ⌥ / Ctrl Shift Alt, `esc` / `Esc`), from the same `chordKeycaps`. | — |
| Terms | "Not selected", "No response", "Settings › AI" match the app; Support's "AI & sending" and "sign-in code" were outdated and now match too. | — |

### Accessibility

- **Color contrast:** token pairs only; axe (WCAG 2.1 A/AA): **0 violations** on all 12 guide routes at 375 / 768 / 1440, light and dark.
- **Touch targets:** navigation, breadcrumb, pager and card links ≥ 44 px; links inside running text are exempt (inline).
- **Text readability:** 68ch articles, prose 17/26, tables in `body` size with row headers.
- **Screen readers:** shortcut cells carry a spoken form ("Command Shift D", "G then T") with the glyphs `aria-hidden`; tables have column and row headers; each table section is labelled by its heading.

### What Works Well

- The keyboard tables are generated from the desktop registry and every screen's bindings, so they can't drift; the build fails if the reader suddenly finds fewer than 40 bindings.
- Platform differences are explicit and short ("On iPhone, …") instead of duplicated pages.
- Lighthouse 13.5 (local build): **100 / 100 / 100 / 100** mobile and desktop on the overview, Getting started, Mail and Keyboard shortcuts.

### Priority Recommendations

1. **Keep keycaps as text** — an emoji keycap looks like a bug.
2. **Fix the missing space** in the overview lead.
3. **Drop "Mod"** from reader-facing text.
