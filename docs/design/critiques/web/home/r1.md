## Design Critique: Home (`/`)

### Overall Impression

Calm and honest: one value line, one download action, the product shown on all three devices, then four pillars and plain promises. The "In early development" chip sets expectations without apologising. The biggest problem is that the OS-detected primary never appeared on Chromium Macs, so most Mac visitors got the generic button.

### Usability

| Finding                                                                                                                                                                                       | Severity    | Recommendation                                                                                                            |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------- |
| OS detection compared `userAgentData.platform` against `/Mac/`, but Chromium reports `"macOS"`, so Chrome / Edge on a Mac fell back to "Download BruteForceHR" instead of "Download for Mac". | 🟡 Moderate | Match `^mac` / `^win` case-insensitively for both `userAgentData.platform` and `navigator.platform`.                      |
| "What's new" rows: the date column is fixed at 11 rem, so at 375 a Beta row wraps the version under the date while stable rows don't; the list reads ragged.                                  | 🟡 Moderate | Stack date above version below 768, row layout from 768; keep the Beta badge beside the version.                          |
| "All changes" link is 26 px tall.                                                                                                                                                             | 🟡 Moderate | `min-h-11` inline-flex so it meets the 44 px target rule used everywhere else.                                            |
| Footer (all pages): with the new Product group, three link columns at 768 wrap "Privacy Policy" and "Terms of Use" onto two lines.                                                            | 🟡 Moderate | Two columns until 1280, three at 1280+.                                                                                   |
| Desktop screenshots render ~330 px wide at 375, so their UI text can't be read.                                                                                                               | 🟢 Minor    | Accept: they show the shape of the product; the alt text describes each screen and the caption says they use sample data. |
| Hero requirement line at 375 wraps to three lines (meta + two links).                                                                                                                         | 🟢 Minor    | Log; both links are useful (first-launch steps for the unsigned build, other platforms).                                  |
| Without a release the hero says "See download options" + "The first release hasn't been published yet."                                                                                       | —           | Correct: no button promises a file that doesn't exist.                                                                    |

### Visual Hierarchy

- **What draws the eye first:** the two-line display heading, then the single filled button. Correct.
- **Reading flow:** chip → heading → lead → action → requirement line → bento (iPhone first at 375). Section eyebrows in mono teal ("What it does", "Getting started", "Our promises") pace the long page.
- **Emphasis:** the iPhone tile at 1440 floats in the middle of a tall tile with large empty space above and below, so the phone looks smaller than the desktops it sits next to.

### Consistency

| Element        | Issue                                                                                                                  | Recommendation                                                                                                              |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Buttons        | New `.button` classes reuse the exact pill, colours and states of `ContactCard`'s primary.                             | —                                                                                                                           |
| Pillars layout | 2 × 2 at 1440 instead of website.md's 4 columns.                                                                       | Keep: at 4 columns each screenshot is ~260 px and unreadable; 2 × 2 keeps them legible. Recorded as a deliberate deviation. |
| How it works   | Static three columns (Beside) at 768 / 1440 and Railway vertical list at 375, without the Cloudstudio scroll chapters. | Keep for now: the chapters need onboarding visuals that the M0 checkpoint didn't capture. Revisit with the Features page.   |
| Wording        | "Download for Mac", "Get it on iPhone", "Invite only" match the Download page and Support FAQ.                         | —                                                                                                                           |

### Accessibility

- **Color contrast:** body `fg.secondary` on canvas 7.31:1 light / 8.63:1 dark; tertiary caption 5.46:1 / 6.47:1; white on `accent.solid` 6.51:1 / 4.58:1.
- **Touch targets:** everything ≥ 44 px except "All changes" (above).
- **Text readability:** prose 17 px / 1.5, lead 20 px; line length ≤ 60 ch in the hero.
- **Alt text:** each screenshot names the device, the screen and what it shows; the device label chips are the `figcaption`.

### What Works Well

- No invented social proof: the page states promises the product is built around (send only after confirmation, no invented CV facts, Undo on automatic changes, export/delete, EU storage) and links the Privacy Policy for the details.
- One action per variant; other platforms are one quiet link away (Spline).
- The same Today screen on iPhone and Mac next to the Windows tracker tells "one account, every device" without a sentence.

### Priority Recommendations

1. **Fix OS detection** — the primary action is the page's purpose.
2. **Even out the what's-new rows and the All changes target** — scanning and touch.
3. **Footer columns at 768** — shared across every page.
