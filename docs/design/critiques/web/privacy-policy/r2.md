## Design Critique: Privacy Policy (`/privacy/`)

### Overall Impression

All r1 issues are resolved: the service list reads cleanly at 375, English no longer hyphenates, the contents list aligns and uses two columns at 768, and the footer reads correctly. What's left is the first screen: a person who taps "Privacy Policy" on Google's consent screen sees the title and then a 14-item contents list — they have to choose a section before they learn anything.

### Usability

| Finding                                                                                                                                                                                                                                                                                                     | Severity    | Recommendation                                                                                                                                                                |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No at-a-glance summary. The per-section "In short" boxes start below the contents; at 375 the first fact ("Other email is never stored") is ~2.5 screens down. The stressed user from the consent screen wants the 4–5 promises that matter (email, sending, AI, where data lives, delete) before deciding. | 🟡 Moderate | Add a "The short version" block right under the title and effective date, before the contents: 5 one-line key points with check icons, each one backed by a numbered section. |
| The sticky contents at 1440 doesn't show which section you're in.                                                                                                                                                                                                                                           | 🟢 Minor    | Optional scroll-spy (`aria-current="location"`) later; the numbered headings already orient. Log.                                                                             |
| No "back to contents" at 375 (carried from r1).                                                                                                                                                                                                                                                             | 🟢 Minor    | Logged in r1.                                                                                                                                                                 |

### Visual Hierarchy

- **What draws the eye first**: title → effective date → contents. After the fix it should be title → short version → contents.
- **Reading flow**: the service list now scans as name → what it does → receives → where, consistently at every width.
- **Emphasis**: "Receives:" / "Where:" labels in `fg.secondary` semibold separate the facts without extra colour.

### Consistency

| Element                         | Issue                                                                                                                                             | Recommendation |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| Service list vs retention table | Different components for different shapes of data (prose facts vs two-column durations); both use `line.subtle` row rules and the same type ramp. | —              |

### Accessibility

- **Color contrast**: unchanged from r1 (all pairs ≥ 4.5:1 text, ≥ 3:1 UI).
- **Touch targets**: contents rows 48 px; header items 44 px.
- **Text readability**: no hyphenation in English; 16–17 px body; reflow at 320 px without horizontal scrolling.

### What Works Well

- The service list makes "who gets what, where" answerable on a phone.
- Two-column contents at 768 brings the first section into the first screen and a half.
- Dark mode summary callouts and the service-list rules stay legible without glare.

### Priority Recommendations

1. **Add "The short version"** above the contents so the key promises are in the first screen.
2. Scroll-spy for the sticky contents (optional, later).
