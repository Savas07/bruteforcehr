## Design Critique: Privacy Policy (`/privacy/`)

### Overall Impression

The first screen now does its job: title, effective date, then five plain promises with check marks — email, sending, AI, where data lives, delete — before the contents. Someone arriving from Google's consent screen on a phone gets the answer in one screen and can drill into the numbered section behind each point.

### Usability

| Finding                                                                                                                                                              | Severity | Recommendation                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| At 768 (r3 first capture, `a7c1769`) the short-version card was narrower than the contents card below it (68 ch at the root font size), leaving a ragged right edge. | 🟢 Minor | **Fixed in this round** (`4773c67`): full width below 1280, 68 ch at the prose size from 1280, matching the body column.          |
| Key points don't link to their sections.                                                                                                                             | 🟢 Minor | The contents list directly below covers navigation; links inside every point would add 5 more tab stops before the contents. Log. |
| Carried: no scroll-spy in the sticky contents; no back-to-contents at 375.                                                                                           | 🟢 Minor | Logged (r1, r2).                                                                                                                  |

### Visual Hierarchy

- **What draws the eye first**: the title, then the short-version card (white card with a title and teal checks) — correct; the teal "In short" callouts further down remain the per-section device, so the two summary levels don't compete (white card vs tinted callouts).
- **Reading flow**: title → description → effective date → short version → contents → intro → sections. At 1440 the contents stay sticky on the left and the short version leads the right column.
- **Emphasis**: checks in `accent.text` are the only accent on the first screen besides links; no filled accent competes.

### Consistency

| Element | Issue                                                                                                               | Recommendation |
| ------- | ------------------------------------------------------------------------------------------------------------------- | -------------- |
| Cards   | Short version and contents use the same card (radius `lg`, `line.subtle` border, `surface.base`, 20–24 px padding). | —              |
| Copy    | Each key point is backed by a section: email → 4, sending → 4.6, AI → 5, storage → 7, export/delete → 9.            | —              |

### Accessibility

- **Color contrast**: key points `fg.primary` on `surface.base` 17.43:1 (light) / 15.15:1 (dark); check icons `accent.text` on `surface.base` 7.00:1 / 7.76:1 (decorative, `aria-hidden`).
- **Touch targets**: unchanged (contents rows 48 px).
- **Text readability**: key points at the prose size, one line each at 1440, two to three at 375.

### What Works Well

- The answer to "what happens to my email?" is the first line of the page.
- The structure is now: promises → contents → plain summaries → full text — four levels of depth, each optional.
- Light and dark both hold the same hierarchy.

### Priority Recommendations

1. No Critical or Moderate findings. Keep the logged Minors (scroll-spy, back-to-contents, key-point links) for the final-stage critique.
