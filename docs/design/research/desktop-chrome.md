# Desktop chrome: sidebar, command palette, shortcuts sheet, update banner

Research date: 2026-10-22 · Source: Mobbin MCP, `platform: "web"` (desktop-class SaaS apps, per BRIEF §5.2) · Implementation: `apps/desktop` (M0 shell)

## Scope

Research matrix (BRIEF §5.3), row **Desktop only**: sidebar navigation, command palette, keyboard shortcuts sheet, update-available banner. It also covers the window chrome from §5.4 (macOS hidden-inset title bar with traffic lights, Windows title bar overlay with Mica, Snap-friendly minimum size), because the sidebar and title bar are designed together.

Queries (all `task_intent: "Design a cross-platform job search, CV builder and application tracker app"`, `output_destination: "code"`, `mode: "deep"`): `sidebar navigation`, `sidebar navigation with inbox, today and projects sections`, `command palette`, `keyboard shortcuts dialog`, `update available banner prompting app restart`, `new version available notification`. I also read the user's saved collection **MENU BAR** (`9fcb6eab-…`). Its one item is a website header ([Serus](https://mobbin.com/sites/sections/7fd02b57-a187-4d62-86bf-9c8fb0764f72)), so it belongs to the website research, not app chrome.

Examined: 16 sidebar screens, 8 palettes, 8 shortcut sheets and 15 update/what's-new screens (n8n appears in both update queries). Every pattern has at least 3 kept references.

## Decision — Desktop (macOS + Windows)

Implemented in `apps/desktop` (M0) unless marked **M1**.

**Window chrome**

- **macOS:** `titleBarStyle: "hiddenInset"` with `trafficLightPosition {x: 20, y: 19}`. That centres the 14 pt lights in a 52 px toolbar row and aligns them with the sidebar icons (`x = 12 px padding + 8 px row inset`). The sidebar uses `vibrancy: "sidebar"` (`visualEffectState: followWindow`), and its CSS background is transparent. The content pane stays opaque, so text contrast doesn't depend on the wallpaper. The native menu bar lists every shortcut: **View → Command Palette… ⌘K**, **Go → Today…Mail ⌘1–⌘5**, **Help → Keyboard Shortcuts… ⌘/**.
- **Windows:** `titleBarStyle: "hidden"` with `titleBarOverlay {height: 40}`. Caption buttons are native, so Snap layouts appear when hovering Maximize. A full-width 40 px title-bar row holds the app name, and its right padding comes from `env(titlebar-area-*)`. On Windows 11 22H2+ (build ≥ 22621) the window gets `backgroundMaterial: "mica"` with a transparent overlay colour. Older builds fall back to opaque chrome colours. Caption symbol colours follow `nativeTheme`. The content pane has a rounded top-left corner, as in Windows 11's own apps. The font stack puts `"Segoe UI Variable Text"` / `"Segoe UI Variable Display"` ahead of `system-ui`. The menu is hidden behind the overlay, so the sidebar's "Keyboard shortcuts" row and the palette are the discovery path on Windows.
- **Minimum size:** 480 × 360. Microsoft's guidance is a minimum width "of at most 500 effective pixels … to support snap layouts" ([Support snap layouts](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-snap-layout-menu)). 480 fits thirds on 1536-epx screens and quadrants on 1366×768. Below 640 px the sidebar collapses to a 60 px icon rail with tooltips.
- **Light/dark** follows the OS through `nativeTheme` (`prefers-color-scheme` in the renderer, plus a `nativeTheme.updated` handler for native colours). There is one neutral `src/renderer/theme.css` until `@bfhr/ui-tokens` replaces it.

**Sidebar navigation**: Superlist + Todoist + LangChain.

- Order: **Jump to… `⌘K`** (opens the palette, keycap visible), then **Today · Jobs · Tracker · CVs · Mail**, then **Keyboard shortcuts** pinned at the bottom. Insights and Settings join in their milestones, Settings at the bottom.
- 32 px rows, 16 px icons (lucide, stroke 1.75), 13 px labels. The selected row gets a neutral fill and medium weight, with no accent bar. Hovering a row shows a tooltip with the label and its shortcut (`Jobs ⌘2`). In the narrow rail, that tooltip is the only visible label; the accessible name always comes from the hidden label.
- Later: counts on Today and Mail ("needs attention"), and the update card in the footer (below).

**Command palette** (cmdk inside a Radix Dialog): Vapi + Supabase + Navattic.

- 560 px wide, 14 vh from the top, scrim behind. The input row has a search icon and the placeholder "Jump to a section or command…". The first result is pre-selected.
- Groups: **Go to** (destinations with ⌘1–5 keycaps), **Help** (Keyboard shortcuts ⌘/). The footer reads `↑ ↓ to move · ↵ to open · esc to close` and is hidden from assistive tech, because the combobox/listbox semantics already announce it.
- ⌘K toggles the palette. Choosing a destination moves focus to that section's heading.
- M4+: searchable entities in two-line rows (Mintlify/Base44) and actions ("Track an application…").

**Keyboard shortcuts sheet** (Radix Dialog): Circle + Notion Mail + Teams.

- 480 px modal with the title "Keyboard shortcuts" and a one-line description. Groups **Navigation** / **General**, each row a label (`dt`) with keycaps (`dd`) and dividers between rows. Modifiers follow the platform (`⌘` vs `Ctrl`, Teams), and screen readers get a spoken label ("Command K").
- Opened with ⌘/ / Ctrl+/, from the sidebar, from the palette, or from Help → Keyboard Shortcuts…. Add search once there are more than ~20 shortcuts (Frame.io / Notion Mail).
- Shortcuts have one source, `src/shared/shortcuts.ts`, which feeds the menu, the sheet, the palette and the tooltips. Key presses are routed in the main process (`before-input-event`), so each shortcut fires exactly once. Digits match physical keys, so they also work on AZERTY.

**Update-available banner** (**M1**, with electron-updater): n8n + Campsite + Gumloop.

- A non-blocking **card in the sidebar footer**, above "Keyboard shortcuts". It appears only after the update has downloaded and stays until acted on. No modal, no toast, no badge count. In the narrow rail it becomes an icon with a dot.
- Content: a title, one sentence with the version, **Restart to update** (primary), and **What's new** (opens a release-notes dialog with version, date and notes, like Gumloop's). "Later" collapses the card to a single line. The update still installs on quit (BRIEF §7).
- Restart never discards work. If an editor has unsaved changes, Restart asks to save first (the CV editor owns that check).

**Router: TanStack Router** (`@tanstack/react-router`, code-based routes, hash history).

- Why: route paths and `<Link to>` are type-checked against the route tree, and the tree is generated from `src/shared/destinations.ts`, so the sidebar, palette, menu and routes can't drift apart. Search params are typed and validated at the route, which suits the M4 job filters and saved searches, where filter state belongs in the URL. Code-based routes need no codegen plugin. Hash history fits the `app://bfhr/index.html` origin: route changes never trigger a document navigation, so the `will-navigate` guard stays strict.
- Rejected: **React Router 8**: fully typed routes need the framework-mode typegen; data mode is untyped strings. **wouter**: tiny, but no typed routes and no search-param validation.

## Open questions

1. **App icon and wordmark** don't exist yet. Packaging uses the default Electron icon. They need their own design and critique pass (BRIEF §5.4).
