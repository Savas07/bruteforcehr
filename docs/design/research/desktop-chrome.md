# Desktop chrome: sidebar, command palette, shortcuts sheet, update banner

Research date: 2026-10-22 · Source: Mobbin MCP, `platform: "web"` (desktop-class SaaS apps, per BRIEF §5.2) · Implementation: `apps/desktop` (M0 shell)

## Scope

Research matrix (BRIEF §5.3), row **Desktop only**: sidebar navigation, command palette, keyboard shortcuts sheet, update-available banner. It also covers the window chrome from §5.4 (macOS hidden-inset title bar with traffic lights, Windows title bar overlay with Mica, Snap-friendly minimum size), because the sidebar and title bar are designed together.

Queries (all `task_intent: "Design a cross-platform job search, CV builder and application tracker app"`, `output_destination: "code"`, `mode: "deep"`): `sidebar navigation`, `sidebar navigation with inbox, today and projects sections`, `command palette`, `keyboard shortcuts dialog`, `update available banner prompting app restart`, `new version available notification`. I also read the user's saved collection **MENU BAR** (`9fcb6eab-…`). Its one item is a website header ([Serus](https://mobbin.com/sites/sections/7fd02b57-a187-4d62-86bf-9c8fb0764f72)), so it belongs to the website research, not app chrome.

Examined: 16 sidebar screens, 8 palettes, 8 shortcut sheets and 15 update/what's-new screens (n8n appears in both update queries). Every pattern has at least 3 kept references.

## Decision — Desktop (macOS + Windows)

Implemented in `apps/desktop` (M0, Tauri 2: Rust shell in `src-tauri/`, React UI in a WKWebView on macOS and WebView2 on Windows) unless marked **M1**. Tauri specifics verified against the Tauri 2.12 config schema and source (tauri 2.12.5, wry 0.57, tao 0.37) on 2026-10-22.

**Window chrome** (`src-tauri/src/window.rs`)

- **macOS:** `titleBarStyle: "Overlay"` + `hiddenTitle: true`, so the webview fills the window, with `trafficLightPosition {x: 20, y: 28}`. That puts the 14 pt lights at x 20 and top 19 (centred in the 52 px toolbar row, aligned with the sidebar icons: `x = 12 px padding + 8 px row inset`). Tauri's `y` grows the title-bar container to `14 + y` while the buttons keep their 9 pt offset from its bottom, so `y = 19 + 9`; measured on macOS 26 from a screenshot of the built app. The rows above the sidebar and the content pane are `data-tauri-drag-region`s (they need `core:window:allow-start-dragging` and `allow-internal-toggle-maximize` for double-click zoom). The window is built from a `WindowConfig` rather than builder setters: only that path gives tao the inset as well, and tao re-applies it after `setTitle:`, which AppKit uses to reset the lights (tauri#13044); the title follows the section. The sidebar uses `windowEffects: ["sidebar"]` (`state: followsWindowActiveState`) on a transparent window, and its CSS background is transparent. Transparency no longer needs `macOSPrivateApi` (a no-op since Tauri 2.12.1). The content pane stays opaque, so text contrast doesn't depend on the wallpaper. The native menu bar lists every shortcut: **View → Command Palette… ⌘K**, **Go → Today…Mail ⌘1–⌘5**, **Help → Keyboard Shortcuts… ⌘/**, plus the standard app, File, Edit (needed for ⌘C/⌘V in the webview) and Window menus.
- **Windows:** **native decorations**. Tauri 2 has no title-bar overlay with native caption buttons on Windows: `titleBarStyle` and `trafficLightPosition` are macOS-only in the schema, and the feature request (tauri#2663) closed without one. A custom HTML title bar (`decorations: false`) loses the Snap Layouts flyout, which needs `WM_NCHITTEST → HTMAXBUTTON` from a native caption, so we keep the system title bar and draw no fake caption buttons. On Windows 11 22H2+ (build ≥ 22621) the window is transparent with `windowEffects: ["mica"]`; Mica covers the title bar and the transparent sidebar, and DWM matches the caption to the system light/dark theme. Older builds stay opaque (canvas colour). The native menu bar sits under the title bar (File · Edit · View · Go · Help) and shows the Ctrl accelerators, so the shortcuts are discoverable as on macOS. The content pane has a rounded top-left corner, as in Windows 11's own apps. The token font stack puts `"Segoe UI Variable Text"` / `"Segoe UI Variable Display"` ahead of `system-ui`.
- **Minimum size:** 480 × 360, default 1280 × 800. Microsoft's guidance is a minimum width "of at most 500 effective pixels … to support snap layouts" ([Support snap layouts](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-snap-layout-menu)). 480 fits thirds on 1536-epx screens and quadrants on 1366×768. Below 640 px the sidebar collapses to a 60 px icon rail with tooltips.
- **Light/dark** follows the OS: the window theme is left unset, so the webview's `prefers-color-scheme`, the macOS vibrancy, Mica and the Windows caption all track the system setting. Colours come from `@bfhr/ui-tokens` (`tokens.css` + the Tailwind theme in `tailwind.css`).
- **First paint:** a native initialization script defines `window.__BFHR_CHROME__ = {platform, material}` before any page script, so the layout (`data-platform`, `data-material`) is right on the first frame without an IPC round trip.

**Security** (`src-tauri/tauri.conf.json`, `capabilities/main.json`)

- CSP: `default-src 'none'; script-src 'self'; worker-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src ipc: http://ipc.localhost; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; object-src 'none'`, sent as a header by Tauri's asset protocol. Tauri adds hashes for its own scripts and a per-load nonce for styles; `index.html` carries `<meta property="csp-nonce" nonce="__TAURI_STYLE_NONCE__">`, which Tauri replaces with that nonce, and `get-nonce` hands it to Radix's scroll-lock `<style>`. `freezePrototype: false` (M2): the Firebase Firestore SDK's bundled Closure code assigns `prototype.toString` on its own classes, which throws once `Object.prototype` is frozen (the "override mistake"), so the whole bundle failed to start; the CSP above (`script-src 'self'`, no eval) is what keeps foreign script out. `withGlobalTauri: false`, no remote URLs. `worker-src 'self'` (M2) admits only the bundled pdf.js module worker of the CV ATS check (`features/cv-editor/ats/extract.ts`); no blob: workers, no eval, no wasm.
- One capability for the `main` window: `core:event:allow-listen`/`unlisten` (menu commands), `core:window:allow-start-dragging` + `allow-internal-toggle-maximize` (drag rows), `allow-open-external`. No plugin JS commands are granted (the opener plugin is used from Rust only, with its link-click handler off); there is no shell or filesystem access.
- `open_external(url)` validates in Rust: `https` only, host exactly `bruteforcehr.web.app` or `github.com`, no credentials, no explicit port, ≤ 2048 chars. Navigation outside the app origin (`tauri://localhost` / `http://tauri.localhost`) is cancelled in `on_navigation`; `window.open` and `target=_blank` are denied in `on_new_window`.
- The WebdriverIO plugins exist only in the `e2e` cargo feature with `tauri.e2e.conf.json` (its own capability); release bundles never contain them.

**Sidebar navigation**: Superlist + Todoist + LangChain.

- Order: **Jump to… `⌘K`** (opens the palette, keycap visible), then **Today · Jobs · Tracker · CVs · Mail**, then **Keyboard shortcuts** pinned at the bottom. Insights and Settings join in their milestones, Settings at the bottom.
- 32 px rows, 16 px icons (lucide, stroke 1.75), 13 px labels. The selected row gets a neutral fill and medium weight, with no accent bar. Hovering a row shows a tooltip with the label and its shortcut (`Jobs ⌘2`). In the narrow rail, that tooltip is the only visible label; the accessible name always comes from the hidden label.
- Later: counts on Today and Mail ("needs attention"), and the update card in the footer (below).

**Command palette** (cmdk inside a Radix Dialog): Vapi + Supabase + Navattic.

- 560 px wide, 14 vh from the top, scrim behind. The input row has a search icon and the placeholder "Jump to a section or command…". The first result is pre-selected.
- Groups: **Go to** (destinations with ⌘1–5 keycaps), **Help** (Keyboard shortcuts ⌘/). The footer reads `↑ ↓ to move · ↵ to open · esc to close` and is hidden from assistive tech, because the combobox/listbox semantics already announce it.
- ⌘K toggles the palette. Choosing a destination moves focus to that section's heading.
- M4+: searchable entities in two-line rows (Mintlify/Base44) and actions ("Track an application…").

**Keyboard shortcuts sheet** (Radix Dialog): Circle + Notion Mail + Teams.

- 480 px modal with the title "Keyboard shortcuts" and a one-line description. Groups **Navigation** / **General**, each row a label (`dt`) with keycaps (`dd`) and dividers between rows. Modifiers follow the platform (`⌘` vs `Ctrl`, Teams), and screen readers get a spoken label ("Command K").
- Opened with ⌘/ / Ctrl+/, from the sidebar, from the palette, or from Help → Keyboard Shortcuts…. Add search once there are more than ~20 shortcuts (Frame.io / Notion Mail).
- Shortcuts have one source, `src/lib/shortcuts.ts`, which feeds the key handler, the sheet, the palette and the tooltips; the native menu (`src-tauri/src/menu.rs`) repeats the destinations and keys, and its unit tests read the TS files so they can't drift. Key presses in the webview are handled in the UI (`keydown`, capture phase, `preventDefault`), so each shortcut fires exactly once: WebView2 never passes accelerators to the native menu while it has focus (tauri-apps/wry#451), and WebKit skips the menu for keys the page handled. Menu clicks reach the UI as a `menu-command` event. Digits match physical keys (`event.code`), so they also work on AZERTY.

**Update-available banner** (**M1**, with the Tauri updater plugin): n8n + Campsite + Gumloop.

- A non-blocking **card in the sidebar footer**, above "Keyboard shortcuts". It appears only after the update has downloaded and stays until acted on. No modal, no toast, no badge count. In the narrow rail it becomes an icon with a dot.
- Content: a title, one sentence with the version, **Restart to update** (primary), and **What's new** (opens a release-notes dialog with version, date and notes, like Gumloop's). "Later" collapses the card to a single line. The update still installs on quit (BRIEF §7).
- Restart never discards work. If an editor has unsaved changes, Restart asks to save first (the CV editor owns that check).

**Router: TanStack Router** (`@tanstack/react-router`, code-based routes, hash history).

- Why: route paths and `<Link to>` are type-checked against the route tree, and the tree is generated from `src/lib/destinations.ts`, so the sidebar, palette, menu and routes can't drift apart. Search params are typed and validated at the route, which suits the M4 job filters and saved searches, where filter state belongs in the URL. Code-based routes need no codegen plugin. Hash history fits Tauri's single `index.html` on the asset origin: route changes never trigger a document navigation, so the `on_navigation` guard stays strict.
- Rejected: **React Router 8**: fully typed routes need the framework-mode typegen; data mode is untyped strings. **wouter**: tiny, but no typed routes and no search-param validation.
