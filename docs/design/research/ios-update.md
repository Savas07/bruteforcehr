# iOS update gate — design research (update-available banner · update-required screen)

Research date: 2026-10-23 · Source: Mobbin MCP, `platform: "ios"` (`task_intent`: "Design a cross-platform job search, CV builder and application tracker app", `output_destination`: `code`) · Judged from result images, not metadata. No images are stored in the repo.

## Scope

PRD **M1-UPD-2 — iOS version gate**: a banner when `appConfig/ios.latestVersion` is newer than the installed version, and a blocking screen when the installed version is below `minSupportedVersion` ([ADR 0004](../../adr/0004-release-updates-signing.md) §3). iOS can't update itself (App Review Guideline 2.5.2), so both surfaces send the user to **TestFlight**, which installs the build. IA.md allows exactly two full-screen takeovers: signed-out auth and this gate. `desktop-chrome.md` deferred the iOS banner to this file.

## Decision — iOS

1. **Update available = an info-tinted card with the `InlineAlert` anatomy and a dismiss, docked above the tab bar on every tab** (Garmin / Future / Zocdoc anatomy; its own view so the title can use the primary text color, critique r2). Glyph, title "Update available", one sentence naming the version and where it is ("Version 0.2.0 is ready in TestFlight."), text action "Open TestFlight", ✕. It sits in each tab's bottom safe-area inset, so scroll content ends above it and nothing is covered; a top inset would hide the iOS 26 large title (foundation-ios.md). It is app-wide, because a deep link can open any tab.
   - At accessibility text sizes it collapses to one line, "Update available" as the button that opens TestFlight + ✕, so it doesn't cover the tab; the version sentence is the VoiceOver value (critique r1).
   - **Dismiss is remembered per version**: ✕ hides it until a _newer_ `latestVersion` appears. No nagging, no countdown.
   - Toasts stack above it (the toast host lives inside the screen, the banner outside).
2. **Update required = a full-screen cover that can't be dismissed** (Fitbit / Google Health layout, Hue reassurance, Rivian version lines): leading-aligned accent glyph, title "Update required", one sentence for cause → action, a reassurance that updating keeps the data, the installed and required versions in secondary text, and **one primary "Open TestFlight"** pinned to the bottom (at accessibility text sizes the buttons follow the text instead, so nothing is cut off; critique r1). A quiet "Get help" link opens the website's Support page (GitHub issues, with its "issues are public" warning).
3. **Open TestFlight**: `itms-beta://` opens the TestFlight app; if it isn't installed the open fails and the App Store page of TestFlight opens instead (`https://apps.apple.com/app/testflight/id899247664`). Internal testing has no public join link, so there is no app-specific link to open (decisions.md U7, "Invite only").
4. **When it checks**: at launch and every time the app returns to the foreground, a server read of `appConfig/ios` (public, no sign-in). Only `latestVersion` and `minSupportedVersion` are read.
5. **Fail open**: offline, a failed read, a missing document or an unparseable version show nothing and never block. A failed re-check also hides the banner (TestFlight can't download offline either) but keeps a block learned earlier in the session.
6. No banner or gate when up to date; no "you're up to date" confirmation.
